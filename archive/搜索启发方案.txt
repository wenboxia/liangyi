### 一、 核心对标：多模型对抗与“拆台”机制（对应 P1 & P2D）

两仪论强调“跨模型维度的结构性分歧（Divergence）”，这在当前的学术界与开源前沿已有高度吻合的实践。

* **平台**：GitHub
* **项目名称**：`kucherenko/gangsta` (The Heist Pipeline)

# 两仪论对标项目检索报告

## A 类 · 与"两 AI 高 divergence 对抗式 brainstorm"高度相似（核心思路对标）

### A1. Tencent AI Lab + 清华 + 上海交大 — **Multi-Agent Debate (MAD): Encouraging Divergent Thinking**
- **来源**：Tencent AI Lab 官方研究（EMNLP 2024）/ arXiv / GitHub
- **核心相似点**：这是**与两仪论思路最对标**的工作。论文明确提出 **Degeneration-of-Thought (DoT) 问题** ——单 LLM 一旦对答案建立信心，自我反思无法生成新思考，即使初始判断错误。其解决方案与立场一**几乎重合**：用多 Agent 在"tit for tat"状态下争论，由 judge 管理过程。复杂样本需要更多轮辩论；用不同 LLM 充当 agents 时 LLM 不一定是公平 judge——后一点也与两仪论"persona 轴受 AI identity 轴约束、A1 模型不能扮拆台"的跨轴约束完全同构。
- **差异点**：MAD 用单一底模分裂出"affirmative / negative"，没有显式跨厂商 divergence；judge 是 AI 不是人。两仪论坚持"人类做最终决策"。
- **链接**：https://arxiv.org/abs/2305.19118

### A2. MIT + Google Brain — **"Society of Minds" Multi-agent Debate**（Du, Tenenbaum 等）
- **来源**：arXiv / OpenReview / ICML 2024
- **核心相似点**：多个 LLM 实例独立提出方案再多轮辩论，共同收敛到答案；显著提升数学/策略推理与事实准确性。这是 multi-agent debate 这一支研究的奠基论文，明确以 Minsky 的"Society of Mind"为思想源——与两仪论"多源造场"类比同源。
- **差异点**：辩论收敛由 AI 完成共识，没有人类作为最终综合者。
- **链接**：https://arxiv.org/abs/2305.14325 / https://composable-models.github.io/llm_debate/

### A3. UNC Chapel Hill — **ReConcile: Round-Table Conference among Diverse LLMs**
- **来源**：ACL 2024 / arXiv / GitHub
- **核心相似点**：与两仪论"divergence 优先于能力"的乘法模型最贴近。把 ChatGPT、Bard、Claude2 当作来自**不同模型族**的 agents 圆桌讨论，置信加权投票得出共识。多模型组件本身就贡献了 6.8% 的最大性能提升——证明跨厂商异质性是核心增益来源，这与两仪论"divergence 必须跨底模坐标"的硬规则在实证上相互印证。
- **差异点**：3 个 agent 而非 2 个；自动投票而非人类综合。
- **链接**：https://arxiv.org/abs/2309.13007 / https://github.com/dinobby/ReConcile

### A4. Tsinghua thunlp — **ChatEval: Multi-Agent Debate for Evaluation**
- **来源**：清华大学官方 GitHub
- **核心相似点**：多 Agent 担任"裁判组"，每人有不同 persona 自主辩论评判内容质量；研究发现**赋予不同 persona 至关重要——同 persona 会导致性能退化**。这一发现直接支撑两仪论 persona 轴和"避免假 divergence"的设计。
- **差异点**：用于评测文本质量，不用于产品方案 brainstorm。
- **链接**：https://github.com/thunlp/ChatEval

### A5. OpenAI — **AI Safety via Debate**（Irving / Christiano / Amodei）
- **来源**：OpenAI Safety 团队论文
- **核心相似点**：两个 AI 轮流陈述，由人类 judge 选谁更真实有用——把对齐重构为博弈；其对抗结构使"撒谎比反驳更难"。这是把"两个 AI 对抗 + 人类做最终判定"作为可扩展监督机制的最早奠基研究——与两仪论 P1.3 的"人类综合"机制思路完全同构。
- **差异点**：目标是 AI 安全监督，不是产品决策。两个 debater 用同模型，不强调跨底模 divergence。
- **链接**：https://arxiv.org/abs/1805.00899

### A6. 多团队联合 — **DebateCV: Debate-driven Claim Verification**（最新）
- **来源**：arXiv（2025）
- **核心相似点**：两个 Debater 持对立立场基于证据辩论，Moderator 综合判断；其对抗交叉验证机制用于解决三种典型错误模式——与你 P2 的"多 reviewer 各 target 一种 failure mode"设计哲学一致。
- **链接**：https://arxiv.org/abs/2507.19090

### A7. Queen's University — **RedDebate: Multi-Agent Red Teaming Debate**
- **来源**：arXiv（2025）
- **核心相似点**：用多 LLM 间的对抗式辩论主动找出彼此推理盲点，迭代改进——批评单 Agent 监督（如 Constitutional AI 自我批评）"agent 可能意识不到自己的错误"。这正是两仪论"两个相同 AI 没有场曲率"立场的实证支撑，也对应 P2D 触发式拆台思路。
- **链接**：https://arxiv.org/abs/2506.11083

## B 类 · 多角色协同 Agent / 链式分工（与 P3 文档生成 + P2 多角色审查对标）

### B1. Microsoft — **AutoGen / Microsoft Agent Framework**

### B2. 清华 OpenBMB — **ChatDev: Communicative Agents for Software Development**

- **核心相似点**：7 角色流水线 CEO → CPO → CTO → 程序员 → 审核员 → 测试员 → 设计师，链式协作，把开发拆为 5 子任务 3 阶段，每阶段终止条件是"两次代码无变化"或 10 轮通信——这是把"P3 文档生成的链式展开"做到了软件开发全流程上的工业级实例。
- **链接**：https://github.com/OpenBMB/ChatDev

### B3. DeepWisdom — **MetaGPT: Multi-Agent Meta-Programming Framework**
- **来源**：DeepWisdom 开源（GitHub trending 长期榜首之一）
- **核心相似点**：把"产品经理→架构师→工程师→QA"的真实软件公司 SOP 编码进多 Agent 系统，用**结构化通信协议**（不是开放自然语言）传递文档。"结构化通信"思路与你"idea.md 是单一立场干净文档、不保留双声音痕迹"的硬规则相通——都是为了让下游 reviewer 看到独立产出。
- **链接**：https://github.com/geekan/MetaGPT

### B4. 清华 OpenBMB — **AgentVerse**
- **来源**：ICLR 2024 / 清华开源
- **核心相似点**：提供 Task-solving（多 Agent 自动协作系统）和 Simulation 两套框架；可拼装专家小组协作。软件设计示例：code writer + code tester + code reviewer 三方协作迭代——和两仪论 P2 的多审查者模式同构。
- **链接**：https://github.com/OpenBMB/AgentVerse

### B5. CrewAI Inc — **CrewAI**
- **来源**：crewAI Inc 开源 + 商业版（PwC、DocuSign 等已部署）
- **核心相似点**：每个 Agent 用"role + goal + backstory"定义；**人类检查点直接嵌入任务执行流程**，监督者可在任务推进前审查或微调输出。其"hierarchical（manager 委派）/ sequential / consensual（投票）"三种过程与两仪论 P2 的"linear 四次小循环"在结构选型上正好覆盖。
- **链接**：https://github.com/crewAIInc/crewAI

### B6. LangChain — **LangGraph**
- **来源**：LangChain 官方（2025 年 10 月 v1.0 GA）
- **核心相似点**：把 Agent 交互建模为有向图节点；提供 interrupt-before / interrupt-after 让图在指定节点暂停等待人类输入，再用人类输入恢复执行——这是"人在每个 fix 节点做综合"的最自然落地框架。LangGraph 的 checkpoint 机制可以原生支持你 idea.md 多版本（v0→v5）演进与 P2/P3 边界锁定。
- **链接**：https://github.com/langchain-ai/langgraph

### B7. Anthropic — **Multi-Agent Research System**（Claude Research 背后架构）
- **来源**：Anthropic 官方工程博客
- **核心相似点**：Lead Researcher 拆解任务给 subagents 并行处理；记忆管理避免 token 超限；内部测评显示 Opus + Sonnet 多 agent 比单 agent 提升 90%+。**专门的 CitationAgent** 负责为所有论断标注来源——保持研究完整性。和你的 decision-log 思路接近：把"理由溯源"从主流程剥离出来给独立 agent。
- **链接**：https://www.anthropic.com/engineering/built-multi-agent-research-system

## D 类 · 多源融合 / Mixture-of-Agents（与"多源造场"理念相关）

### D1. Together AI + Stanford — **Mixture-of-Agents (MoA)**
- **来源**：Together AI 开源 / ICLR 2025 Spotlight
- **核心相似点**：分层架构 + 多 Agent；每层 Agent 拿前一层所有输出作辅助信息生成响应；选 LLM 时**性能与多样性两个标准**——异质模型贡献远大于同模型。"性能 × 多样性"和你的 `价值 ≈ divergence × min(capability) × match` 乘法模型在第一性原理上同构。Together 默认 4 个 proposer（Qwen / Llama / DeepSeek / MiniMax）+ 1 个 aggregator——异构组合策略可直接借鉴到 P1。
- **链接**：https://github.com/togethercomputer/MoA / https://www.together.ai/blog/together-moa

### D2. Stanford OVAL — **STORM / Co-STORM**
- **来源**：Stanford 官方 / GitHub / NAACL 2024
- **核心相似点**：两个核心假设——**多元视角带来多元问题；深度问题需要迭代研究**——多阶段流程是先发现多元视角再让 LLM 扮演专家提问。Co-STORM 引入 expert + Moderator 多 agent 类型，支持人机协作信息收集。"先发散视角 → 再综合大纲 → 再展开"的节律与你 P1（发散）→ P2（压力测试）→ P3（展开）几乎一一对应。
- **链接**：https://github.com/stanford-oval/storm

### D3. UCLA / 多团队 — **A-HMAD: Adaptive Heterogeneous Multi-Agent Debate**
- **来源**：King Saud Univ. 计算机信息科学期刊（Springer Nature, 2025）
- **核心相似点**：指出现有辩论方法**用同质 agent + 简单多数投票，效果有限**；引入异质专精 agent + 学习权重的共识优化器，比标准 debate 在六个 benchmark 上提升 4-6%——这是 ReConcile 路线的最新进展，与两仪论"divergence 优先"完全同向。
- **链接**：https://link.springer.com/article/10.1007/s44443-025-00353-3

## E 类 · 多 Persona / 单模型多视角（轴二 "persona divergence" 对标）

### E1. UIUC + Microsoft — **Solo Performance Prompting (SPP)**
- **来源**：NAACL 2024 / Microsoft Research 合作论文
- **核心相似点**：指示 LLM 召唤多个 persona 协作解决任务（如让 LLM 自动产出"小说家+科学家+核物理学家"分别讨论）；研究表明 LLM 可在不微调情况下有效自主识别 persona。这是你 P2A "Claude 切投资人"那一步的方法论根据：persona 轴在单底模上是可激活的，但你方法论同时指出了上限——A1 路径的 Claude 激活不了拆台 persona。
- **链接**：https://arxiv.org/abs/2307.05300

### E2. de Bono → ChatGPT 应用 — **Six Thinking Hats**
- **来源**：经典管理学方法 + 多家 LLM 应用实践
- **核心相似点**：六顶帽子各代表一种思维角度（事实/情感/批判/乐观/创意/控制），系统切换避免单一思维定势。这是你 P2 "四步各 target 一种 failure mode"的思想前身——但两仪论从信息论 + 工作记忆容量推出"4 步刚好"，而不是直接照抄六顶。
- **链接**：https://easyaibeginner.com/chatgpt-six-thinking-hats-framework/（应用示例）

### E3. Town Hall Debate Prompting
- **来源**：arXiv（2025-01）
- **核心相似点**：把同一 LLM 实例化为多个"专家" persona 进行结构化辩论、批判、投票，GPT-4o 在逻辑题上 +13% 准确率——这是 P2A/P2C 单底模多角色机制的最近实证。
- **链接**：见综述 https://www.emergentmind.com/topics/persona-prompting-pp

## 关键观察

1. **最贴近的项目是 Tencent AI Lab MAD**：它给两仪论"立场一·对抗 AI 溶解人"提供了最直接的实证依据（DoT 问题），且明确指出"不同 LLM 当 agents 时 judge 不公平"——这正是你跨轴约束的实验前置。

2. **多数对标项目让 AI 做最终判定**（投票/共识/aggregator），而两仪论坚持人类综合——这是结构性差异，不是缺失。OpenAI Debate 是少数让人类做 judge 的设计。

3. **divergence 优先于 capability** 这条原则在 ReConcile 和 MoA 已有实证（异质模型贡献了主要性能增益），但**没有项目把它写成像两仪论那样明确的"乘法模型 + 三阶段选择法"**。

4. **国内工程平台（Coze/Dify/n8n）能直接承载两仪论**作为可视化执行容器，但它们本身不提供方法论——你的工作流 + 这些平台是互补关系。

5. **ChatDev 和 MetaGPT 把 P3 链式文档生成做到了软件开发领域的工业级**，可以反向参考其 SOP 设计来扩展两仪论 P3 的 PRD/Tech Spec/CLAUDE.md/Dev Guide 之间的依赖图。

# 六、附件中非常独特、目前没发现完整现成对应物（你的原创性高点）

真正没找到成熟同构现成方案的是：

1. **“双 AI divergence 优先于 capability”的选模原则**
   近似原创。

2. **P2B 单盲复审 + 知识诅咒攻击**
   非常少见。

3. **P2C 漂移审查（不是查错而是查方向漂移）**
   几乎独有。

4. **触发式拆台（仅三方都通过才触发）**
   非常独特。

5. **会话卫生作为方法论组成部分**
   现有 Agent 框架几乎没人做到。

这几块不是简单“像某开源项目”，更接近原创组合创新。
