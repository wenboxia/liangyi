# P2D · 拆台专家反馈

## 论据 1 · 草案态评测本质是随机数生成器，PM 的迭代完全建立在噪声之上

方案的前提假设是“没有效度验证的评测也能帮助 PM 迭代判据”。这个假设不成立。当 Profile 的 Spearman ρ 可以低至 0.3、0.2 甚至为负时，扣分报告给 PM 的信号与真正的输出质量之间不存在任何统计学上可靠的关系。PM 基于这种信号“迭代”判据，等价于对着噪声做优化——每一次调整都是在拟合评测器自身的系统偏差，而不是在逼近真实的“好”。**反例**：某客服团队用草案态 Profile 发现摘要类任务的 Presentation 扣分集中在“结尾缺少礼貌用语”，于是 PM 在 prompt 中硬性加入结尾祝福语，结果用户满意度反而下降，因为过长的结尾打断了后续工单流转。事后他们用 300 条线上样本算了 Spearman ρ = -0.18，整整三个月都在往错误方向用力。草案态不是在“试”，是在制造有害幻觉。

## 论据 2 · 可选升级通路在组织行为学上等于“永不升级”，等于把严谨性彻底架空

方案把效度验证从入场门槛降为升级通路，预设的假设是“需要严格决策的团队会自愿走升级”。这个假设违背所有组织行为学的常识。一旦草案态 Profile 能产出报告、挂 CI、产生 visual feedback，管理层对“仪表盘有绿色数字”的满足感就已经被满足。升级需要额外投入 22 人时校准、标注、算 ρ、过审阅——在一个已经“有数字可看”的状态下，没有任何业务负责人会主动申请这笔预算，除非出了重大线上事故。**反例**：代码审查平台从最初的可选 commit gate 演进到今天的强制 PR gate，所有主流工具最终都走向了“不通过就合并不了”的强制执行模式，正是因为整个行业反复验证了一个铁律——严谨性只要不是结构性强制的，就会被系统性跳过。v4 的可选升级通路就是 v1 的退化版，只不过把“不需要严谨”包装成了“用户有选择权”。

## 论据 3 · judge 重回协作者立场等于放弃评测的唯一价值：独立于开发者的第二声音

方案把 judge 定位为“协作者”并恢复 `suggested_fix`，预设的假设是“提供启发式建议对工程师调试有价值”。这个假设从根本上误解了评测工具的立身之本。Agent 工程师自己就能看 trace、自己想就能写 prompt 修改建议；他们真正缺少的不是又一个“建议你试试加约束”的噪声源，而是一个独立于他们自己优化目标的、不对 prompt 作者负责的外部质量信号。一旦 judge 是协作者，它产出的扣分和修复建议就天然和工程师的目标（让扣分消失）同向，导致整个评测体系变成工程师和 judge 之间的合谋游戏——工程师把 suggested_fix 贴进 prompt，扣分消失，质量问题原地不动。**反例**：Google 的 Auto-Evaluation 实践表明，当评估模型与生成模型耦合在同一优化循环中时，reward hacking 不可避免；唯一有效的止损手段是评估方独立且不接受开发者反馈。v4 把 judge 变成工程师的同伙，等于亲自关掉了评测平台存在的唯一理由。

## 论据 4 · 把“定义好”的话语权还给业务方是一个漂亮的错误，PM 不具备定义评测维度的元能力

方案的核心主张是“PM 对‘什么算好’有最终话语权”。这个假设搞混了“提出质量需求”和“定义可操作的测量模型”是两种完全不同的能力。PM 能说“我要客服不发火”，但 PM 无法说出发火在 1000 条对话中的 37 种表面形式、无法区分“语气生硬”和“合理拒绝”、无法预判某个关键词阻断规则会让 20% 的正常退款流程被误杀。把定义维度的工具直接交给 PM，本质是要求业务方同时担任测量学家——而他们做不了这件事，结果就是 Profile 变成 PM 直觉的数字化投影，测量的是 PM 的个人审美偏好而不是 Agent 的实际质量。**反例**：字节跳动早期的内容审核规则库完全由业务运营定义，上线后误杀率高达 40% 以上，最终不得不引入测量学团队全部重做。v4 的“话语权还给业务方”是把这条路重走一遍，只不过这次死的不是内容审核，是 Agent 评测。

## 论据 5 · 草案态满地跑、升级态没几个人走，最终退化为无人维护的配置文件坟场

方案预设的采纳模型是“大量团队用草案态，少数升级，平台繁荣”。实际最终形态会是每个 PM 花 2 小时 fork 一个场景包调几个参数跑出第一份报告，两周后 Profile 不再更新，但 CI 里永远挂着这个没人维护的草案 Profile 继续产生无意义的扣分。当草案 Profile 数量超过 20 个、无人升级、无人校准、无人读报告时，平台的存在价值就已经归零——因为它成了一张坏信号泛滥的污染源，所有人都会学会忽略它。**反例**：任何内部度量平台在没有强制治理的情况下，最终的结局都是配置腐烂——SLA 仪表盘、代码质量门禁、告警规则库，无一例外。v4 放弃 v3 的结构性治理、把一切寄希望于“用户自驱力”，这不是回拉重心，这是主动选择废墟。
