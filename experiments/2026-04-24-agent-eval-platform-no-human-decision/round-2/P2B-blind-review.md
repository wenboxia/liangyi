# P2B · AI 工程师单盲反馈

## 1. 一句话总结（第一眼理解）
这是一个基于 Langfuse 二次封装的 Agent 评测扩展层，通过自建业务断言、中文场景包和效度验证三个模块，试图把评测分数和线上业务指标挂钩，用来支撑上线决策。

## 2. 如果同事说"以后评估都用这个"，你会用吗？为什么？
**不会立刻用，会先要求看落地细节再决定。**

原因：
- 文档说"不自建先做胶水"，但"业务断言适配器"和"效度验证回路"的具体接入方式、错误处理、重试机制、超时策略完全没写，我无法评估集成成本和稳定性风险。
- 效度验证要求"近 N 周至少 500 条线上样本"，但冷启动场景或低频业务根本凑不齐这个量，文档没说数据不足时的降级方案。
- κ目标按维度分级这个逻辑我能理解，但"校准集规模下限按κ的置信区间宽度反推"只给了结论，没给计算公式、置信区间算法或可复用工具，我无法执行。
- 文档删除了 `suggested_fix` 字段，但作为工程师我实际调试时非常依赖"哪里错了 + 怎么改"的可操作线索，只给扣分证据不给修复方向，我的问题定位效率会下降。
- 全文多次提到"工单"、"SLA"、"Calibration Owner"，但这些流程依赖的组织协同机制（谁建单、谁派单、系统怎么感知状态变更）完全没提，我没法判断这会不会变成纯人工扯皮。

## 3. 卡点 / 看不懂 / "啊？" / "没解决痛点"

### 卡住 / 看不懂 / 产生"啊？"的地方
1. §2.2 说"分层打分器细节见 v1,不赘述"——我没看过 v1，不知道 Layer 1-4 具体怎么协作，不知道"LLM 证据抽取层只抽证据不打分"的输出格式是什么，无法对接代码。
2. §2.3 硬红线定义"可 100% 断言化或规则化"，但举例"政策数值条款如'7 天内'"：如果政策原文是自然语言而非结构化规则，怎么转成断言？转换逻辑谁写？文档没说。
3. §2.4 的 `EvidenceLocator` 用 JSONPath 指向 trace 节点，但 Langfuse 的 trace 数据结构长什么样？文档没给 schema 示例，我没法写代码解析 `messages[3].tool_calls[0].arguments.refund_amount` 这种路径。
4. §2.6 说"Judge-vs-Human κ每周自动回放"——"自动回放"的触发条件是什么？数据从哪拉？计算脚本谁维护？监控告警怎么配？全没交代。
5. §2.7 效度验证要求"双样本检验 p<0.05"——用哪种检验方法？t 检验？Mann-Whitney？样本不独立（同一用户多轮对话）时怎么处理？统计方法细节缺失。
6. §3.2 架构图里"Validity Pipeline"和"Calibration Workflow"两个模块之间的数据流没画清楚，我不知道效度验证失败时，工单是怎么自动生成并派给 Calibration Owner 的。
7. §3.3 说"级联的真实节省约 20-30%"——"级联"指什么？是打分器层间级联还是 Profile 间级联？文档前文没定义这个术语，我看不懂这个结论怎么来的。
8. §4.2 估算校准集标注时间"1 分钟/条"——这个时间怎么来的？是预标注 + 人工复核还是纯人工？如果是 LLM 预标注，预标注的置信度阈值是多少？没说明。
9. §4.4 Phase 1 说"写 v2 Extension Layer 最小版本:Profile schema + 断言引擎骨架 + 3 条硬红线规则"——"骨架"的接口定义、错误码规范、日志格式、健康检查端点都没给，我无法评估开发工作量。
10. 全文多次提到"工单"，但工单系统对接的是 Jira？自研？还是 Langfuse 原生？工单的字段映射、状态同步机制、权限控制完全没提。

### "这根本没解决我真实痛点"的地方
1. 我实际调试 Agent 时最需要的是"快速复现问题 trace + 一键重跑 + diff 对比"，文档说 Langfuse 原生支持这些，但 v2 扩展层会不会干扰原生 trace 的归档和回放？没说。
2. 文档强调"效度验证"作为准入门槛，但我日常迭代中 80% 的改动是小 prompt 调整，每次改都要凑 500 条线上样本算ρ，迭代周期会被拉长到无法接受。
3. 作为工程师我需要知道"评测失败时怎么本地 debug"，但文档只说了线上效度验证和人工二审流程，没说本地回放、mock 数据、单元测试的支持方案。
4. 文档说"预算护栏为 Profile 必填字段"，但我的痛点是"不知道某次评测花了多少钱"，而不是"月度总预算"，缺少单次 run 的成本透传和实时告警。
5. 文档要求每个 Profile 指定 Calibration Owner 并响应 5 工作日 SLA，但没提如果 Owner 离职/转岗/请假时，系统怎么感知并重新派单，这在实际协作中很容易卡住。
