1. **一句话总结（第一眼理解版）**
这是一个把团队对 Agent 输出"好不好"的主观感觉，拆解成具体、可校验的窄问题规则，并自动跑分、定位扣分原因和原文依据的评测工具。

2. **如果同事说"以后评估都用这个"，我会用吗？为什么？**
**愿意试，但"以后都用"有保留。**

- **愿意试的点**：单次诊断场景很实用——粘贴输入输出就能知道哪条规则没过的、引用了原文哪段，比纯靠感觉复盘效率高；"固定回归集"替代全量回溯，日常调参时跑一下成本低，这个设计能接受。
- **保留的点**：
  - 配置一条"窄问题规则"到底要多细？文档说"禁止宽泛 prompt"，但我没法预判我写的规则会不会被静态检查拦截，试错成本不透明。
  - 信效度 gate 要求每条规则≥50 条人工标注，高权重≥100 条。如果我临时加一个业务规则，标注样本谁标、多久能标完、标完平台算κ/ρ要多久？这些时间成本文档没给预期。
  - "规则通过率"明确说不支持跨 Agent 对比，但如果业务方拿着两个 Agent 的通过率数字来问"哪个更好"，我拿什么话术解释？平台只说"视觉上阻止拉平"，但阻止不了人脑对比。

3. **阅读过程中的卡点 / "啊？"时刻 / 痛点未解决感**

**卡住 / 看不懂 / "啊？"的地方：**
- "窄问题规则"的边界：文档举例"回答是否明确确认了用户的情绪？(是/部分/否)"算窄，但"回答是否共情？"算宽？这个判断标准依赖设计器的静态检查，但文档没给检查逻辑或更多正反例，我第一次配的时候怎么知道会不会被拦截？
- 信效度 gate 的操作链路：文档说"上传人工标注样本→平台计算κ/ρ→判定阈值"，但没说我上传的样本格式是什么（JSON？CSV？）、标注维度怎么对齐规则、计算结果是实时出还是异步、如果κ=0.59 差 0.01 没过，我能看具体哪几条标注分歧大吗？
- "引用原文片段"的执行细节：裁判 LLM 强制 extractive 引用，但如果原文很长、裁判引用的片段本身有歧义（比如只引了半句话），平台怎么处理？报告里会标出"引用可信度"吗？
- "结构化抽取验证"标为重量级接入，但没说清楚什么场景必须用它、接入要改哪层代码、是平台提供 SDK 还是我自己写 parser。
- 人工抽检协议里"2 名业务方独立打主观判断"：如果业务方就是配这条规则的人，复核是不是自己审自己？如果业务方没时间标，平台有兜底标注资源吗？

**"这根本没解决我真实痛点"的地方：**
- 我日常调优时，很多问题不是"某条规则没过"，而是"整体回复风格怪怪的"。文档说用模板库兜底窄问题拆解，但如果我的场景是长尾的、模板库里没有，我是不是就得自己拆？拆的过程中如果感觉"怎么拆都不对"，平台有退路吗？
- 信效度 gate 的标注成本：如果我只是想快速验证一个 prompt 改动，但加一条新规则要先标 50 条样本、等平台算指标，这个反馈周期会不会比"我人工看 10 条"还慢？文档说低信度规则可以"仅作为观察信号"，但观察信号能不能用于日常迭代？
- 回归集是"冻结"的 100-300 条，但如果我的 Agent 用户分布变了（比如新上了一个功能，用户问法变了），冻结集会不会导致评测结果和线上真实表现脱节？文档没说回归集怎么更新、谁来触发更新。
- 依赖 Langfuse 自托管：文档说"自建层与 Langfuse 通过稳定接口隔离"，但如果 Langfuse 升级改了 evaluator runner 的接口，我的评测方案会不会挂？平台有兼容性测试或回滚方案吗？
