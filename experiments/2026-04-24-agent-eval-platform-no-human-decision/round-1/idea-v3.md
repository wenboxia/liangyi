# Agent 评测平台（v3）

## 一句话产品定位

一个基于 Langfuse 自托管实例之上的评测方案与诊断产品——让团队把"业务方对 Agent 输出的质量判断"编译成窄问题、可校验、带人工兜底的评测规则，把每次扣分落到可操作的具体断言和原文引用上。

## 目标使用者与使用场景

核心用户是上线了 Agent 的 PM 与工程师。典型场景：

- **单次诊断**：PM 粘一组看起来不对的对话，想知道扣在哪条规则上、指向原文哪一段。
- **版本迭代**：工程师改完一版，批量跑固定回归集，看 v1 vs v2 的维度通过率差异。
- **上线观察**：新 Agent 接入先作为观察信号，稳定 2–4 周后由业务线自决是否作为发版门禁。

管理层看到的是"各 Agent 在自身方案下的规则通过率走势"，不是跨 Agent 的统一质量分。

## 核心评分机制

### 规则三级制（新）

v3 把规则分三级，对应不同的信度要求与用途——**这是对"信效度 gate 让快速迭代变慢"的正面回应**：

- **门禁规则（Gate）**：通过信效度 gate，计入规则通过率，可作为发版门禁。
- **观察规则（Observe）**：信度介于下限与门禁阈值之间，报告中以"低信度"标记展示，不计入通过率，但可用于日常迭代的定性参考。
- **实验规则（Experimental）**：零标注即可使用，仅出现在单次诊断报告中，不进批量、不进趋势图、不能作为门禁。适合"临时验证一个 prompt 改动"这种轻量场景。

规则创建时默认是 Experimental，业务方可随时升级到 Observe / Gate，升级触发信效度流程。

### 规则四类

1. **硬断言规则**：字段存在、禁用词、JSON Schema、正则。二元结果，不经过 LLM。天然高信度，跳过 gate。
2. **窄问题 LLM 裁判规则**（核心形态）：只允许二元（是/否）或三档序数（是/部分/否）输出；禁止 0–10 自由打分 prompt。
3. **结构化抽取验证**：抽实体对照业务 API。重量级接入，详见后文。
4. **外部计量规则**：接入业务指标，可选。

### 窄问题边界与设计器 lint（新）

窄问题判定有明确准则，设计器实时 lint 反馈，避免"配完才知道被拦"：

- **必须满足**：(a) 答案空间闭合（枚举值 ≤ 3 档）；(b) 判定条件可引用输出中的具体片段；(c) 问题不包含"好/坏/优秀/合适"等无锚形容词。
- **正例**：「回答是否明确确认了用户的情绪？(是/部分/否)」「回答末尾是否提供了退款链接？(是/否)」「回答的数字金额与工具返回值是否一致？(一致/不一致/未涉及)」
- **反例**：「回答是否共情？」（缺答案空间收敛、无锚形容词）/「回答质量如何？(0–10)」（自由打分）/「语气是否合适？」（"合适"未定义）。

设计器内置示例库（每个类型 ≥ 20 条正反例），实时给 prompt 打 lint 分，并提示如何把宽问题拆成若干窄问题。

### 引用原文约束（加严）

窄问题裁判必须返回 `quote` 字段，引用输出中的具体片段。加强为：

- **最小粒度**：引用需是完整子句（句号、问号、分号分隔），不允许半句；长度不足的提问会被要求扩展为"引用区间 [start, end]"含上下文窗口。
- **歧义标记**：若裁判标 `quote_confidence = low` 或引用长度 > 输出 40%，报告上以黄色 badge 提示"引用可信度低"。
- **未找到支撑**：裁判若无法定位引用，规则结果标为"无法判定"而非扣分，触发人工抽检队列。

报告依赖的是"可核对性"，不是"相信 reason 是真实理由"。引用太短或无法定位都会主动降级而不是装作没事。

### 跨 Agent 可比性（话术补充）

规则通过率作为元信号展示各 Agent 相对自身的趋势。针对"业务方拿两个通过率数字问哪个更好"，平台内置**话术与对照视图**：

- 每个 Agent 的通过率卡片附带一句固定标注："此数字仅反映该 Agent 相对自身的趋势，不与其他方案的通过率可比。"
- 提供**结构对比视图**：把两个 Agent 的方案规则并列展示，标出覆盖相同业务目标的规则对，让业务方自己判断"这两个 Agent 是不是在比同一件事"。这是拒绝回答"哪个更好"时给出的建设性替代。

## LLM 裁判的信效度检验

门禁规则上线前必须通过信效度 gate：

- **样本量**：门禁规则 ≥ 50 条人工标注，权重 ≥ 0.2 的 ≥ 100 条；观察规则 ≥ 20 条即可。
- **指标**：二元用 Cohen's κ，序数用 Spearman ρ。
- **阈值**：κ ≥ 0.6 或 ρ ≥ 0.7 → 门禁级；0.4 ≤ κ < 0.6 或 0.5 ≤ ρ < 0.7 → 观察级；低于下限不允许升级（但仍可作为 Experimental 使用）。
- **漂移监控**：每月用 100 条固定校准集重跑，低信度自动降级。

### 标注链路的端到端时间预期（新）

- **格式**：平台提供 CSV 模板下载，列为 `input | output | answer | annotator_id`；在线标注队列同样结构。
- **标注来源**：优先业务方自标（平台内置轻量标注界面）；业务线人手不足时，复用**跨线标注池**——平台团队维护的一组接受过校准的标注者，按工单排期。
- **中位时长目标**：50 条门禁样本从提交到出 κ/ρ 结果 ≤ 3 个工作日；100 条 ≤ 5 个工作日。异步回执，完成后邮件 + 站内通知。
- **分歧可视化**：若 κ = 0.59 差一点没过，报告展示每条标注的人工答案与裁判答案并排，并高亮分歧样本，配导出 CSV。不让用户盯着单一数字猜原因。

## 适配路径与采纳机制

- **模板库**：5–8 个场景模板（客服、代码评审、RAG 问答、数据抽取、内容审核、工具调用、摘要、长对话）。每个模板的规则已通过信效度 gate 并附带校准集，新业务线 fork 继承证据。
- **首批 pairing**：前 5 个业务线的首个方案由平台团队做 1–2 次 1 小时的流程引导，目标是走通一遍流程。
- **方案市场**：业务线成熟方案发布为内部模板。
- **长尾场景兜底**（新）：模板库未覆盖的场景，可以先用 Experimental 规则做单次诊断驱动调优，积累 20+ 有代表性的样本后再发起标注、升级为 Observe / Gate。"感觉怎么拆都不对"时的退路是——承认这条规则暂时只能作为观察信号，不强行上 Gate。

## 回归机制

- **固定回归集**：每方案绑定 100–300 条冻结样本。方案变更只重跑回归集。
- **按需全量**：仅发版 tag 时跑全量，人工 review。
- **回归集轮换机制**（新，应对分布漂移）：
  - 每季度自动触发**轮换提案**：从最近季度线上样本中按分层采样抽 50 条候选，替换回归集中命中率最低或与线上分布偏离最大的样本，由方案 owner 审核通过。
  - **分布漂移告警**：线上样本特征分布（输入长度、意图分类、工具调用频次）与回归集偏离 > 预设阈值时主动告警，提前触发轮换。
  - 轮换时保留 50% 以上的原样本作为稳定基线，防止历史趋势断裂。

## 反 Goodhart 防线

外部计量可选。默认防线是人工抽检：

- **抽样**：每周 2%，上限 50 条。
- **回避约束**（新）：**复核人员不得与规则作者重叠**；同一业务方线上的规则作者与复核者需为不同人。业务线人手不足时，由跨线标注池兜底。
- **双评 + 仲裁**：2 人独立打判断，分歧送第三方。
- **背离触发**：人工与规则背离率 > 15% 触发方案 review。

## 系统形态

基础设施用 Langfuse 自托管，自建层聚焦三件：

1. **评测方案设计器**：含窄问题 lint、信效度 gate、标注队列对接。
2. **诊断视图**：左侧对话、右侧维度卡片、未通过规则展开窄问题答案 + 原文引用高亮 + 引用可信度标记。
3. **规则通过率看板**：纵向趋势 + 低信度标记 + 结构对比视图。

其他（traces、datasets、evaluator runner、CI、标注队列基础能力）直接用 Langfuse。工程量 2–3 人半年 v1。

### Langfuse 依赖的保障（新）

- **版本锁定**：自建层明确锁定一个 Langfuse 版本区间，不跟随 upstream 自动升级。
- **兼容套件**：自建层在 CI 中维护一组针对 Langfuse evaluator runner / dataset API 的契约测试。Langfuse 升级前先跑这组测试，全绿才允许升级。
- **回滚预案**：Langfuse 升级失败时，可 48 小时内回退到上一个锁定版本；自建层的方案数据与 Langfuse 解耦存储，不依赖 Langfuse schema。

### 结构化抽取验证的接入形态（新）

- **适用触发**：输出必须包含可机器校验的业务实体（订单号、金额、SQL、URL、API 调用参数）且业务 API 可查时才启用，否则默认不用。
- **接入方式**：平台提供 TypeScript / Python SDK，业务方实现一个 `async function verify(extracted): Result` 接口，平台负责调度、重试、结果归档。不强制业务方改现有服务。
- **非必需**：默认模板不启用，在方案设计器里标注为"高接入成本"，避免被当成必配项。

## 关键风险与边界

- **窄问题表达负担**：由模板库 + lint 示例兜底。
- **信效度 gate 上不了线**：Experimental 级规则作为合理退路。
- **Langfuse 依赖**：契约测试 + 版本锁定 + 回滚预案。
- **通过率被误读**：固定标注 + 结构对比视图 + 不同纵轴。
- **标注链路堵塞**：跨线标注池兜底，3–5 工作日出结果为明示 SLA。

平台的价值不在于评得多准，在于让"感觉不对"变成一个可核对的窄问题 + 原文引用 + 带信度证据的判断；以及让"快速迭代"这个日常动作不被评测门禁堵住。

## 响应日志（v2 → v3）

- **反馈 1（窄问题边界不清）**：响应。新增"窄问题边界与设计器 lint"一节，给出三条必要条件、正反例对照、设计器实时 lint。
- **反馈 2（标注时间成本不透明）**：响应。新增"标注链路的端到端时间预期"，写明 CSV 格式、跨线标注池、3–5 工作日 SLA、分歧可视化。
- **反馈 3（跨 Agent 通过率话术）**：响应。通过率卡片内置固定标注文案；新增"结构对比视图"作为拒答"哪个更好"时的建设性替代。
- **反馈 4（上传格式/分歧展示）**：响应。明确 CSV 模板 + 标注界面；κ 差一点没过时展示逐条分歧并支持导出。
- **反馈 5（引用片段歧义/太短）**：响应。加严引用约束——最小粒度为完整子句、引用可信度标记、无法定位时降级为"无法判定"并入人工队列。
- **反馈 6（结构化抽取接入细节）**：响应。新增"结构化抽取验证的接入形态"一节，明确触发条件、SDK 接入方式、默认不启用。
- **反馈 7（抽检自己审自己）**：响应。反 Goodhart 防线加"复核人员不得与规则作者重叠"硬约束，兜底走跨线标注池。
- **反馈 8（长尾场景没模板怎么办）**：响应。新增"长尾场景兜底"——允许 Experimental 规则驱动调优并积累标注，再升级到 Observe/Gate，不强求一步到位。
- **反馈 9（信效度 gate 拖慢快速迭代）**：响应，且是本版最重要的结构性调整。引入规则三级制（Gate / Observe / Experimental），Experimental 零标注即可用于单次诊断；标注只有在规则要升级为门禁或计入趋势时才成为必要条件。
- **反馈 10（冻结回归集 vs 分布漂移）**：响应。新增回归集季度轮换机制 + 分布漂移告警 + 保留 50% 基线样本。
- **反馈 11（Langfuse 升级兼容）**：响应。新增版本锁定 + 契约测试套件 + 48 小时回滚预案。
