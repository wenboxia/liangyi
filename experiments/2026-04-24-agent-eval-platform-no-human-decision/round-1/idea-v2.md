# Agent 评测平台（v2）

## 一句话产品定位

一个基于 Langfuse 自托管实例之上的评测方案与诊断产品——让团队把"业务方对 Agent 输出的质量判断"编译成窄问题、可校验、带人工兜底的评测规则，并把每次扣分落到可操作的具体断言上。

## 目标使用者与使用场景

核心用户是上线了 Agent 的 PM 与工程师。典型场景：

- **单次诊断**：PM 粘一组看起来不对的对话，想知道扣在哪条规则上、指向原文哪一段。
- **版本迭代**：工程师改完一版，批量跑固定回归集，看 v1 vs v2 的维度通过率差异。
- **上线观察**：新 Agent 接入时跑通所属场景的方案，先作为观察信号，稳定 2–4 周后再讨论是否作为发版门禁。门禁由业务线自决，平台不预设。

管理层看到的是"各 Agent 在自身方案下的规则通过率走势"，不是跨 Agent 的统一质量分——后文展开。

## 核心评分机制与维度

产品底层信念：**评估维度是配置的**。每个 Agent 类型对应一个评测方案，方案由维度构成，维度下挂规则，规则是最小执行单元。

规则四类：

1. **硬断言规则**：字段存在、禁用词、JSON Schema、正则。二元结果，不经过 LLM。
2. **窄问题 LLM 裁判规则**（核心形态）：不允许写"请给这段回答的共情力打 0–10 分"这种宽泛 prompt。规则必须拆成具体的是/否或 3 档序数问题，例如"回答是否明确确认了用户的情绪？(是/部分/否)"。这是对批判 5 的正面回应——把打分决策收紧到一个窄问题，让 reason 与 score 之间的耦合更紧；同时强制 reason 字段**引用原文具体片段**（extractive），裁判 prompt 模板内置这一约束。宽 prompt 在设计器中会被静态检查拦截。
3. **结构化抽取验证**：从输出抽实体对照业务 API。标为"重量级接入"，不在默认模板中启用。
4. **外部计量规则**：接入业务指标。**从 v1 的强制项降为可选项**——外部埋点接入成本与数据团队排期是跨团队硬骨头，不能作为上线门槛（批判 7）。

报告形态是多维诊断面板：维度下列规则通过 / 未通过清单，每条未通过展示窄问题答案 + 引用的原文片段。因为问题窄、答案结构化、原文被引用，可操作性基于"可核对性"而不是"相信 reason 是真实理由"。

**跨 Agent 可比性**：不给统一质量分，但给一个**规则通过率（Rule Pass Rate）**作为元信号——每个 Agent 在自己方案下的规则通过率趋势图。这不声称"Agent A 比 B 好"，只声称"A 相对自己在变好/变差"。管理层看走势和红黄灯，不看绝对数字对比。这回应批判 6 但不违反"代码 Agent 和客服 Agent 分数不能拉平"的底线。

## LLM 裁判的信效度检验（批判 1 的正面回应）

任何 LLM 裁判规则上线前必须通过信效度 gate：

- **样本量**：每条规则 ≥ 50 条人工标注样本，高权重规则（在方案中权重 ≥ 0.2）≥ 100 条。
- **指标**：二元问题用 Cohen's κ，序数问题用 Spearman ρ，每条规则单独算。
- **阈值**：κ ≥ 0.6 或 ρ ≥ 0.7 → 可作为门禁规则；0.4 ≤ κ < 0.6 或 0.5 ≤ ρ < 0.7 → 仅作为观察信号，在报告中标记"低信度"且不计入通过率；低于下限 → 不允许保存方案。
- **漂移监控**：每月用固定的校准集（100 条固定人工标注）重跑所有上线规则，低信度标记自动回退。

阈值是经验起点，可按 Agent 类型调整（合规类收紧，创意类放宽），但调整走评审流程、记录在方案元数据里。写出这组数字不是承诺它永远正确，是承诺这个问题被严肃对待、有明确可审计的回答。

## 系统形态与构建路径（批判 3 的正面回应）

**不从零自建基础设施**。Langfuse 开源自托管实例已经提供 traces、datasets、experiments、evaluator runner、对接自有 LLM Gateway、CI 集成——重造这些不产生边际价值。自建层聚焦在三件 Langfuse 原生不提供、且是我们差异化来源的东西：

1. **评测方案设计器**：图形化配方案、维度、窄问题规则；内置宽 prompt 静态检查和引用原文约束；内置信效度 gate（上述样本上传 + κ/ρ 计算 + 阈值判定）。
2. **诊断视图**：左侧原始对话、右侧维度卡片、每条未通过规则展开窄问题答案 + 引用片段高亮。Langfuse 原生视图给不到这个结构。
3. **规则通过率看板**：同 Agent 版本纵向趋势 + 低信度规则标记。

其他功能——数据集版本、批量评测执行、CI 触发、trace 存储——**直接用 Langfuse**，不重写。产品边界收窄后，工程量从一个专职小团队常年投入降到 2–3 人半年可交付 v1。

## 适配路径与采纳机制（批判 2 的正面回应）

放弃"工作坊 / 陪跑"语言。采纳机制是：

- **模板库**：平台团队预先构建 5–8 个场景模板（客服、代码评审、RAG 问答、数据抽取等），每个模板包含已通过信效度 gate 的窄问题规则集合 + 标注样本。新业务线从模板 fork，改业务约束，跑自己的标注样本，通过 gate 即可上线。
- **首批 pairing（非工作坊）**：前 5 个业务线的首个方案由平台团队做 1–2 次 1 小时的 pairing，目标是让业务方走完一遍流程，不是帮他们把方案做好。
- **方案市场**：业务线成熟方案发布为内部模板，携带自己的校准集，其他业务线 fork 时继承信效度证据。

自助性的保证来自模板 + 信效度 gate 的结构化引导，不来自"非工程 PM 能从空白页面开始配"的承诺——后者本来就是虚假承诺。

## 回归机制（批判 4 的正面回应）

放弃"方案变更强制回溯全部历史批次"。改为：

- **固定回归集**：每个方案绑定一个 100–300 条的冻结回归集（人工标注的高价值样本）。方案变更只重跑回归集，几分钟 + 几十块钱内完成。
- **按需全量**：仅在方案正式发版（打 tag）时跑一次全量历史，人 review 差异报告；日常调 prompt 不触发。
- **差异视图**：只展示通过率变化 + 新增失败用例清单，不展示全量 diff。

这把回溯成本从"堵流水线"降到"每次存档前跑一遍冒烟"。

## 反 Goodhart 防线（批判 7 的正面回应）

外部计量从强制项降为可选加分项。默认防线改为**人工抽检**，轻量协议：

- **抽样率**：每周随机抽 2% 的评测样本，上限 50 条。
- **复核**：2 名业务方独立打主观判断，分歧送第三方仲裁。
- **背离报告**：人工判断与平台规则结果的背离率 > 15% 时，触发方案 review。

这比"每个 Agent 接三套业务系统"现实得多，而且业界有工具支持（Langfuse 的 annotation queue 原生可用）。

## 关键风险与边界

- **窄问题约束带来的表达负担**：写"是否共情"比写"打共情分"难。由模板库兜底，模板里的窄问题就是经验资产。
- **信效度 gate 可能让大量方案上不了线**：这是正确的——上不了线的方案本来就不该产生数字。只作为观察信号是合理退路。
- **Langfuse 依赖**：绑定一个开源项目的演进节奏。缓解：自建层与 Langfuse 通过稳定接口隔离，必要时可切换 evaluator runner。
- **规则通过率被误读为"质量总分"**：管理层可能还是把它当成跨 Agent 比较。在看板上明确标注"本指标仅反映 Agent 相对自身的趋势"，并把不同方案的通过率默认以独立色块 + 不同纵轴展示，视觉上阻止拉平。

平台的价值不在于评得多准，在于让"感觉不对"变成一个可核对的窄问题 + 原文引用 + 带信效度证据的判断。

## 响应日志

- **批判 1（LLM 裁判效度论证为零）**：响应。新增"LLM 裁判的信效度检验"整节，给出样本量（50/100）、指标（κ/Spearman ρ）、阈值（门禁 / 观察 / 拒绝三档）、漂移监控（月度校准集）。
- **批判 2（自助 vs 工作坊矛盾）**：响应。删除工作坊与持续陪跑语言，改为模板库 + 首批 1–2 次 pairing 引流。采纳机制显式依赖模板资产，不依赖人肉咨询。
- **批判 3（vs Langfuse 差异未论证）**：响应。调整产品边界——基础设施（traces、datasets、evaluator runner、CI）直接用 Langfuse 自托管；自建层只做方案设计器、诊断视图、规则通过率看板三件差异化产物。工程量从常年专职团队降到 2–3 人半年 v1。
- **批判 4（回溯成本炸弹）**：响应。放弃全量历史回溯，改为 100–300 条的冻结回归集日常重跑，仅发版 tag 时跑一次全量。
- **批判 5（reason 是 post-hoc 解释）**：响应。规则形态收紧为窄问题（二元/三档序数），禁止宽泛 0–10 分 prompt，设计器静态检查拦截；reason 字段强制引用原文片段。可操作性基于可核对性，不基于"相信 reason 是真实理由"。
- **批判 6（无跨 Agent 数字 = 无管理层抓手）**：响应。引入"规则通过率"作为元信号提供趋势视图，但明确标注不作跨 Agent 绝对对比、不同方案独立纵轴展示。守住"不同 Agent 绝对分不可比"的底线，同时给管理层一个可看的信号。
- **批判 7（外部计量与人工抽检成本被低估）**：响应。外部计量从强制降为可选；结构化抽取验证标注为重量级接入，默认模板不启用；反 Goodhart 默认防线改为轻量人工抽检协议（2% / 上限 50 条 / 双评 + 仲裁 / 15% 背离触发 review）。
