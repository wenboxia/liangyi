# Agent 评测平台（v4）

## 一句话产品定位

一个把业务方对 Agent 输出的软性质量判断翻译、沉淀、复用的工程基座——核心产出是**团队共享的评测方案**，平台自身是这些方案被配置、调试、运行、传播的场所。不是一个裁判统计学系统。

## 目标使用者与使用场景

核心用户是上线了 Agent 的 PM 与工程师。**三场景并重，不分主次**：

- **单次诊断**：粘一组看起来不对的对话，看扣在哪条规则上、指向原文哪一段。
- **版本迭代**：改完一版 Agent，跑回归集，看维度表现的版本对比。
- **上线把关**：新 Agent 接入时跑通所属场景的方案，作为发版资格的结构化依据。是否作为门禁由业务线自决。

这三件事同等重要——任何让"单次诊断最顺、门禁最费劲"的设计选择都是错的。

## 核心评分机制

产品底层信念：**评估维度是配置的**。每个 Agent 类型对应一个评测方案，方案由维度构成，维度下挂规则。

### 规则四类，软判断是一等公民

1. **硬断言规则**：字段存在、禁用词、JSON Schema、正则。二元结果。
2. **LLM 裁判规则**：由配置人编写 rubric prompt，告诉裁判"你是 XX 场景的验收员，按以下标准打分并说明原因"，返回 `score + reason + quote`。**支持 0–5 分制的软性判断**——共情、语气、合规、信息完整度这些场景是平台的核心用户，不把它们驱逐出主规则形态。
3. **结构化抽取验证**：抽实体对照业务 API。可选重量级接入。
4. **外部计量规则**：接入业务指标。**回到推荐地位**——不再强制，但在方案设计器里显著引导，理由是真实业务指标是对抗 Goodhart 的最强防线，可选不代表不重要。

### 窄问题是推荐写法，不是强制形态

v3 把窄问题（是/否、三档序数）做成唯一裁判形态，副作用是把"共情""语气"这类软判断挡在了门外。v4 恢复 v1 的立场：**窄问题是推荐写法，通过设计器的 lint 提示与示例引导，不作为静态检查拦截的硬约束**。

- 设计器给每条 LLM 裁判规则打 **"可核对性评分"**（High / Medium / Low），评分依据包括：答案空间是否闭合、prompt 是否含无锚形容词、是否要求 extractive 引用。分数低不会被拒绝保存，只会在报告和看板上以标记显示，让使用者和观看者都知道这条规则的信度权重。
- 配置人可以**选择接受低可核对性**——有些场景（新 Agent 初期探索、长尾主观判断）宁愿要粗糙的信号也不要没有信号。平台不替业务方做这个判断。

### 引用原文是软约束

裁判 prompt 模板默认要求 `quote` 字段，引用输出中的具体片段。但：

- **不拒绝无引用**：裁判找不到可引用片段时可以返回"无直接支撑"，报告中以 badge 展示而不是丢弃规则结果。
- **不强制完整子句**：短引用照常展示，加上下文窗口即可。
- **可信度标记**：引用长度异常或裁判自标 low confidence 时，报告黄标提示——这是 v3 做得对的，保留。

### 报告形态

多维诊断面板：维度下列规则命中 / 未命中清单，每条未命中展示裁判 reason + 原文引用 + 可核对性标记。PM 看到的是"合规维度 · 规则 3 未通过：未按模板提供退款链接（引用：对话第 4 轮）"。

## 可选认证：不是默认门槛，是信度背书

v3 的信效度 gate（κ ≥ 0.6 / ρ ≥ 0.7 / 50–100 条标注）**从默认门槛降为可选认证**——这是从 v3 大幅回退的关键项。

- **默认状态**：规则创建即可用，直接进入方案、参与批量评测、参与报告。不需要标注、不需要算 κ。
- **认证徽章（Certified）**：业务方如果想把某条规则作为**发版门禁**或对外汇报"该规则已校准"，可以主动走认证流程，提交人工标注样本，平台算 κ/ρ 并颁发徽章。认证是徽章，不是准入。
- **认证的用途**：只有带徽章的规则可以被配置为"阻断发版"的硬门禁；未认证规则可以参与通过率统计和报告，但不作阻断。

这样做的理由：v1 的根基是"业务方配规则"，不是"标注链路通畅"。标注是对想要高置信度的规则的加码，不是对所有规则的税。

"跨线标注池"、"3–5 工作日 SLA"、"CSV 模板"、"分歧可视化"作为认证流程的配套**保留在附录**，不在主流程里占版面。

## 系统形态

自建侧的核心四件套（v1 的产品身份）**拿回来**：

1. **评测方案设计器**：图形化配方案、维度、规则；含可核对性 lint、模板库、版本控制。
2. **规则调试沙箱**：单条规则试跑，实时看裁判返回的 JSON + 扣分原因。v3 淡化了这件事，v4 恢复为产品成败关键模块之一。
3. **方案市场**：成熟方案作为内部模板发布，替换业务约束即复用。这是"共识"在组织层面沉淀的载体。
4. **CI 插件 + SDK**：把评测嵌入发版流程。

### Langfuse 的定位

Langfuse 是**可选后端**，不是产品底座。

- 默认部署包含自建的 trace 存储与批量执行引擎，单 Docker 容器开箱即用。
- 已有 Langfuse 实例的团队可以把 trace / dataset 持久化层切换到 Langfuse，平台提供 adapter。
- 产品身份不依赖 Langfuse 存在与否。v3 那种"自建层与 Langfuse 通过接口隔离"的姿态把产品降级成了皮肤，v4 不走这条路。

工程量回升——但评测平台本来就不是"2–3 人半年 v1"能交付的东西。承认这个事实比压缩到不成形要好。

## 回归与演化

- **固定回归集**：每方案绑定 100–300 条冻结样本。方案变更只重跑回归集。v3 的这项保留。
- **季度轮换**：从近期线上样本中采样替换命中率最低 / 分布偏离最大的样本，保留 ≥ 50% 基线。v3 保留。
- **全量回溯仅在发版 tag 时触发**，人工 review 差异报告。v3 保留。

## 采纳与组织路径

放弃 v3 的"纯自助 + 1–2 次 pairing"克制叙事。复苏 v1 的部分组织化姿态，但具体形式更轻：

- **模板库**：5–8 个场景模板，规则结构成熟，新业务线 fork 改约束。
- **首批方案的 onboarding clinic**：每个新接入业务线的第一个方案由平台团队陪跑 1 次完整循环（粘样本 → 拆维度 → 写规则 → 调沙箱 → 跑回归集）。不叫工作坊，但承认这是高接触的启动期。第二个方案起放手。
- **方案市场**：成熟方案沉淀为内部模板携带样本与规则结构。
- **不承诺"非工程 PM 从空白页面自助配"**——这是 v3 反而更诚实承认的事，v4 继续承认。

## 反 Goodhart 防线

- **外部计量**：从"强制"降到"推荐"，在设计器里醒目引导。有真实业务指标可接入的场景强烈建议配一条，这是真正难作弊的信号来源。
- **人工抽检**：保留 v3 的协议——每周 2%、上限 50 条、**复核人员不得与规则作者重叠**、双评 + 仲裁、15% 背离触发方案 review。
- **方案版本化 + 回归集**：防止规则静默漂移。

## 跨 Agent 可比性

维持 v1 + v3 的共同底线：不提供跨 Agent 质量总分。

- 管理层看到的是**同 Agent 方案下的指标趋势**（通过率 / 未命中规则 top N / 人工抽检背离率），不是跨 Agent 排行榜。
- 遇到"A 和 B 哪个好"的追问，提供**结构对比视图**（v3 做对的东西，保留）——把两个方案的规则并列，让业务方自己判断"是不是在比同一件事"。

## 关键风险与边界

- **配置门槛**：承认配方案需要业务方投入，不承诺零配置。模板库 + onboarding clinic + 沙箱是降低门槛的手段，不消灭门槛。
- **软判断裁判不稳**：允许软判断存在，但用"可核对性评分"把信度差异前置暴露；认证徽章给愿意加码的规则一条升级路径。
- **规则腐化**：方案版本化 + 回归集 + 季度轮换 + 背离率监控，四层防线。
- **方案市场冷启动**：前 3–5 个业务线的方案由平台团队共建并上架，不指望自然生长。
- **Langfuse 非依赖**：自建后端默认工作，Langfuse 作为兼容后端而非前置条件。

平台的价值不在于评得多准，在于让团队把"感觉不对"翻译成"规则 3 没过，原因是 X，这是我们对这个 Agent 的共同定义"。当团队对这句话点头，平台就在做它该做的事。

## 回退日志（v3 → v4）

- **软判断回归主规则形态**：撤销 v3 "只许窄问题二元 / 三档序数，禁 0–10 自由打分"的硬约束。恢复 LLM 裁判的 rubric 打分形态，让"共情""语气""合规"这类核心场景回到产品中心。窄问题改为推荐写法 + 设计器 lint 引导。理由：v1 的核心用户是软判断场景，v3 把它们驱逐出去是方向性错误。
- **信效度 gate 降为可选认证**：撤销 "门禁规则必须过 κ/ρ 阈值 + 50–100 条标注"的默认门槛。改为 Certified 徽章：认证是规则作者主动发起的信度背书，只有想作为发版阻断的规则才需要。理由：v1 的根基是"业务方配规则"不是"标注链路通畅"，不能把标注做成所有规则的税。
- **规则三级制（Gate / Observe / Experimental）取消**：回退为单一规则形态 + 可选认证徽章。三级制是 v3 为了给快速迭代留口子的补偿设计，既然 gate 本身降级了，三级制失去存在理由，简化掉。
- **Langfuse 从底座降为可选后端**：撤销 "基于 Langfuse 自托管实例之上" 的产品定位。自建后端默认工作，Langfuse 作为 adapter 可切后端之一。理由：v3 那种"我只是 Langfuse 上一层皮"的姿态把产品独立性让渡了，一并损失了 v1 的"基座"身份。
- **外部计量回到推荐地位**：撤销 "从强制降为可选"的轻描淡写。v4 里外部计量仍然可选，但在设计器里醒目引导、在方案审查中作为"高质量方案"的加分项。理由：真实业务指标是反 Goodhart 最强防线，降级到和人工抽检并列是防线稀释。
- **方案设计器 / 沙箱 / 市场 / CI 插件恢复为核心四件套**：v3 把"三件差异化产物"叙事把市场、沙箱、CI 淡出了。v4 恢复为自建侧身份支柱。工程量承认回升，不再承诺 "2–3 人半年 v1"。
- **onboarding clinic 取代"1–2 次 pairing"**：部分回退。放弃 v3 的克制叙事（"平台团队只做 1 小时引导"），承认首个方案是高接触的，但不叫"共创工作坊"——这个词 v2 的批判说对了会让平台变成咨询交付。折中命名为 onboarding clinic：首个方案陪跑一次完整循环，第二个方案起放手。

**保留自 v2/v3 的改进**（方向漂移报告没要求动、且确实改对的）：

- 引用原文 / quote 字段机制（但改为软约束，不拒绝无引用）
- 可信度 badge 标记（引用 low confidence 时报告高亮）
- 固定回归集 + 季度轮换机制
- 人工抽检的复核人员回避约束
- 结构对比视图（回应"A 和 B 哪个好"的替代话术）
- 结构化抽取验证的 SDK 接入形态与"非必需"标注

这些是 v2/v3 真正的增量，不属于方向漂移的一部分，不回退。
