# P2D-fix · 判定规则 prompt（本次实验核心新增变量）

本次实验相对 2026-04-23 美团实验的**唯一改动**是在 P2D-fix 规则里加入终止条件，防止"回 P1 → 重跑 → P2D → 回 P1"死循环。

下面是完整 prompt——给 Claude-2（续 idea.md 执笔窗口）使用。

---

```
下面是拆台者的反馈。按以下规则判断并处理，产出 idea.md 最终版（v5）或宣布回 P1。

判断规则：
- 如果拆台文本出现"前提不成立"/"假设错"/"根本不该做"/"方向错"类强否定措辞，且这些论据有实质支撑 → 宣布"回 P1 重做"，停止产出 v5
- 否则 → 所有拆台论据都作为框架内修改，更新方案为 v5

终止条件（关键）：
- 如果这是第一次 P2D-fix → 按上面规则执行
- 如果这是第二次（即上一轮已回过 P1、刚刚又跑完一遍 P1→P2D）→ 不论 P2D 说什么，一律走框架内修改产出 v5，不得再回 P1

硬性要求：
- 自己判断，不反问
- v5 末尾加"拆台响应日志"，注明这是第几次 P2D-fix、以及如果是第二次，原 P2D 里的强否定论据如何被框架内消化

【本次是第几次 P2D-fix】
[你手动填：1 或 2]

【P2D 拆台】
[贴入 P2D 产出]
```

---

## 规则设计说明

### 核心变量：终止条件

本规则相对上次实验 prompt 的唯一新增是"终止条件（关键）"段落——引入"第几次 P2D-fix"这一轮次状态参数。

### "第几次"是状态信号、不是人工决策

prompt 里 `【本次是第几次 P2D-fix】[你手动填：1 或 2]` 的手动填写**不违反"无人工决策"实验纪律**——这是客观轮次状态（系统外部可观察的执行历史），不是"是否该回 P1"的主观判断。完全机械化的话，这里可以由外部脚本根据实验在流程中的位置自动填入；本次实验为了操作便利，让用户手动填。

### 本规则与 P2D 原 prompt 的结构性关系

P2D 的 prompt 设计是"预设方向错了、找证据支撑"——它天然产出强否定措辞。P2D-fix 的判定规则是"强否定 + 实质支撑 → 回 P1"——几乎必然满足。两者叠加构成结构性必触发。

本终止条件的设计意图：承认第一次必然触发、但限制循环次数到 1。代价是第二次 P2D-fix 必须机械走框架内修改——即使拆台论据再强也不回 P1。这是用"可能产出有内部矛盾的 v5"换取"实验可以跑完"。

第一次 P2D-fix 按规则触发回 P1——1 号、3 号、5 号拆台论据同时命中"强否定 + 实质支撑"（详见 `round-1/P2D-fix-judgment.md`）。

第二次 P2D-fix 尚未执行（待 Round 2 跑完 P1→P2D 后验证终止条件是否生效）。
