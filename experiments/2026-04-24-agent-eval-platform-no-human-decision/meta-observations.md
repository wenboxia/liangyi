# Meta Observations · 第二次无人工决策版实验

本次实验是对 2026-04-23 美团实验的对照。美团实验暴露了 P2D-fix 死循环结构性问题，本次唯一改动是在 P2D-fix 规则里加了显式终止条件——第二次 P2D-fix 强制走框架内修改。

---

## 截至 Round 1 的关键观察

### 观察一 · 终止条件没根治 P2D-fix，只限制了循环次数

美团实验暴露的 P2D-fix 死循环结构性问题：

- P2D 的 prompt 写的是"预设方向错了、找证据支撑"——它**天然产出强否定措辞**
- P2D-fix 的规则是"强否定 + 实质支撑 → 回 P1"——**几乎必然满足**

本次实验在 P2D-fix 里加了显式终止条件（第二次 P2D-fix 强制走框架内修改）。

**结果**：第一次 P2D-fix 仍然触发回 P1。和美团实验完全同构。

**含义**：终止条件是缓解不是根治。它能把无限循环压缩到"最多两次"，但无法阻止"第一次必触发"这个结构性现象。**P2D prompt 的预设设计与 P2D-fix 判定规则之间的结构性冲突被二次印证**——不是美团场景的偶发。

### 观察二 · Claude-2 的元认知倾向被二次印证

美团实验 Claude-2 在 P2D-fix 位置展现了超规则的执行：对五条拆台论据分类、区分 kill shot vs 框架内可修、列出回 P1 应回答的根问题。

本次实验的 Claude-2 在同一位置展现了**同构的行为模式**：

1. 区分命中规则的论据（1/3/5）vs 未命中的（2/4）——只用命中的做判定
2. 分析三条命中拆台打击的是**不同层级的前提**（测量有效性 / 产品范畴 / 价值叙事）
3. 说明为什么框架内修改不可行：三根独立支柱同时动摇，补丁会产出"内部矛盾的妥协物"
4. 列出回 P1 要重答的三个根问题

**含义**：Claude-2 在规则允许范围内施展结构化判断、不是纯机械执行——这个现象在两个不同场景下稳定复现，**可能是比"P2D-fix 不可委托"更稳定的观察**。

对方法论的一个潜在启发：委托给 Claude-2 的决策，**质量可能优于人对"基于规则判断"的预期**。但 Claude-2 的元认知仍在规则允许范围内——它没法跳出规则系统判断"规则本身要不要执行"。美团实验已经写过这个观察，本次实验是第二次复现证据。

### 观察三 · 场景级正面观察（P2 链条 persona 激活与独立性）

除了两条结构性观察外，round-1 的具体产出里有几个正面信号，记下来作为"P2 链条自动化在此场景下仍然能跑出高质量批判"的证据：

1. **P2A 批判质量高且决定了方向**。Claude-3 在"团队工程负责人 / 技术 Lead"persona 下产出 7 条批判（LLM 裁判效度论证为零、自助 vs 工作坊自相矛盾、对 Langfuse/LangSmith 差异没论证、历史批次回溯成本炸弹、扣分可操作性对 LLM 裁判不成立、拒绝跨 Agent 总分切断高层场景、适配成本系统性低估），每条都是"具体漏洞 + 反证"结构，结论倾向"不批"。这一步的高质量批判是 v2/v3 方向调整的直接驱动力——persona 激活成功，不是走过场。

2. **P2C 精准捕捉 v1→v3 漂移**。漂移报告把漂移分解成 5 步（禁自由打分改窄问题 / 信效度 gate / 规则三级制 / Langfuse 交出基础设施 / 外部计量降级 + 工作坊降级），每一步都在回应一个 P2A 的真实批判，但叠加起来把产品从"共识平台"漂到了"标注驱动诊断系统"。这种"每步合理、总和错位"的诊断是 P2C 独立于 P2A/P2B 存在的核心价值——验证了 P2C 不是冗余步骤。

3. **v4 回退日志的细粒度**。v4 里明确列出 7 条回退（软判断回主规则、信效度 gate 降可选认证、规则三级制取消、Langfuse 降可选后端、外部计量回推荐地位、核心四件套恢复、工作坊改 onboarding clinic）+ 6 条保留（引用原文机制、可信度 badge、固定回归集、复核人员回避、结构对比视图、结构化抽取验证 SDK 形态）。说明 Claude-2 在 2C-rollback 位置的自动判断不是粗粒度"全部回退"，而是逐条识别"哪些是漂移的一部分、哪些是 v2/v3 真正的增量"——这是 2C-rollback 可委托性的二次证据。

4. **P2D 拆台与 P2C 诊断是独立维度**。P2D 的 5 条拆台（裁判一致性 ≠ 业务正确性、Certified 徽章的意识形态撕裂、设计师角色缺位、onboarding clinic 形成咨询业务惯性、Langfuse 非依赖代价过高）聚焦在 v4 的**前提级问题**上，完全不重复 P2C 的漂移诊断。P2D 站的是"假设 v4 内部自洽"的基础上打前提，而 P2C 站的是"假设前提成立"的基础上查漂移——两个维度正交，印证了 P2D 不是 P2C 的加强版。

5. **P2A/P2B 批判没有放水**。P2B 单盲阶段 AI 工程师 persona 下给出非常具体的卡点（窄问题边界、信效度 gate 操作链路、引用原文执行细节、结构化抽取验证场景、人工抽检协议、长尾场景退路、标注反馈周期、回归集更新机制、Langfuse 升级兼容性），不是"这个方案真好"或"没什么问题"式的应付。P2A 给出"结论倾向：不批"的强否定结论。两次批判都有真实对抗力——persona 激活在 P2 链条上稳定。

**含义**：P2 链条（2A → 2B → 2C → 2D）在"无人工决策版"设定下依然能跑出高质量的独立批判，每一步 persona 激活、每一步产出不敷衍、每一步维度独立。**P2D-fix 位置的结构性死循环是孤立于 P2 链条其他环节的——它是 P2D-prompt 与 P2D-fix-规则之间的接口问题，不是"整个 P2 链条在自动化下都崩溃"**。这个观察把问题缩小到了具体的接口位置，而不是对整个批判链条的不信任。

## Round 2 的设计缺口

回 P1 后"新 P0 输入该是什么"在本次实验的自动化设计里**没有被规则化**——原方法论里这是人判断。三种可能的处理：

1. **最严格的自动化**——新 P0 输入只有原始 seed idea，**不带** P2D 和 P2D-fix 判定。代价：新一轮 P1 专家在零上下文 + 同样底模下，大概率产出与 v4 高度相似的方案
2. **半规则化**——新 P0 输入 = 原始 seed + P2D-fix 判定文档。代价：P1 专家不再完全单盲
3. **承认人决策**——在这个点显式做第二个人工介入，识别为"系统边界决策"

Round 2 用哪条路径待定。三条嵌套关系——先跑路径 1 最纯，暴露出的现象决定路径 2、3 是否必要。

---

## 两次实验累积的初步判断（待 Round 2 后扩充）

1. **P2D-fix 结构性死循环是方法论本身的问题，不是场景偶发**——两个不同场景同构触发
2. **终止条件是缓解不是根治**——只能限制循环次数、不能阻止第一次触发
3. **Claude-2 的元认知执行稳定复现**——可能是比 P2D-fix 观察更稳定的现象
4. **回 P1 后的 P0 输入本身是一个未被规则化的决策点**——本次实验暴露的新缺口

---

## Round 2 的场景级观察（路径 1：最严格自动化）

Round 2 走路径 1——新 P0 输入只有原始 seed idea，不带 Round 1 的 P2D/P2D-fix 判定。第 2 次 P2D-fix 强制走框架内修改（终止条件生效）。产出 v1→v5 五版完整演进链。

### 观察四 · 终止条件按设计触发并产出 v5（本次实验核心变量验证）

第 2 次 P2D 触发时，P2D-fix 判定文档确认"不回 P1"，强制把全部五条论据作为框架内修改消化到 v5。v5 确实产出了，没有回 P1——**终止条件按设计工作**。

但"产出 v5"不是成功标准。真正的问题是 v5 有没有"敷衍"——是不是把 P2D 措辞改改包进去、核心承诺不动？

实际产出：v5 为 P2D 的每一条论据加了一个结构性治理模块：

- 论据 1（草案态是噪声）→ **SanityFloorGate**（50 条明暗样本 AUC ≥ 0.65 才能发布 + UI 三明治警告 + 90 天强制决策）
- 论据 2（可选升级 = 永不升级）→ **UpgradeTriggerEngine**（14 天 ≥ 100 runs / 挂 CI blocking / 进管理层仪表盘 / 承担 go/no-go 任一触发即强制入升级队列，超期降级为 warning-only）
- 论据 3（judge 协作者 = reward hacking）→ **Held-out 独立集 + RewardHackingDetector**（iteration_set / holdout_set 强制拆分，suggested_fix 只用 iteration 生成、升级验证只在 holdout 做）
- 论据 4（PM 无测量学元能力）→ **Measurement Reviewer 升为 P0 强制共审**
- 论据 5（配置坟场）→ **LifecycleGovernor**（60 天无更新冻结 / 两周无人看 CI 降权 / 季度清理）

**含义**：v5 不是对 P2D 的防御性妥协，是把强否定措辞工程化为具体治理模块，且每个模块都有可实施的阈值/触发条件/降级动作。**终止条件 + 框架内修改 ≠ 否定 P2D，而是"把强否定转为工程约束"**——这是无人工决策变体第一次在实证层面跑通的一个关键机制。

### 观察五 · v4→v5 改动量 < v3→v4，符合终止条件设计意图

- **v3→v4**（P2C 驱动的主动回拉）：重写 7 个主要章节，回退 12 条具体修改，核心立场从"测量仪"改回"协作者"——**全面调整**。
- **v4→v5**（终止条件驱动的护栏叠加）：保留 v4 全部核心立场/架构/Scorer 协议/成本模型/工单对接/开发者工效学，新增 5 个治理模块 + 调整 1 个角色优先级（MR P2→P0）——**叠加修改**。

**含义**：终止条件期望的行为就是"叠加不重构"。当方案经过 4 轮批判已经足够成熟、但仍有被挑出的漏洞时，恰当的响应是给成熟方案加护栏，不是推翻重来。v5 的改动形态验证了这个期望——**这支撑终止条件不是"强制敷衍"，而是"强制在合适阶段停止重构倾向"**。

### 观察六 · P2C 在本场景扮演了"坐标漂移的根因诊断"而非"漂移枚举"

Round 1 美团场景的 P2C 也是漂移诊断，方式是列举每一步改了什么、累积方向偏哪。本 round 的 P2C 在同样列举之外，提出了三个追问：

1. 你的目标用户真的有 Methodology Lead 这个角色吗？
2. v1 想服务的"想起一个新维度就试试看"的轻量场景，在 v3 还跑不跑得起来？
3. judge 到底是测量仪还是协作者？v1 是协作者、v2 是测量仪、v3 半只脚踩回——这个没定，后面所有漂移都会反复。

**其中第 3 个追问是真正的坐标根因**。v4 明确选"协作者"后，所有回退（恢复 suggested_fix、预算降默认、审阅人改兼任、效度降为升级门槛）才有一个统一的方向依据。

**含义**：同一个 P2 链条步骤（P2C）在不同场景下激活的深度可能不同。Agent 评测场景里 judge 的角色定位是根问题；美团场景里 judge 的角色定位没这么核心，所以 P2C 的形态偏枚举。**P2 链条 persona 对"根问题"的识别能力具有场景自适应性**——不是机械地每场景都产出同构的漂移报告。

### 观察七 · Agent 评测场景对"过度学术化"批判的过度矫正倾向特别强

Round 2 的 v3（2A-rewrite）产出了一份把"统计可辩护"作为准入硬门槛的方案：Spearman ρ ≥ 0.5、300 条校准集/维度、1.0 FTE 方法论专员、5 工作日 SLA、provisional_validity 降级态。单看每一条都是对 P2A 真批判的合理响应——P2A 确实指出了"效度缺失"、"κ 撑不住 go/no-go"、"工作坊不可规模化"等硬问题。

但累积效应是 v1 想服务的"PM 当周起 Profile 试"的场景完全跑不起来。P2C 精确识别出这是"权力从定义好→证明测得准的漂移"——**目标用户从 PM 变成了方法论专员 + 工程师 + ops**。

这个现象在美团风控场景下的对等剧烈度低——美团场景的用户角色本身就偏专业，加学术护栏不会把核心用户挤出门。但 Agent 评测场景的 P0 用户是 PM，对轻量性的敏感度远高于专业分析师。

**含义**：**P2 链条批判对"方向漂移"的驱动强度，与场景目标用户对学术严谨性的容忍度负相关**。Agent 评测这类轻量用户为核心的场景，需要 P2C 这一步特别警觉"批判驱动下的过度学术化"；而风控/合规这类专业用户为核心的场景，P2C 的警觉重点可能是别的漂移方向。

### 观察八 · P2B 工程师单盲与 P2A 工程 Lead 批判的互补度达到了"完全正交"

在本 round 的具体产出里：

- **P2A（Claude-3，工程 Lead）**：批判战略层——Cohen's κ 能不能支撑 go/no-go、效度论证缺失、工作坊冷启动人时、build-vs-buy 差分、suggested_fix 因果闭环、红线一刀切、成本无数字。这些问题都要靠"加算法 / 加统计 / 加治理流程"解决。
- **P2B（Qwen-1，AI 工程师）**：批判工效学层——JSONPath 指向什么具体字段、EvidenceLocator schema 长什么样、工单系统对接 Jira 还是自研、κ 自动回放谁维护、本地 debug 怎么做、单 run 成本怎么透传。这些问题都要靠"写 Scorer Protocol 代码 / 写 YAML 断言示例 / 写 CLI / 写错误码规范"解决。

两条批判激活的改进维度完全不重合。v2（P2A-rewrite）加的是统计护栏，v3（P2B-rewrite）加的是工程骨架——分别覆盖了"可被验证"和"可被执行"两个独立层面。

**含义**：**P2A（投资人 / 工程 Lead）和 P2B（目标用户单盲）不是"批判强度的递进"，而是"批判维度的正交"**。在 Agent 评测这种技术密度高的场景，P2B 不是"验证 P2A 的结论对不对"，而是"捕捉 P2A 看不见的工效学黑洞"。如果没有 P2B，v2 会是一份有统计护栏但没工程细节的 PPT；如果没有 P2A，v3 会是一份有工程细节但没学术护栏的原型。

### 观察九 · 无人工决策变体下首次跑通完整 v1→v5 五版演进闭环

美团 Round 1 里，第一次 P2D-fix 就触发回 P1，所以那次实验没有产出 v5——P2D-fix 的"框架内修改触发下的方案完整形态"是**第一次**在本次实验 Round 2 被观察到。

这套 5 版演进的节奏是：v1 原始共识 → v2 学术严谨倾斜 → v3 工程骨架补齐 → v4 因过度学术而回拉 → v5 回拉后的结构性加护栏。在没有人工介入的情况下完成了"方向飘→发现漂移→方向回→发现新缺陷→结构性加固"的完整调节周期。

**含义**：**方法论的"批判链条 + 拆台 + 回 P1 / 框架内修改"机制在自动化变体下具备自我校正能力**。它不是"人工把关才跑得通"，而是能在规则允许范围内产出接近人工决策质量的演进轨迹——前提是 P2 链条 persona 激活充分、P2C 诊断精确、终止条件在合适时间生效。本 round 是第一次完整证据。

### 观察十 · holdout_set 机制是对 Agent 评测场景特定风险的精确响应

v5 引入 iteration_set / holdout_set 强制拆分，是对 P2D 论据 3（judge 协作者 = reward hacking）的回应。这个设计的必要性在 Agent 评测场景特别显著，因为：

- Agent 评测的 P0 用户（PM + Prompt 工程师）会直接看 judge 反馈并据此改 prompt
- judge 是 LLM，改 prompt 让扣分消失是最直接的优化路径
- 如果 judge 产出的扣分和工程师的优化目标同向，整个评测变成合谋游戏

这个机制在美团风控场景下的必要性弱得多——风控场景的用户不会直接基于 judge 反馈改"策略"，决策链条里还有风控专家、合规、业务审核等多层独立判断。

**含义**：**P2D 的强否定论据在不同场景下对应的工程化响应差异巨大**。Agent 评测场景里 reward hacking 是真问题 → 需要 held-out 集 + detector；风控场景里 reward hacking 不是核心问题 → 不会产出同等机制。这验证了 P2 链条批判的"场景化有效性"——同一个 prompt 的 persona 激活在不同场景会指向不同的工程细节，而不是产出同构的泛泛之论。

## 两次实验累积的判断（Round 2 结束更新）

1. **P2D-fix 结构性死循环在方法论本身**——两场景同构触发，本次实验第二次印证
2. **终止条件按设计工作且产出实质性 v5**——不是敷衍，是把强否定工程化为治理模块
3. **Claude-2 的元认知执行稳定复现**——三个不同触发位置（美团 P2D-fix 回 P1 判定 / Round 2 P2C 诊断 / Round 2 P2D-fix 框架内修改）都展现了超规则结构化判断
4. **v4→v5 改动量 < v3→v4**——符合"叠加不重构"的终止条件设计意图
