# 专家 B 方案：以载体形态优先的专属投资 Skill 设计

## 一、核心判断：这个 Skill 首先是一个“自解释的运行时环境”

在专家 B 看来，一个真正能穿越时间、跨模型使用的投资 Skill，本质上不是一份“漂亮的投资策略说明书”，而是一个**自包含、自维护、自校验的运行时容器**。它必须能够在任意一个具备基础推理能力的 AI 中，仅凭自身内容与用户当次提供的变量，就完成一次完整、安全、时效正确的投资对话。因此，整个设计的重心必须放在三件事上：**事实的时效性编码、规则的完全可执行化、以及载体格式的极简通用化**。

下面给出的方案，不是“建议 Skill 里写什么投资逻辑”，而是“这个 Skill 的文件应当如何被架构，才能让任何 AI 在 2027 年、2029 年甚至更远的时候打开它，都不会悄悄给出一个早已违法的建议”。

---

## 二、载体格式选择：分层 Markdown + 前置结构化元数据

为了让任何 AI（包括不支持 function calling 的纯文本模型）都能立即正确解析，Skill 文件采用 **纯文本 Markdown** 作为主格式，但在文件最顶部嵌入一段 **YAML 前置元数据（front matter）**。这一段 YAML 是机器优先读取的“类型声明”和“时效声明”，其后才是人类可读的自然语言策略。

```
---
skill_id: wenbo_investment_v1
skill_type: persona_and_rule_executor
owner: Wenbo Xia
created: 2026-05-23
declared_current_date_placeholder: "{{CURRENT_DATE}}"
expiry_facts:
  - fact_id: residence_permit
    description: 瑞典居留卡有效期
    hard_date: 2027-01-12
    effect_after: residence_permit_expired
  - fact_id: nordea_card
    description: Nordea 银行卡有效期
    hard_date: 2028-12-31
    effect_after: nordea_card_expired
  - fact_id: tax_id
    description: 瑞典税务局 ID 卡有效期
    hard_date: 2029-09-22
    effect_after: tax_id_expired
  - fact_id: revolut_access
    description: Revolut 可用性（依赖居留状态）
    condition: residence_permit_valid AND china_citizen
    effect_after: revolut_uncertain
  - fact_id: wise_access
    description: Wise 可用性（依赖居留状态）
    condition: residence_permit_valid
    effect_after: wise_uncertain
required_inputs_per_session:
  - available_capital
  - target_allocation_amount
  - investment_horizon_override
  - special_concerns
execution_mode: sequential_constraint_check
---
```

这层前置 YAML 是整个 Skill 的“可执行骨架”。它的设计逻辑是：**把一切会随时间腐烂的事实，从自然语言中抽离出来，变成 AI 可以在执行第一步就进行日期比较的结构化数据**。任何一个 AI 拿到这个 Skill，第一件事不是去读后面的长文，而是解析这个 YAML，把 `{{CURRENT_DATE}}` 替换成真实当前日期，然后逐一计算每个 `expiry_facts` 的状态。这样，“居留卡 2027-01-12 过期”就从一段可能被忽略的文字，变成了一个必定会被计算的布尔值 `residence_permit_valid = false/true`。

## 三、硬到期日的处理：从静态描述变为“时效状态机”

这是专家 B 方案中最具抗腐烂性的部分。P0 想法中提到的几个关键日期——居留卡、Nordea 卡、税务 ID——以及依赖居留状态的 Revolut/Wise 可用性，不能以叙述方式埋在正文里。必须将它们建模成一个**时效状态机**，并规定 AI 在每次执行时必须遵循的检查流程。

具体设计如下：

在 Skill 文件的“第一部分”紧接 YAML 之后，放置一段 **强制性执行前检查流程（Pre-execution Check Protocol）**。这段文字以指令口吻写给 AI，而非写给 Wenbo，确保无论什么模型，只要遵循指令，就会执行这些检查。

**Pre-execution Check Protocol 内容要点（自然语言但高度指令化）：**

1. **日期解析**：从你的系统或用户提供的上下文中，获取当前真实日期 `CURRENT_DATE`。如果无法获取，必须向用户询问当前日期，不可继续执行。
2. **事实状态判定**：逐一比对 YAML 中的 `expiry_facts`：
   - 若 `hard_date` 早于 `CURRENT_DATE`，则对应的事实状态设为 `expired`。
   - 若 `condition` 中包含对其他事实状态的引用，则先计算依赖项，再判定该条件真假。
3. **生成一份“当前约束快照”**：在内部（或向用户展示）列出当前生效和失效的约束。例如：
   - 当前日期 2026-05-23：`residence_permit_valid=true`, `nordea_card_valid=true`, `tax_id_valid=true`, `revolut_uncertain=false`, `wise_uncertain=false` → 所有通道可用。
   - 当前日期 2027-02-01：`residence_permit_valid=false`, `nordea_card_valid=true`, `tax_id_valid=true` → 触发 `residence_permit_expired` 效应，`revolut_uncertain=true`, `wise_uncertain=true`。
4. **将快照作为后续所有建议的硬约束**：任何投资路径、出入金方法、账户使用建议，都必须先通过这个快照的过滤。凡是快照中标记为不可用或不确定的通道，不得作为主要建议，只能作为“待验证”或“历史”提及。

这样设计的好处是：**腐烂的不是 Skill，而是 Skill 每次运行时的输入（日期）**。Skill 本身不需要更新，只要 AI 接受当前日期，它就会自动给出符合当时法律与账户状态的建议。2029 年税务 ID 过期后，同样自动反映。

## 四、跨境支付与市场准入约束的规则编码

跨境约束不能只写成一段“注意：你 Revolut 可能不能用”的提示，而必须变成 **可执行的 if-then 规则矩阵**。在 Skill 文件中，这些规则以“约束规则表”的形式给出，AI 必须将其视为决策的必需条件。

**约束规则设计（以自然语言描述，但结构固定）：**

```
## 规则矩阵：支付通道与市场准入

本矩阵由 Pre-execution Check Protocol 的结果动态激活。每个通道的状态取决于三个基础事实：
- R: residence_permit_valid (居留卡有效)
- N: nordea_card_valid (Nordea卡有效)
- T: tax_id_valid (税务ID有效)
- C: china_citizen (恒真，中国国籍)

### 通道 1：Revolut 海外股票/加密账户
- 可用性判定：R == true AND N == true
- 若 R == false：强烈不建议使用。Revolut 对中国国籍者在无欧盟居留时审核极严，已有账户可能被限制。此为高风险通道。
- 建议动作：若 R == false，引导用户提前将 Revolut 资产转移至替代通道（见下文）。

### 通道 2：Wise 多币种账户
- 可用性判定：R == true OR (R == false AND 用户已在中国完成 Wise 身份验证)
- 注意：Wise 允许中国居民使用，但功能受限。若 R 变为 false，需评估账户是否已切换至中国地址。
- 建议动作：若 R 即将到期，建议提前在 Wise 中更新居住地为国内，并确认投资功能可用性。

### 通道 3：Nordea 瑞典银行
- 可用性判定：N == true
- 到期后：无法接收瑞典克朗转账，但卡本身不作为投资主通道，影响较小。

### 通道 4：中国内地银行与券商（蚂蚁财富等）
- 可用性判定：C == true（恒可用）
- 注意：资金回国或在国内操作不受上述居留状态影响。这是长期稳定通道。

### 通道 5：未来可能的国际券商（如 IBKR、富途、雪盈等）
- 准入判定：取决于届时 Wenbo 的税务居民身份。若 R == false 且已回国，中国税务居民身份下，可通过国内渠道开通美港股。
- Skill 内置建议：当检测到 R == false 时，自动提示用户应切换到以中国税务居民身份申请国际券商，并退出依赖欧盟居留的金融工具。
```

这种写法把“能不能用”变成了 AI 在生成建议前必须执行的逻辑判断。它不是一个提醒，而是一道硬过滤网。任何建议如果与判定结果矛盾，就是违规输出。

## 五、Web Search 能力的设计：以“声明 + 触发条件 + 查询模板”嵌入

Web search 不是一句“请搜索新闻”就能被跨模型执行的。不同 AI 的搜索能力触发方式不同，有些需要显式指令，有些需要特定格式。为了让 Skill 的搜索能力具备可移植性，必须做三层设计：

**第一层：能力声明**

在 Skill 的元数据或开头部分写明：
```
capability_required: web_search
search_trigger: conditional
```
这告诉任何加载这个 Skill 的系统：“若你拥有 web search 能力，请启用；若无，则告知用户你无法执行该 Skill 的全部功能。”

**第二层：触发条件与频率**

不是每次对话都要搜索。Skill 中规定：
- 当用户提问涉及“当前市场状况”“最新消息”“近期事件影响”“现在该加仓什么”等时态敏感词时，触发搜索。
- 当用户提供的是明确的具体金额与操作指令，且不涉及时事时，不强制搜索，以节省时间。
- 每周最多一次“例行宏观扫描”的建议，但由用户确认是否执行。

**第三层：可执行的搜索查询模板**

Skill 中内置一组经过设计的搜索查询模板，AI 可以直接使用或微调，而不是每次都从零构造。例如：
```
search_query_templates:
  - “2026年5月 AI 芯片 政策 市场 新闻”
  - “俄乌 伊朗 局势 对 全球 股市 影响 2026”
  - “OpenAI 上市 最新 进展”
  - “中国 新能源 光伏 政策 2026”
```
模板保证了搜索方向始终与 Wenbo 关注的板块对齐，避免 AI 搜索泛化信息。AI 执行时，将当前日期填入模板中的年份或月份占位符。

这样，搜索就不再是一个模糊的“希望”，而是一个明确可调用的功能模块，即使换了一个 AI，只要它理解“搜索”和“模板”的概念，就能执行出一致性很高的信息获取行为。

## 六、哪些内容固化、哪些作为每次输入：Skill 的边界设计

一个健壮的 Skill 必须像函数一样，有明确的参数和固定代码。专家 B 方案的划分如下：

**固化在 Skill 中的内容（不变或极少变的部分）：**

- 全部个人身份背景（国籍、专业、当前身份描述，但身份描述中含时间词“研究生二年级”是唯一的软肋，处理方式见下文）
- 投资哲学与风格：平衡型、核心卫星划分、超长跑目标、板块偏好（AI/计算机/机器人/通信等）
- 全部约束规则（如上一节所述）
- 投资组合基准快照（2026-05-23 截图数据），但标注为 `snapshot_date: 2026-05-23`，并在 Skill 中写明：“此快照仅代表该时点状态，用于让 AI 了解投资习惯与倾向，不是当前持仓。若用户需要基于当前持仓的建议，需在每次输入中提供最新持仓。”
- 预设的搜索查询模板
- 风险与交易规则偏好（例如核心仓用 ETF、卫星仓允许个股，不接受杠杆衍生品等）
- 跨境通道的备选路径说明（当居留卡过期后，建议的回国后投资架构）

**每次对话由 Wenbo 输入的内容（变量部分）：**

- 当前可用资金总额、本次拟投入金额
- 本次投资的具体问题或需求
- 是否有任何新的个人状态变化（如“我已回国”“我已申请某券商”）
- 是否提供最新持仓（如果希望基于最新持仓分析；若无，AI 应仅基于固化快照的历史倾向给出建议，并明确提醒快照已过时）
- 当前日期（如果 AI 无法自行获取）

这里有一个设计难点：Skill 中“我在瑞典读研究生二年级”这句话本身就携带了时间腐烂性。如果 2028 年打开，这句话就成了一句谎言。专家 B 的解决方案是：将这类**状态描述也参数化**。在 YAML 中增加一个字段 `life_stage`，其值定义为 `"studying_in_sweden_masters"`，并在 Skill 正文中用函数式描述替代静态陈述：

> “Wenbo 当前的生活阶段由 `life_stage` 定义。如果 `life_stage` == `studying_in_sweden_masters`，则其资金特征为‘学生、资金有限’，且物理位于瑞典。当此阶段变更时，Wenbo 会在输入中告知，你需要据此调整对风险承受力与资金流入口径的判断。”

这样，自然语言部分不再写死“我是学生”，而是写“根据当前生活阶段动态调整”。

## 七、Skill 文件的最终结构总览（为了最大化可移植性）

综合以上，专家 B 方案中的 Skill 文件由以下六个板块依次构成：

1. **YAML Front Matter**：元数据、硬日期、条件事实、所需输入、执行模式声明。
2. **Pre-execution Check Protocol（AI 必读指令）**：如何获取日期、计算状态、生成约束快照。用指令体编写，以 “You MUST” 开头，确保模型遵循。
3. **身份与哲学（动态部分）**：Wenbo 的背景、投资目标、风格、板块偏好。用 `life_stage` 变量替代固态描述，用 `investment_philosophy` 固定段落表达核心不变的理念。
4. **约束规则矩阵**：支付通道、市场准入的 if-then 规则，以及当约束触发时推荐的替代路径。这是整个 Skill 法律安全性的核心。
5. **投资组合历史快照**：2026-05-23 持仓，标注为历史参考，附带说明其用途限制。
6. **搜索与信息获取模块**：能力声明、触发条件、查询模板。
7. **输出格式指引**：告诉 AI 最终给 Wenbo 的建议应该包含哪些部分（当前约束状态、基于约束的可选方案、基于搜索的时事分析、核心仓/卫星仓建议、风险提示），以确保建议的一致性。

## 八、立场总结

专家 B 坚持：这个 Skill 的首要价值，不是里面写了多少年化收益率的精妙算法，而是 **它在 2027 年 1 月 13 日那天，当任何一个 AI 被问及“我 Revolut 里的美股要不要卖”时，能毫不含糊地给出“你的居留卡已过期，Revolut 可用性已进入高风险状态，建议立即转移”的结论，而不需要 Wenbo 自己记住所有日期。** 这种健壮性只能通过把时间敏感事实从叙事中剥离、变成前置逻辑、并强制每次执行计算来达成。

这份方案给出的，正是这样一个 Skill 的完整载体设计。它不替 Wenbo 做任何投资决定，但它确保未来任何 AI 在做决定辅助时，都不会跨过现实法律与账户状态的红线。这才是“专属投资 Skill”作为一件知识资产的真正长久价值。
