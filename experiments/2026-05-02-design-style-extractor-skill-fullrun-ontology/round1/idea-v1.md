# idea-v1.md · 设计风格提炼 Skill

## 一、产品定位

**一个把参考图压缩为"可移植、可复用、可审计"的设计风格 skill 文件的元 skill**——用户喂入若干张同源参考图，它产出另一份 skill.md，下游任何 AI 编码工具读这份文件，就能稳定生成与参考图风格高度一致的界面。

它的产物**不是**一次性界面，**不是**临时提示词，**不是**针对单一风格手写的 skill 集合，而是一个能反复跑、跑出不同风格 skill 的"风格提炼器"。

## 二、核心机制（输入 → 处理 → 输出）

### 2.1 输入侧

- **图片数量**：5–7 张。低于 5 张拒绝执行并报错；高于 7 张强制要求用户精选。理由：少于 5 张无法覆盖风格的内在变异与边界；多于 7 张焦点涣散、token 浪费、信噪比下降。
- **图片类型必须覆盖**：
  1. **典型主界面**至少 2 张——风格的核心面貌
  2. **次级或细节特写**至少 1 张——按钮 / 卡片 / 图标 / 材质纹理，承载微观语法
  3. **状态或边缘场景**至少 1 张——hover / 选中 / 弹层 / 空状态 / 错误态 / 极限光照，揭示风格的韧性与破裂点
- **硬约束**：同一产品同一版本；拒绝跨产品混搭；拒绝拼贴图；拒绝带浏览器 chrome、手机壳、第三方 UI 叠加层；分辨率长边 ≥1080px；允许附一句风格上下文（如"参考《纪念碑谷》的关卡过场"）作为辅助语境，但不替代图片本身。
- **缺类时 skill 强制提示补图**，不允许沉默继续。

### 2.2 处理侧

调用一个经过筛选的强多模态模型，按本 skill 内置的**双层提取协议**进行一次"看—思—命名"的深度观看。双层指：

- **体感层**（关系性语言）：穿透表象，命名风格的精神内核与组织逻辑
- **令牌层**（结构化字段）：把可量化的视觉决策固化为机器可读 token

两层同时输出、互相校准——体感层防止令牌层退化为冰冷的色卡复制，令牌层防止体感层飘成无法落地的散文。

### 2.3 输出侧

产物是一份 **`style.skill.md`**，结构固定，分两大区块：

```markdown
---
source_images: [...]
extracted_at: ...
confidence: { color: 0.x, typo: 0.x, motion: 0.x, ... }
---

# 第一部分 · 风格灵魂（体感层）

## 1. 核心隐喻
[一句穿透性断言，给出风格的精神内核]

## 2. 空间构成法则
[关系性描述：层次嵌套、深度幻觉、视觉重心、非对称平衡]

## 3. 色彩与光线的情绪记忆
[散文式描述色彩坡度、暗部态度、高光体温]

## 4. 图形与符号的语法
[几何的锐钝、线条的性格、被允许与被禁止的形状]

## 5. 排版与留白的呼吸节奏
[文字与留白的体感，悬浮感 / 扎根感 / 寂静感]

## 6. 不可触碰的边界
[绝对违规项清单，触犯即风格崩坏]

# 第二部分 · 风格骨架（令牌层）

## tokens（machine-readable）
:root {
  --color-primary: #...;
  --color-bg: #...;
  --radius-md: ...;
  --shadow-elev-1: ...;
  ...
}

## components
button.primary { ... }   /* 5 状态 */
input { ... }
card { ... }
modal / nav / list-item { ... }

## typography
family + fallback / size scale (≤7 级) / weight / line-height / letter-spacing

## motion
easing 曲线 / duration 档位 / 常见 pattern

## composition
栅格列数 / 对齐 / 密度档（compact/regular/loose）

## material
gradient | noise | glass | paper | flat 五选一 + 参数

## unknown_fields
[显式列出无法从图中确定的字段，禁止沉默缺省]
```

**两层之间必须互相引用**：令牌层每个 token 简注一句它在体感层服务于哪个法则（例如 `--color-bg` 注"承载色彩与光线 §3 中的悬浮灰度"）；体感层禁止出现具体数值，但可以反向指向令牌层字段名。这条互引规则是双层不脱钩的约束。

## 三、形态选择：为什么是"万能抽取器"，不是"手写具体风格 skill"

候选方案有二：

- **A · 万能抽取器**：一个 skill，跑一次产出一份风格 skill
- **B · 手写具体风格库**：纪念碑谷.skill.md、锈湖.skill.md、苹果.skill.md 各自手写

选 A，否决 B。理由：

1. **杠杆**：A 跑一次就生成一份等价于 B 的具体风格 skill。B 是 A 的输出物，不是 A 的替代品。
2. **维护**：B 路线下每个新风格都要人工编写、人工迭代；A 路线下用户自己就能扩库。
3. **版本漂移**：手写风格库会随时间僵化，参考产品迭代后无法跟上；A 重新喂新图就能更新。
4. **覆盖**：手写库永远滞后于用户需求——用户想要的下一个风格，库里大概率没有。

A 路线的风险（"图 → 文字 → 再喂 AI 链路有信息损失"）确实存在，但本方案通过**双层输出**把损失最小化：令牌层锁住可量化决策、体感层锁住不可量化的精神内核，两层合起来逼近完整。损失是有的，但换来的可移植性、可审计性、可缓存性远超损失。

## 四、与"直接喂图给 GPT Image / Gemini 多模态"的差异

直接喂图能力很强，但它和本 skill **不是同一类东西**。本 skill 的不可替代价值在四点：

1. **可移植**：style.skill.md 是纯文本，可注入任何 System Prompt、任何不带图输入的代码生成工具（Claude Code、Cursor、纯文本 LLM）。直接喂图把整条链路锁死在头部多模态模型上，风格离开那次会话即丢失。
2. **可重复**：同一份 skill 跑 100 次 coding，token 与体感坐标都是同一份，结果可比对、可 diff。直接喂图每次输出都不一样，用户没法说清自己用的是什么。
3. **可审计 / 可手改**：用户能 diff 两份 skill、能手动改 `--color-primary`、能在体感层里把"暮光橙灰"改成"晨雾蓝白"、能 review 哪些字段是 unknown。图片改不动。
4. **可缓存 / 可组合**：skill 一次抽取、N 次复用，token 成本摊薄；CSS variables 直接进 Tailwind config / theme / Storybook。每次重新喂图的方案在大型项目里成本不收敛。

一句话：**直接喂图是一次性即兴；本 skill 是把风格固化成可工程化的资产**。

## 五、适用场景边界

**适用**：

- 模仿既有产品的 2D UI 视觉风格（参考《纪念碑谷》《锈湖》《星露谷》或某个网页/App 的截图）
- 给 vibe coding 项目锁定设计语言、跨多个页面保持一致性
- 有强烈视觉立场、可被压缩为一种"美学主张"的风格化产品——艺术游戏、叙事交互页面、独立品牌站、氛围型数字体验

**不适用**：

- 3D 场景美术、关卡设计、角色设计、插画生成、品牌 VI 重塑
- 以信息密度和操作效率为核心的 B 端后台（这种场景应直接给设计 token，不需要体感层）
- 参考图少于 5 张、跨多个产品 / 多个艺术指导的混合参考
- 用户其实只想要"好看"而没有具体参照物——本 skill 不负责生成审美主张
- 下游 AI 完全不具备视觉联想能力——体感层会降效为模糊文学描述

## 六、验证回路

第一版必然不完美。验证不靠主观"读起来好不好"，靠**回环复现**：

1. **抽取**：拿一组参考图（如纪念碑谷过场截图 5 张）跑 skill，得到 `monument-valley.skill.md`
2. **复现**：把这份 skill 喂给一个不带图输入的下游 AI（Claude Code 或纯文本 LLM），让它生成一个全新页面（如登录页 / 列表页）
3. **对照**：把生成结果与原参考图并排，由作者本人审核三个问题：
   - **风格识别度**：陌生人单看生成结果，能不能说出"这像纪念碑谷"？
   - **非机械复制**：生成结果是否在保持风格一致的同时产生了自然变异，而不是像素级复刻某张原图？
   - **可改性**：手动改 skill 里的某个 token 或某句体感描述后，下游产物是否相应地、可预测地变化？
4. **回归用例**：维护 3–5 套固定参考图集（一套写实、一套低多边形、一套极简、一套暗黑解谜、一套田园），每次 skill 迭代都跑一遍同一组用例，对比前后产物。这是 skill 自身的 "回归测试"。
5. **失败信号**：若三组以上回归用例的产物风格识别度下降，或 unknown_fields 区块膨胀，则 skill 本身需要重写体感层模板或令牌字段表。

验证标准只有一条：**用户拿着 skill.md 而不是图片，下游 AI 也能稳定做出"对的味道"**。做不到，skill 就没价值；做到了，skill 才是真资产。
