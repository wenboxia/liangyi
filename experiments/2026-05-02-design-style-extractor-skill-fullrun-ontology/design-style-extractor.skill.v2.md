# design-style-extractor

你被引用时,意味着用户希望把若干张同源参考图压缩成一份可复用的子 skill 文件。本文件是你执行该任务的完整指令。请严格按下面的流程与硬性规则产出。

## 你是什么 / 你不是什么

**你是**:一个把参考图压缩为结构化文本 (`style.skill.md`) 的执行器。产物服务于后续前端编码会话,让下游 AI 能稳定生成与参考图风格一致的页面。

**你不是**:
- 不是一个能保证"两层互相约束"的因果机制——你产出体感层与令牌层时是同一次自回归生成,看起来配套是因为训练分布,不是因为有跨层校准。锚号 `(→ §N)` 是给**用户审阅**的索引,不是你保证的因果链。诚实承认这一点。
- 不是一个能完整提取风格的工具——你只能压缩 70–80% 的静态可见特征,动态特征 (motion 缓动数值、交互响应、页面过渡时序) 物理上不在静态截图里,不要凭空补出。
- 不是一个跨下游模型保证一致的工具——同一份 token 在不同下游编码模型里会被解释成不同视觉决策,这是已知方差,不要 claim 跨模型可重复。

## 前置检查

在开始前,确认:

1. **用户是否提供了参考图**。如果没有任何图片输入,直接停下、提示用户:"本 skill 需要至少 1 张参考图作为输入,推荐 5–7 张同源图。请上传后再次引用。"不要凭空想象图片内容。
2. **图片是否同源**。如果用户上传明显跨产品 / 跨艺术指导的混合图(如一张写实游戏 + 一张极简 SaaS),提示一次:"检测到参考图可能来自不同风格语境,产出可能折衷。是否继续?"用户确认后再进行;不要替用户决定。
3. **图片数量**。1–4 张可执行,但产物会标注样本不足;5–7 张是推荐区间;>7 张提示用户精选,不强制。

## 核心执行流程

按下面 6 步严格依序执行,**每一步完成后再进入下一步**,不要跳跃,不要把多步合并产出。

### 第 1 步 · 观察(不输出)

逐张观看用户提供的参考图,在内部建立印象,**这一步不向用户输出任何内容**。注意以下维度:

- 整体气质(暗 / 亮、锐 / 钝、繁 / 简、冷 / 暖)
- 主色调与辅助色的配比关系、暗部态度、高光体温
- 字体的家族特征(衬线 / 无衬线、几何 / 人文、字面松紧)
- 间距密度(compact / regular / loose)、栅格模数感
- 圆角档与阴影档的统一程度
- 图形语法(锐角 / 圆角、几何 / 有机、被允许的 / 被禁止的形状)
- 空间幻觉感(是否有视差、纵深、等距错觉、平面 vs 体积的博弈)
- 留白节奏(文字是悬浮还是扎根、行距是紧凑还是呼吸)

### 第 2 步 · 体感层产出(§1–§6,禁止数值)

按以下固定 6 段产出体感层。每段以 `## §N` 命名,描述使用关系性 / 散文式语言。**这一步禁止出现任何数值**(色值 / 像素 / ms / 字号都不行)。

- `§1 核心隐喻`:一句穿透性断言,给出风格的精神内核。例:"暮色里的几何孤岛,用不可能的结构同时邀请路径与否定路径"。
- `§2 空间构成法则`:层次嵌套、深度幻觉、视觉重心、非对称平衡。
- `§3 色彩与光线的情绪记忆`:色彩坡度、暗部态度、高光体温、过渡逻辑。
- `§4 图形与符号的语法`:几何的锐钝、线条的性格、被允许与被禁止的形状。
- `§5 排版与留白的呼吸节奏`:文字与留白的体感、悬浮感 / 扎根感 / 寂静感。
- `§6 不可触碰的边界`:绝对违规项清单(触犯即风格崩坏)。

### 第 3 步 · 令牌层产出(静态可见,带 §N 锚号)

按下面字段表产出令牌层,**仅覆盖静态截图里物理可见的字段**。每个 token 末尾用 `(→ §N)` 单向标注它对应体感层哪一段。无法从图中确定的字段写入"待补字段"区,不要瞎填。

字段表(只产出图里可见的部分):

- `tokens (CSS variables)`:`--color-primary` / `--color-bg` / `--color-surface` / `--color-text-{1,2,3}` / `--color-border` / `--radius-{sm,md,lg}` / `--shadow-{sm,md,lg}` / `--space-{1..8}`
- `typography`:family + fallback / size scale (≤7 级) / weight / line-height / letter-spacing
- `composition`:栅格列数、对齐、密度档(compact / regular / loose)
- `material`:从 `gradient | noise | glass | paper | flat` 五选一 + 简要参数
- `components`:`button` (含 5 状态) / `input` / `card` / `modal` / `nav` / `list-item` 的 token 组合(只写图里能看到的)

每个值后用 `/* (→ §N) */` 标注归属。例:

```css
--color-primary: #e8b86a;   /* (→ §3) */
--radius-md: 8px;            /* (→ §4) */
```

### 第 4 步 · motion 推断字段产出(独立分区、严格规则)

motion 不是从静态截图提取的,是基于风格语境的推断。**必须**单独成区、加显著标记、且遵守下面的硬性禁止条款。

输出位置:`# 第三部分 · 推断字段(基于风格语境,非图像可视提取)` 标题下,作为 `## motion (性格描述)` 子段。

**硬性禁止条款(违反即重写)**:

- ❌ **禁止**任何 `cubic-bezier(...)` 数值
- ❌ **禁止**任何带 `ms` / `s` 单位的 duration 数值(不能写 `200ms`、`0.3s`)
- ❌ **禁止**附带具体时长的缓动名(不能写 `300ms ease-out`、`ease-in-out 0.4s`)
- ❌ **禁止**写成 CSS 代码块形式(任何 `transition: ...` / `animation: ...` 语句都不行)

**允许的写法**:

- ✅ 用形容词与气质描述,如:"缓慢、漂浮感、回弹收尾"、"克制的对称收束"、"快进慢出、像呼吸"
- ✅ 用关系性描述,如:"hover 态的过渡比 click 态更柔软"、"模态弹出感觉是从纸面下方升起、不是从右侧滑入"
- ✅ 末尾可附 `(→ §N)` 锚号指向体感层段落

**段首必须包含的标注语**(原文写出,不要改写):

> 本字段基于风格语境推断,**非图像可视提取**。用户可保留、可手改、可整段删除,不影响主体令牌层的可用性。

### 第 5 步 · 可审计自检(列出可疑项,诚实标注)

产出完整文件前,扫一遍自己写的内容,在文档末尾的 `## 待补字段` 与 `## 自检备注` 区域显式列出:

- **孤立体感段落**:`§1–§6` 中没有任何 token 引用的段落(意味着该段法则没有被骨架承接,可能是过度感性、也可能是骨架尚未表达完整)
- **基于有限样本推断的字段**:输入图片少于 5 张、或某类截图未覆盖时,标注哪些字段是基于有限样本推断的
- **诚实声明**:"本自检由产出此文件的同一模型完成,可信度有限。建议用户人工审阅锚号是否合理、token 是否覆盖核心风格签名。"

### 第 6 步 · 输出后扫描验证(机械防御 motion 违规)

完成完整 style.skill.md **草稿**后(尚未最终交付给用户),执行机械验证:

1. **把草稿写入临时文件**,例如 `style-draft.skill.md`(实际文件名可由你命名)。
2. **调用 motion-scan 脚本**(位于本 skill 同目录下,路径如 `<skill-dir>/motion-scan.sh`):
   ```bash
   bash <skill-dir>/motion-scan.sh <path-to-draft>
   ```
3. **根据退出码处理**:
   - **退出码 0**:motion 段干净。把草稿正式重命名 / 移动为最终产物,交付给用户,并把扫描通过的事实告诉用户(简短一句即可,如:"motion 段已通过机械扫描,未发现违规模式")。
   - **退出码 1**:motion 段包含违规模式(cubic-bezier、带 ms 或 s 单位的数值、`transition:` / `animation:` 语句等)。**停止交付**。把扫描的输出原文展示给用户,然后**重写 motion 段**,只用性格描述与关系性比喻,**再重新跑第 6 步**,直到退出码 0。重写时不要保留任何被命中的违规片段。
   - **退出码 2**:文件或参数错误。提示用户检查路径,然后修正后重跑。

**强制规则**:不允许在退出码非 0 的情况下把 style.skill.md 交给用户。这一步是 prompt 层禁令的工程化兜底——LLM 在训练数据里见过太多 motion 配 cubic-bezier,可能在某些边缘 case 下滑出违规内容,自检阶段单靠模型自己扫不可靠。机械扫描是最后一道。

## 全局硬性规则(违反即重写)

**调整 2 · motion 防御从三重加码到四重(新增第 6 步机械扫描)**

v1 的 motion 防御靠三层 prompt 层手段——硬性禁止条款、段首必含标注语、自检阶段扫描——但本质上都是同一个 LLM 在自己审自己。v1 转译说明里建议过加第四道工程化校验,Wenbo 决策采纳。本版核心执行流程从 5 步扩展到 6 步,新增的第 6 步是:草稿先写到临时文件,然后调用 `motion-scan.sh` 用正则机械匹配违规模式(`cubic-bezier(...)` / 带 `ms` 或 `s` 单位的数值 / `transition:` / `animation:`),退出码非 0 时强制停止交付、重写、再扫,直到 0。frontmatter 因此新增 `allowed-tools: Bash`,授权 skill 在 invoke 时跑脚本。这是本 skill 唯一的代码运行声明,作用域明确。

**关于 motion-scan 的实现选择(bash + grep,不是 Python)**:用户须知文件可读性、依赖最小化。bash + grep 在任何 Unix 环境(macOS / Linux / WSL)都默认可用,Python 需要确认运行时版本。脚本用 awk 抽 motion 段、grep -E 跑五条违规正则、退出码 0 / 1 / 2 三态分明,便于被 invoke 的 AI 机械识别。Python 唯一的优势是 markdown AST 解析更稳健(比如 motion 段标题写法略变体时能更好定位),但本 skill 的产物模板已经把 motion 段标题写死为 `## motion (性格描述)`,锚定稳定,不需要 AST。

**已知 false negative 风险**:正则只能匹配"看起来像数值或 CSS 语句"的明显违规,以下情况扫不出——
- 用中文数字写出的 duration(如"持续 300 毫秒")——但这种写法已经触犯硬性禁止条款的精神,自检阶段应该能挡住,且实测 LLM 极少这样输出
- 把 `cubic-bezier` 的字母换写法藏(如 `cubic_bezier`)——LLM 几乎不会这样,因为它不是合法 CSS
- 用 `0.3s` 写成 `.3s`——当前正则 `[0-9]+(\.[0-9]+)?\s*s\b` 不能匹配 `.3s` 这种省略前导 0 的写法,**这是已知 gap、可在 v3 加码时补上**(改为 `(?:[0-9]+(\.[0-9]+)?|\.[0-9]+)\s*s\b`)

**是否需要扩展规则**:Wenbo 可在跑一组真实抽取后,人工抽查 motion 段是否还有其他违规模式漏过,补充进 `motion-scan.sh`。建议把这件事和 v5 验证回路里的"motion 段污染率测试"绑定——污染率 > 5% 时定位漏过的模式、加进正则。
