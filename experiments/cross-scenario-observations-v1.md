## 二、跨场景同构复现(结构性发现)

两次实验稳定复现的四个现象,是目前证据最强的结构性发现。

### 2.1 P2D-fix 死循环的结构性必然

两场景首次 P2D-fix 都触发了"回 P1"——不是运气问题,是 P2D prompt 设计与 P2D-fix 判定规则之间的结构性冲突:

- P2D 的 prompt 写的是"预设方向错了、找证据支撑"——它**天然产出强否定措辞**
- P2D-fix 的规则是"强否定 + 实质支撑 → 回 P1"——**几乎必然满足**

Round 2 加了终止条件后,能把无限循环压缩到"最多回 P1 一次"。但**第一次必触发**这个现象仍然稳定——Round 2 的第一次 P2D-fix 还是触发了回 P1 的条件(只是因为这是第一次、没动用终止条件)。

**含义**:P2D-fix 不是某一场景的偶发故障,是方法论自动化变体下的固有结构。终止条件是缓解补丁,不是根治。如果不改 P2D 的 prompt 或 P2D-fix 的判定规则,任何新场景跑自动化变体都会在第一次 P2D 位置触发回 P1。

### 2.2 Claude-2 元认知执行的跨位置稳定性

Claude-2 在不同的自动化决策位置都展现了"超出 prompt 机械条件的结构化判断"特征:

- 实验 1 美团 · P2D-fix 位置 — 对五条拆台论据分类、区分 kill shot vs 框架内可修、列出回 P1 应回答的根问题
- 实验 2 Round 1 · P2D-fix 位置 — 同构行为,三条命中论据打击不同前提、说明框架内修为何不可行
- 实验 2 Round 2 · P2C 漂移诊断 — 从"漂移枚举"升级为"追问坐标根因"(judge 是测量仪还是协作者)
- 实验 2 Round 2 · P2D-fix 框架内修改 — 把五条强否定论据逐条工程化为治理模块,未产生防御性妥协

三个不同触发位置、两个不同场景、都稳定复现"在规则允许范围内施展结构化判断"的行为模式。

**含义**:Claude-2 的元认知倾向可能是比"P2D-fix 死循环"更稳定的现象。但关键边界没变——Claude-2 的自主判断都在**规则允许范围内**,它没法跳出规则系统判断"规则本身要不要执行"(这是边界决策,见 2.4)。

### 2.3 P2 链条 persona 四步正交

两场景都印证了 2A → 2B → 2C → 2D 是四个**维度正交**的批判,不是强度递进:

- **P2A(投资人 / 领域 Lead)** · 战略层批判 — 方案的效度、信度、商业可行性、build-vs-buy
- **P2B(目标用户单盲)** · 工效学层卡点 — 能不能接着写代码、本地 debug、工单对接、schema 规范
- **P2C(知情复审)** · 漂移诊断 — 每步合理、总和错位的路径分解
- **P2D(拆台专家)** · 前提拆台 — 假设方案内部自洽的基础上打它的前提

Agent 评测 Round 2 里的 P2A 和 P2B 对比尤其清晰:P2A 指向"统计护栏(κ、ρ、校准集)",P2B 指向"工程骨架(Scorer Protocol、EvidenceLocator、工单字段映射)",两者指向的改进维度**完全不重合**。

**含义**:自动化变体下 P2 链条仍然跑出高质量独立批判——每一步 persona 激活、每一步不敷衍、每一步维度独立。**P2D-fix 的死循环是孤立于 P2 链条其他环节的接口问题,不是"整个 P2 链条在自动化下都崩溃"**。

### 2.4 可委托 vs 不可委托的决策点分类

两场景稳定出现的分类:

**可委托给 Claude-2(质量不差)**:
- P1.3+1.4 两份专家方案综合 + idea.md 执笔
- 2A-fix / 2B-fix / 2C-rollback 的批判取舍(响应 / 忽略 / 回退)
- Round 2 的 2D-fix 框架内修改(规则明确时)

**不可委托**:
- P2D-fix 的"框架内修改 vs 回 P1"判定(无客观规则能撑住 + P2D 预设导致判定必然触发)
- 实验退出决策(是否继续自动跑、是否收束观察)

**性质差异**:
- 可委托的是**系统内部的局部判断**——批判是否有理、方向漂移是否可接受,这些在 Claude-2 的上下文里有判断素材
- 不可委托的是**系统的边界判断**——是否终止、是否退出、是否承认前提级失败,这些需要站在规则系统之外

这个分类是本体启发二的核心素材(见第四节)。

## 三、场景化现象(只一侧出现或表现不同)

值得留档但不上升为结构性发现的四个现象。

### 3.1 P2C 诊断深度的场景差异

- **美团** · P2C 产出是"漂移路径枚举"——产品从"风控智能体产品"漂到"FTE 替代项目"的分步路径
- **Agent 评测** · P2C 在漂移枚举之上提出三个**根因追问**,最关键的是"judge 是测量仪还是协作者?v1 是协作者、v2 是测量仪、v3 半只脚踩回——这件事没定,后面所有漂移都会反复"

Agent 评测 Round 2 的 v4 能实现干净的立场回拉,直接依赖这个根因被识别出来。

**判断**:P2C 的诊断深度可能取决于场景本身是否有"一个可定位的坐标根因"——Agent 评测场景有(judge 的角色定位),美团场景里漂移来自多个独立方向(tier 化、可解释性、工作坊等)、没有单一坐标根因。这是场景特性,不是 P2C prompt 设计差异。

### 3.2 过度学术化倾向的场景敏感度

两场景 P2A 批判驱动 v2 往学术严谨方向倾斜的行为同构。但倾斜的后果差异巨大:

- **美团** · 加学术护栏(可解释性、人工复核比例、灰度阶段)不会把核心用户挤出门——风控场景的用户本身就偏专业
- **Agent 评测** · 加学术护栏(Spearman ρ ≥ 0.5 准入、300 条校准集、1.0 FTE 方法论专员)直接把 PM "当周起 Profile 试"的核心场景挤出门

这个差异迫使 Agent 评测 Round 2 在 v3→v4 做一次显著的立场回拉;美团场景没有同等剧烈的回拉需求。

**判断**:**P2 链条批判对"方向漂移"的驱动强度,与场景目标用户对学术严谨性的容忍度负相关**。P0 用户越接近专业角色(风控、合规、QA Lead),过度学术化的杀伤越小;P0 用户越接近轻量角色(PM、产品运营),杀伤越大。这对 P2C 这一步在不同场景下要警觉的漂移方向有含义——不是所有场景都要盯同一类漂移。

### 3.3 reward-hacking 风险的场景特异性

Agent 评测 Round 2 的 v5 引入 iteration_set / holdout_set 强制拆分 + RewardHackingDetector,是对 P2D 论据 3(judge 协作者 = reward hacking 合谋游戏)的工程响应。

- **Agent 评测场景** · P0 用户(PM + Prompt 工程师)直接基于 judge 反馈改 prompt,judge 又是 LLM——合谋路径极短,reward hacking 是真风险
- **美团场景** · 决策链条里有风控专家、合规、业务审核等多层独立判断,合谋路径长,reward hacking 不是核心问题

holdout_set 机制在美团场景里不会产生同等必要性。

**判断**:**P2D 的强否定论据在不同场景下对应的工程化响应差异巨大**。persona 激活具有场景化特异性——同一个 prompt 在不同场景指向不同的工程细节,而不是产出同构的泛泛之论。

### 3.4 完整 v1→v5 闭环是 Round 2 独有

美团 Round 1 首次 P2D-fix 就触发回 P1,所以 v5 是通过"人工介入 + 前提级调整补丁"产出的,不是自动化规则下的 v5。

Agent 评测 Round 2 因为终止条件,**第一次**在自动化规则下跑通了完整五版演进链:v1 原始共识 → v2 学术倾斜 → v3 工程骨架 → v4 因过度学术而回拉 → v5 回拉后结构性加护栏。

**判断**:终止条件不仅解决死循环问题,还让方法论在自动化变体下首次展示了"方向飘→发现漂移→方向回→发现新缺陷→结构性加固"的完整自我校正能力。这是单次观察,需要再跑 1-2 个场景的 Round 2 看这个完整闭环是不是稳定出现。

## 四、对美团实验三个本体启发的证据更新

美团 meta-observations 提出的三个本体启发(存作候选观察、未进本体)。Agent 评测两轮的证据如何更新这些启发?

### 4.1 启发一 · 人工决策密度可能不均匀

美团实验的陈述:前几个 fix 的决策点(2A-fix/2B-fix/2C-rollback)Claude-2 能自主做到不差的质量,所以"所有 fix 都由人决策"可能是保护过度。

**Agent 评测证据**:
- Round 1 的 2A-rewrite、2B-rewrite、2C-rollback 全程自动化,产出质量不差
- Round 2 的同样三个环节同构,质量同样不差
- Round 2 的 2D-fix(规则明确时)自动产出 v5,没有敷衍

**更新判断**:启发一被**跨场景二次强化**。两次实验都证明了"前几个 fix 可委托"不是偶发。但仍然不到"大多数情况下"的门槛——两场景的用户群体差异大、场景数量少。

### 4.2 启发二 · "边界决策"作为本体概念

美团实验的陈述:P2D-fix 不可委托不是偶然,那里是"站在规则系统之外判断要不要退出"的边界决策。方法论里有些决策是系统内部可判的,有些必须系统外判。

**Agent 评测证据**:
- Round 1 的 P2D-fix 位置同样不可委托(同构触发回 P1)——强化
- Round 2 因为终止条件,"要不要回 P1"这个边界决策被**事先规则化**为"第二次强制框架内修改",运行时 Claude-2 就不再需要做边界判断了——**这是对启发二的精细化**

**对启发二的精细化**:

边界决策的本质可能不是"必须人做",而是"**必须要有站在系统外的决策依据**"——可以是:

1. **运行时由人做**(美团实验)
2. **事先由人设计规则消化掉**(Agent 评测 Round 2 的终止条件)
3. **外部规则系统持续兜底**(未出现的第三种形态)

终止条件本质是"人在实验设计时预先做好的边界决策"——它让 Round 2 的 Claude-2 可以自动完成看起来像边界判断的动作,因为决策已经被设计者(人)事先做完了。

这个精细化对启发二很关键:**边界决策可以被规则化消化、但规则本身必须是站在系统外被设计的**。这条路径让"人的介入密度"可以进一步压低——不是每次运行时都需要人,只需要在设计环节有人。

**更新判断**:启发二从"嫌疑"升级为**带有精细化描述的候选观察**。

### 4.3 启发三 · 立场三精确化

美团实验的陈述:立场三可能从"人的核心价值是做出最终决策"精确化为"人的核心价值是做出那些站在系统外的决策"。

**Agent 评测证据 + 启发二精细化后的影响**:

如果启发二精细化为"边界决策可以被事先规则化",那么立场三的表述可能还要再精细一层:

- 第一版(现在的立场三):人的核心价值是做出最终决策
- 第二版(美团启发三):人的核心价值是做出那些站在系统外的决策
- 第三版(本次观察的候选表达):**人的核心价值是设计系统的边界规则 + 在规则未覆盖的边界情景中做判断**

这个表述把"人的不可替代性"从"每个决策点亲自做"分解为两部分:

- **设计环节** · 人决定系统的边界(什么时候停、什么时候退出、什么算前提级失败)
- **运行环节** · 只在规则未覆盖的意外情景中介入

如果启发二成立、启发一可操作化,立场三的这个第三版就是它们的立场层汇总。

**更新判断**:立场三的精细化方向在本次实验里得到**间接支持**(通过启发二的精细化)。但立场层重写是重度改动,需要更多场景证据。

### 4.4 证据强度总评

| 启发 | 美团一次证据 | Agent 评测两轮证据 | 当前证据强度 | 下一步需要 |
|---|---|---|---|---|
| 启发一 · 密度不均匀 | 提出 | 跨场景二次复现 | 候选观察(加强) | 再跑 2-3 个不同场景确认 |
| 启发二 · 边界决策 | 提出 | 强化 + 精细化(三种消化路径) | 候选观察(加强 + 精细化) | 再跑 1-2 个不同场景验证精细化 |
| 启发三 · 立场三精确化 | 提出 | 间接支持(通过启发二) | 候选观察(与启发二绑定) | 跟随启发二的证据积累 |

**离本体门槛还有距离**。按立场二"大多数情况下有效",可能还需要 2-3 个不同类型场景(比如 C 端个人消费产品、开源工具、内部工具)的自动化变体实验。

## 五、对实验设计本身的发现

### 5.1 终止条件规则被 Round 2 验证按设计工作

Round 2 的 P2D-fix 终止条件是"第二次强制走框架内修改"。实测:

- 第一次 P2D-fix 仍然触发回 P1(规则允许)
- 第二次 P2D-fix 强制框架内修改,产出 v5 不回 P1
- v5 的质量:**实质性产出**——把 P2D 的五条强否定论据工程化为五个具体治理模块(SanityFloorGate / UpgradeTriggerEngine / RewardHackingDetector / MR 升 P0 / LifecycleGovernor),每个都有阈值、触发条件、降级动作

**结论**:给 P2D-fix 加终止条件是可行的工程补丁。它不阻止"第一次必触发"这个结构性现象,但把无限循环压缩到"最多一次回 P1"。

### 5.2 "回 P1 后新 P0 输入规则化"缺口仍未验证

Round 1 暴露的缺口:回 P1 后新 P0 输入该是什么(原始 seed / 带判定 / 承认人决策)在自动化设计里没被规则化。Round 1 留了路径 1/2/3 三个候选。

Round 2 走了路径 1(最严格自动化:新 P0 输入只带原始 seed)。但 Round 2 因为终止条件,第二次 P2D-fix 没触发回 P1——**所以路径 1 的"新 P0 输入合理性"这个问题并没有被实际暴露出来**。

要验证这个缺口,需要设计一个"第一次 P2D-fix 就必须走回 P1 → 然后观察新 P1 产出质量"的实验。Round 2 没提供这类证据。

### 5.3 下一步实验场景候选(仅候选,不是建议)

如果要继续这条实验线,候选场景方向:
