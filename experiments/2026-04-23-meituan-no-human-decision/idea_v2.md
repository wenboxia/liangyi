# idea.md (v2)

## 产品定位

一套以证据为核心的商家刷单风控智能体，通过**黑白区全自动处置 + 灰区智能体辅助人审 + 大客区强制深度复核**的三档分流，替代一线风控员的重复性判别工作，同时保留对抗黑产的核心人力。首年目标：在刷单判别岗位上替代 55%~70% 的 FTE，建设期成本回收周期 6~8 季度。

## 目标使用者 / 被影响方

**直接使用者**：美团大众点评与外卖平台风控运营。组织上拆成两条线——
- **一线判别员**：工作重心从"逐单看数据下结论"转为"灰区案件三选一决策 + 大客案件深度复核"，人均日处理案件量目标提升 3~4 倍。
- **黑产情报小组**（保留、不缩编）：负责新作弊模式发现、规则与对抗样本挖掘、周级规则更新决策。这部分人力恰恰是对抗黑产的根本武器，不在 FTE 替代范围内。

**被影响方**：
- **平台商家**：误判直接影响经营。大客/连锁/高 GMV 商家一律进强制深度人工复核通道，系统永不自动处置。
- **消费者**：刷单污染评价与排序。
- **合规商家**：承担不公平竞争成本。
- **黑产刷单团伙**：主要对抗对象，会以日级周期反推系统边界。

## 核心机制与判断逻辑

核心立场：**在商家申诉、监管问询、合规审计三重压力下，可解释性是承重结构而非装饰。** 判决主干必须是可还原证据的规则与可解释模型；黑盒端到端模型只做辅助感官；LLM 完全不上在线判决链路。

### 三档分流架构

| 分档 | 占比（目标） | 处置方式 | FTE 占用 |
|------|------|------|------|
| 黑白区（规则高置信 + GBDT 高分同向） | 55%~65% | 系统直接处置，事后抽检 | ~0 |
| 灰区（单侧高分或双侧中分） | 25%~35% | 智能体预组织证据，人工三选一 | 人均产能提升 3~4× |
| 大客区（头部商家 / 连锁品牌 / 高 GMV / 历史争议） | 5%~10% | 强制深度人工复核，系统只做建议 | 维持现状 |

这一分档**正面回应"既要替代绝大多数又要双重高置信"的矛盾**：自动处置的边界就收在黑白区，灰区不追求自动化，只追求人效提升。FTE 节省的两个来源是"黑白区直接替代"和"灰区单案耗时压缩"，不是一句"接管绝大多数"混过去。

### 判决管线

**第一段：结构化证据提取。** 六维度（订单、用户、商家、设备、支付、评价）特征由特征中台统一维护与版本化。

**第二段：分层打分。** 规则引擎负责显式经验沉淀与高确信拦截；GBDT 负责灰区边界判别，SHAP 输出 Top 贡献特征；商家行为序列 Transformer 作为**离线辅助信号**，对灰区做补充风险分与注意力高亮，但**不在在线链路上**，不参与毫秒级判决。

**第三段：报告生成与人工决策台。** LLM 仅在运营工作台**异步**生成自然语言报告，负责把规则命中、GBDT 分与 SHAP、序列模型高亮片段组织成人类可读的证据摘要。LLM **不在在线判决链路上**、不贡献风险分、失败时降级为模板化结构报告。这直接回应"既然 LLM 可以降级业务不中断，它为什么在关键路径上"——v2 中它从关键路径上被移除了。

## 系统形态 / 接入方式

**在线链路**：订单落库与评价发布节点，Flink 流处理 → 特征查询 → 规则引擎 → GBDT，毫秒级返回风险分。全程**无 LLM**。

**离线链路**：T+1 对活跃商家跑行为序列模型，产出灰区候选清单与注意力热力。

**运营工作台**：LLM 按案件异步生成报告，运营打开案件时报告已就绪；降级路径为结构化模板。

**灰度与门槛**：新系统先以 **shadow mode 并行运行 3 个月**，与现有人工判别做逐案比对，建立双向指标基线。放量门槛（硬性）：
- 与人工判别在黑白区一致率 ≥ 97%
- 灰区误伤率（被判刷单后申诉成立率）≤ 现有人工基线的 1.2 倍
- 大客案件 100% 走人工，不纳入自动处置统计

低于基线即回滚，不讨价还价。

## 人效目标与基线门槛

**假设基数**（Phase 0 实测后修订）：刷单判别一线 FTE 约 N 人，日均案件量约 M 万。

**节省路径**：
- 黑白区全自动：消化 60% 案件 × 100% 替代 → 节省 0.60N FTE
- 灰区人效提升：30% 案件 × 单案耗时压缩 70% → 节省 0.21N FTE
- 大客区不动：10% 案件 × 维持现状 → 0 节省
- **合计目标替代 55%~70% FTE，折算成本回收周期 6~8 季度**（含建设期 4~6 季度）

**上线前必做 Phase 0（基线测量，2 个月）**：对当前人工判别做抽样标注与一致性测量，量化资深风控员的真实准确率/召回率/耗时分布。**没有这份基线就没有"上线"的概念**——回应"拿商家经营权做线上实验"的担忧。

## 交付节奏与依赖

按诚实估算，这是 **18~24 个月**的跨团队工程，而非一个季度的智能体产品。

| 阶段 | 周期 | 交付物 | 前置依赖 |
|------|------|------|------|
| Phase 0 | 0~2 月 | 人工基线测量、特征口径清单、规则 DSL 原型 | 数据团队对齐埋点版本 |
| Phase 1 | 2~8 月 | 特征中台 v1、规则引擎、GBDT 打分服务、在线 Flink 链路、运营工作台（无 LLM） | 特征中台是跨部门数据治理工程，需单独立项 |
| Phase 2 | 8~14 月 | Shadow mode 上线，行为序列模型离线训练与灰区辅助信号接入，A/B 框架，漂移熔断 | Phase 1 稳定 |
| Phase 3 | 14~20 月 | 放量至黑白区全自动处置，LLM 报告生成上线（异步、可降级），主动学习回路 | Phase 2 通过放量门槛 |
| Phase 4 | 20~24 月 | 大客通道与申诉闭环打磨，FTE 替代目标达成 | Phase 3 稳定运行 ≥ 1 季度 |

回滚预案：任一阶段指标低于基线，回退至上一阶段，不强推。

## 关键风险与边界

**误伤的合规与舆情成本。** 单次头部品牌误判上热搜的损失可覆盖一年人力节省，这不是"双重高置信"一句话能消化的。具体措施：
- 大客/连锁商家一律走强制人工通道，系统只做建议不做决策
- 《算法推荐管理规定》合规披露：每一次自动处置向商家明示"算法自动化决策 + 证据链 + 申诉路径"
- 法务会签申诉流程 SLA，48 小时内必须启动复核

**对抗节奏的不对称性。** 黑产以日级迭代，模型月级回训远远不够。具体措施：
- 黑产情报小组不裁撤，保留每日新模式扫描能力
- 规则引擎支持**日级热更新 + 小时级监控告警**（命中率陡降即触发）
- 序列模型按月回训 + 对抗样本持续注入
- **明确写入立项书：自动化替代的是"判别执行"岗，不是"模式发现"岗**

**模型偏见。** 历史误标集中的地域/品类会让模型学到伪关联。敏感属性去偏训练 + 分组公平性指标（地域、品类、商家规模的误伤率差异）纳入上线红线。

**数据口径漂移。** 特征中台每个特征配分布监控，漂移超阈值自动告警并熔断下游依赖。

**实施复杂度风险。** 7 条批判里最诚实的一条：这是 4~5 个团队的基础设施项目。应对：按 Phase 分阶段立项、每阶段独立验收、每阶段可回滚。避免"18 个月后发现还没上线"。

**人机责任边界。** 系统只替代重复性判别执行。高风险品类、大客商家、跨区域团伙案、历史争议商家、监管问询案件——始终强制人工决策。责任归属永远在人。

| # | 批判要点 | 处理 | 理由 |
|---|------|------|------|
| P2A-1 | 无 FTE 替代比与回收周期数字 | **响应** | 加入"人效目标与基线门槛"章节，给出 55%~70% FTE 替代目标、6~8 季度回收期、参数化假设基数；Phase 0 用 2 个月实测后修订。预算审批确实需要量化锚点。 |
| P2A-2 | "替代绝大多数"与"双重高置信"自相矛盾 | **响应（核心重构）** | v2 放弃"接管绝大多数"的空话，改为黑白区 / 灰区 / 大客区三档分流，黑白区全自动、灰区辅助人审、大客区强制人工。FTE 节省明确拆成"替代"和"提效"两个来源，不再一句话含混。 |
| P2A-3 | 没有对齐人工基线，无法证伪"模型比人强" | **响应** | 加入 Phase 0 基线测量阶段（2 个月，抽样标注 + 一致性测量）和 shadow mode 3 个月并行运行，放量门槛写成硬数字：黑白区一致率 ≥ 97%、灰区申诉成立率增幅 ≤ 1.2×。低于基线回滚。 |
| P2A-4 | 误伤的法务与舆情成本当零处理 | **响应** | 大客/连锁/高 GMV 商家强制人工通道写入主架构；《算法推荐管理规定》合规披露义务写入处置流程；法务会签申诉 SLA。不再只靠"双重高置信"一句话挡。 |
| P2A-5 | 黑产日级迭代 vs 系统月级回训，且裁掉的恰是对抗者 | **响应** | 明确保留"黑产情报小组"为独立人力单元，不纳入 FTE 替代范围；规则引擎支持日级热更新 + 小时级监控告警；立项书正面写明"替代执行岗，不替代模式发现岗"。 |
| P2A-6 | LLM 在关键路径但可被拿掉，是"为 AI 而 AI" | **响应** | LLM 完全退出在线判决链路，仅在运营工作台异步生成报告，失败时降级为模板。在线毫秒级链路全程无 LLM，不引入新故障域与 SLA 负担。 |
| P2A-7 | 实施难度被系统性低估 | **响应** | 加入"交付节奏"章节，明确 18~24 月四阶段 roadmap、每阶段交付物与前置依赖、每阶段可独立回滚。承认这是跨 4~5 团队的基础设施项目，不是一个季度的智能体产品。 |
