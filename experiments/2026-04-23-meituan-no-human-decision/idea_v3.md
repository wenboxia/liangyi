# idea.md (v3)

## 产品定位

一套以证据为核心的商家刷单风控智能体，通过**黑白区全自动处置 + 灰区智能体辅助人审 + 大客区强制深度复核**的三档分流，替代一线风控员的重复性判别工作，同时保留对抗黑产的核心人力。首年目标：在刷单判别岗位上释放 55%~70% 的 FTE，建设期成本回收周期 6~8 季度。

## 目标使用者 / 被影响方

**直接使用者**：美团大众点评与外卖平台风控运营。组织上拆成三条线：
- **一线判别员**：工作重心从"逐单扒六维度数据"转为"灰区案件三选一决策 + 大客案件深度复核 + 新模式上报"。
- **黑产情报小组**（保留、扩编、不缩编）：负责新作弊模式发现、规则与对抗样本挖掘、日级规则更新决策。对抗黑产的根本武器，明确不在 FTE 替代范围内。
- **风控产品与模型团队**：负责规则 DSL 编辑、模型回训、基线监控。一线员工不编写 DSL，不需要学代码。

**岗位稳定性承诺（写入立项书）**：
- FTE 释放以**自然离职不补员**为主，不进行无预警裁员
- 主动转岗通道优先开放：黑产情报小组、模型标注师、规则策略编辑、申诉复核专员、大客区深度复核岗
- 6 个月带薪再培训过渡期
- 立项即公示转岗岗位与筛选标准，不搞事后通知

**被影响方**：
- **平台商家**：误判直接影响经营。大客/连锁/高 GMV 商家一律进强制深度人工复核通道，系统永不自动处置。
- **消费者**：刷单污染评价与排序。
- **合规商家**：承担不公平竞争成本。
- **黑产刷单团伙**：主要对抗对象，以日级周期反推系统边界。

## 核心机制与判断逻辑

核心立场：**在商家申诉、监管问询、合规审计三重压力下，可解释性是承重结构而非装饰。** 判决主干必须是可还原证据的规则与可解释模型；黑盒端到端模型只做辅助感官；LLM 完全不上在线判决链路。

### 三档分流架构

| 分档 | 占比（目标） | 处置方式 | FTE 占用 |
|------|------|------|------|
| 黑白区（规则命中分与 GBDT 分**同时 ≥ 高阈值**，或**同时 ≤ 低阈值**） | 55%~65% | 系统直接处置，事后抽检 | ~0 |
| 灰区（单侧高分 / 双侧中分 / 两分背离） | 25%~35% | 智能体预组织证据，人工三选一 | 1 名员工日处理量按 Phase 0 实测修订 |
| 大客区（头部商家 / 连锁品牌 / 高 GMV / 历史争议） | 5%~10% | 强制深度人工复核，系统只做建议 | 维持现状 |

**"同向"的明确定义**：规则分与 GBDT 分同时进入高置信区间（判定为刷单）或同时进入低置信区间（判定为正常），两者结论一致方可自动处置。两分背离（一高一低）一律进灰区。

### 判决管线

**第一段：结构化证据提取。** 六维度（订单、用户、商家、设备、支付、评价）特征由特征中台统一维护与版本化。

**第二段：分层打分。** 规则引擎负责显式经验沉淀与高确信拦截；GBDT 负责灰区边界判别，SHAP 输出 Top 贡献特征；商家行为序列 Transformer 作为**离线辅助信号**，对灰区做补充风险分与注意力高亮，**不在在线链路上**、不参与毫秒级判决。

**第三段：报告生成与人工决策台。** LLM 仅在运营工作台**异步**生成自然语言报告摘要，把规则命中、GBDT 分与 SHAP、序列模型高亮片段组织成人类可读的证据摘要。LLM **不在在线判决链路上**、不贡献风险分、失败时降级为模板化结构报告。

## 系统形态 / 接入方式

**在线链路**：订单落库与评价发布节点，Flink 流处理 → 特征查询 → 规则引擎 → GBDT，毫秒级返回风险分。全程**无 LLM**。

**离线链路**：T+1 对活跃商家跑行为序列模型，产出灰区候选清单与注意力热力。

**一线工作台**（本版重点补齐）：
- **三选一决策选项**：① **确认刷单**（走处置流程） ② **驳回嫌疑**（解除标记并记录理由） ③ **升级专家复核**（流转黑产情报小组或大客通道，含必填理由字段）。无"存疑挂起"选项——每个案件必须有明确去向，避免积压。
- **多标签批量处理**：工作台支持同时打开最多 10 个案件，进入视图时报告已预加载至本地缓存；网络抖动时显示上次缓存版本并置灰操作按钮，避免误操作。
- **规则版本锁定**：案件进入判别视图的瞬间快照当时的规则与模型版本，后续规则热更新不影响进行中的案件；顶栏显示"当前适用版本号"，提交后落库留档。
- **可疑新模式上报按钮**：工作台右上角一键触发，自动携带当前案件证据流转至黑产情报小组队列；上报后被证实并纳入规则库的员工有专项激励（纳入绩效正向项，不纳入负向项）。
- **一键合规报告导出**：PDF + 结构化 JSON 双格式，包含完整证据链、规则命中清单、GBDT 分与 SHAP Top N、序列模型注意力片段、判别人决策与理由、版本号、时间戳。应对监管问询直接下载，不需要手动拼截图。
- **降级体验一致性**：LLM 失败进入模板报告时，字段结构与正常报告**严格一致**，不需要判别人两边对照填表。
- **公平性指标**：纯后台监控项，不给一线弹窗，不纳入一线员工日常工作动作。

**灰度与门槛**：新系统先以 **shadow mode 并行运行 3 个月**。关键说明：**shadow 期间一线员工按正常业务量工作，系统独立并行跑一套不进入处置链路的判决用于比对——不存在"一线判两份"，不额外占用员工工时**。参与疑难案件专项标注的员工有专项津贴。

**放量门槛（硬性）**：
- 与**资深风控员**（5 年以上经验、Phase 0 期间选定基准组）的判别在黑白区一致率 ≥ 97%
- 灰区误伤率（处置后申诉成立率）≤ 现有人工基线的 1.2 倍
- 大客案件 100% 走人工，不纳入自动处置统计

低于基线即回滚，不讨价还价。

## 一线员工的权益与责任边界

**责任划分（新增，写入 SLA 与员工手册）**：
- 判别人基于系统摘要做出决策→事后判错：若**摘要事实准确**但决策失当，责任在判别人；若**摘要存在事实错误、遗漏关键证据、或逻辑误导**，责任在产品团队，触发摘要生成逻辑复盘，**判别人免责**。
- 每份报告自带"证据 hash + 摘要版本号 + 生成参数"，申诉复核时可精确还原当时摘要内容，不依赖判别人记忆。
- 基于失败的 LLM 摘要降级模板做出的决策，降级事实本身不构成判别人过错。

**绩效中立（新增）**：
- **Shadow mode 期间"人-系统不一致"不纳入个人绩效**，仅用于系统校准。
- 放量后，个人误判率按现行标准考核，**不因系统存在而上调考核标准**。
- 系统建议与判别人决策不一致时，判别人有权维持自己的结论（在工作台里明确选择"驳回系统建议"），此类操作本身不是负向项。

**工作量承诺（修正 v2 不严谨处）**：
- v2 曾出现"人均日处理案件量提升 3~4 倍"，该数字在数学上推不通（灰区占比 25%~35% × 单案耗时压缩上限），已撤回。
- v3 仅承诺**灰区单案平均决策耗时目标压缩 60%~70%**（Phase 0 实测基线后修订），整体人效提升幅度按 shadow 实测结果公布，不事先承诺虚数。
- FTE 释放主要来自黑白区直接替代，而非压榨单人产能。

**SLA 与积压保护**：
- 48 小时申诉复核 SLA 从**商家提交申诉起算**。
- 智能体自动分配 + T-12h 自动提醒 + T-6h 上级可视；若系统未及时分配或排班问题导致超时，归因到产品与排班方，**不计入个人过错**。
- 申诉队列可视化，员工可主动领取；积压超阈值自动熔断并上级介入。

**主动学习标注**：
- 标注任务独立计工时，不挤占日常判别 KPI。
- 参与标注者按标注质量发放专项激励。

## 人效目标与基线门槛

**假设基数**（Phase 0 实测后修订）：刷单判别一线 FTE 约 N 人，日均案件量约 M 万。

**节省路径**：
- 黑白区全自动：消化 60% 案件 × 100% 直接替代 → 释放 0.60N FTE
- 灰区单案耗时压缩：30% 案件 × 目标耗时 −60%~70% → 释放约 0.18~0.21N FTE
- 大客区不动：10% 案件 × 维持现状 → 0 释放
- **合计目标释放 55%~70% FTE，成本回收周期 6~8 季度**（含建设期 4~6 季度）

**Phase 0（基线测量，2 个月）**：对当前人工判别做抽样标注与一致性测量，量化资深风控员的真实准确率/召回率/耗时分布。**没有这份基线就没有"上线"的概念**。

## 交付节奏与依赖

18~24 个月的跨团队工程，非一个季度的智能体产品。

| 阶段 | 周期 | 交付物 | 前置依赖 |
|------|------|------|------|
| Phase 0 | 0~2 月 | 人工基线测量、特征口径清单、规则 DSL 原型、**员工转岗方案公示** | 数据团队对齐埋点版本、HR 对齐转岗预算 |
| Phase 1 | 2~8 月 | 特征中台 v1、规则引擎、GBDT 打分服务、在线 Flink 链路、一线工作台 v1（含批量预加载、版本锁定、合规报告导出、新模式上报） | 特征中台跨部门数据治理 |
| Phase 2 | 8~14 月 | Shadow mode 上线，行为序列模型离线训练与灰区辅助信号接入，A/B 框架，漂移熔断 | Phase 1 稳定 |
| Phase 3 | 14~20 月 | 放量至黑白区全自动处置，LLM 报告生成上线（异步、可降级），主动学习回路 | Phase 2 通过放量门槛 |
| Phase 4 | 20~24 月 | 大客通道与申诉闭环打磨，FTE 释放目标达成，**转岗完成率 ≥ 80%** | Phase 3 稳定运行 ≥ 1 季度 |

任一阶段指标低于基线，回退至上一阶段。

## 关键风险与边界

**误伤的合规与舆情成本。** 大客/连锁商家一律走强制人工通道；《算法推荐管理规定》合规披露：每次自动处置向商家明示"算法自动化决策 + 证据链 + 申诉路径"；法务会签申诉流程 SLA。

**对抗节奏的不对称性。** 黑产情报小组不裁撤；规则引擎支持**日级热更新 + 小时级监控告警**（命中率陡降即触发）；序列模型按月回训 + 对抗样本持续注入；立项书正面写明"替代执行岗，不替代模式发现岗"。

**模型偏见。** 敏感属性去偏训练 + 分组公平性指标纳入上线红线（后台监控，不打扰一线）。

**数据口径漂移。** 特征中台每个特征配分布监控，漂移超阈值自动告警并熔断下游依赖。

**实施复杂度风险。** 按 Phase 分阶段立项、每阶段独立验收、每阶段可回滚。

**员工接受度风险（v3 新增）。** 员工视角下"被迫使用"系统若伴随工作量陡增、责任不清、绩效不利、岗位焦虑，会反向拖垮系统——表现为消极使用、误操作率上升、新模式漏报。对策即上一章"一线员工的权益与责任边界"全部条款，不是软承诺，是产品上线前必须落地的硬约束。

**人机责任边界。** 系统只替代重复性判别执行。高风险品类、大客商家、跨区域团伙案、历史争议商家、监管问询案件——始终强制人工决策。责任归属永远在人，但**"人"指的是产品与判别链路上的所有角色，不是把锅全甩给一线员工**。
