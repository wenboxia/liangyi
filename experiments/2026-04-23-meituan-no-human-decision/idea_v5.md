# idea.md (v5)

## 产品定位

一套商家刷单**风险信号生成器与人工裁决加速器**——通过规则引擎、可解释模型、行为序列模型三层信号融合，配合证据化工作台，为每个被审查的案件生成结构化的风险信号与证据包，供人工风控员使用。

系统不替代判决动作本身。最终的"是否刷单 / 是否处罚 / 处罚强度"全部由人工决定；系统的价值在于压缩人审单案耗时、提升证据组织质量、降低疲劳误判率、沉淀可复核痕迹，而不是把人从决策链路上替换下来。

**本文档范围**：信号生成、证据包封装、人工工作台、发布策略、预算依据。项目对人员结构、法务披露、反垄断与公平竞争义务的外部约束由平行方案承载。

## 目标使用者 / 被影响方

**直接使用者**：
- **风控判别员**：使用工作台审查案件并做裁决。工作从"逐单扒六维度数据"转为"基于证据包做决策 + 新模式上报"。**审查覆盖保持 100%，没有自动判决豁免的案件**。
- **黑产情报小组**（保留、扩编）：新作弊模式发现、规则迭代、对抗样本挖掘。
- **风控产品与模型团队**：规则 DSL、模型回训、基线监控。一线员工不编写 DSL。

**被影响方**：
- **所有平台商家**——不论规模、不论 GMV、不论是否连锁品牌，**共用同一套判别信号门槛与证据标准**。处罚前一律经过人工裁决，系统不直接下发处罚。
- 消费者（搜索决策质量）、合规商家（公平曝光）、黑产刷单团伙（主要对抗对象）。

## 核心机制：风险信号生成 + 证据包封装

核心立场（与 v1~v4 的关键差异）：**系统不做"判决"，系统做"辅助"**。理由是法律事实——模型内部的 SHAP、注意力权重、规则命中分等产物在法律意义上不构成"证据"，它们是"对模型内部状态的数学描述"，不能作为处罚商家的独立凭证。这一点从产品承诺里被彻底移除。

### 信号三层叠加

| 信号层 | 产出 | 性质 |
|------|------|------|
| 规则引擎 | 规则命中清单 + 命中分 | 显式、人类可读、可争议 |
| GBDT 打分 | 风险分 + SHAP Top 特征贡献 | **模型内部归因，非法律证据** |
| 行为序列 Transformer | 补充风险分 + 注意力高亮 | **离线信号，非法律证据** |

三层信号在置信度相同方向上合并为**综合风险等级：高 / 中 / 低**。等级决定进入人审队列的优先级与复核流程路径，**不决定处罚本身**。

### 证据包封装

每个推送的案件附带结构化证据包：
- **原始事实数据**（订单时序、评价文本、设备信息、支付流水等）——**这部分是事实证据**
- **规则命中清单 + 命中参数值** —— 辅助线索，人类可验证
- **风险分与 Top 特征 SHAP 值** —— 明确标注"模型内部视角，非证据"
- **序列模型注意力片段** —— 明确标注"模型内部视角，非证据"
- **同类历史处置参考** —— 帮助判别员做一致性判断

证据包的产品定位是**帮助人审员快速看到该关注什么**，不是替代人审员下判决。商家申诉也走人审通道，复核人独立使用证据包 + 原始事实重做判断。

## 处置分层：基于行为严重度，不基于商家规模

**所有商家共用同一套判别门槛。** v2~v4 基于商家规模的"大客区 / 黑白区 / 灰区"分层已废除。系统只做一件事：对任意规模的商家生成同一规格的风险等级。

**处置力度按行为严重度与处罚可逆性分层**（对所有商家一致适用）：

| 处置强度 | 触发条件 | 执行方式 |
|------|------|------|
| 轻度（提醒 / 搜索降权试行） | 人审确认、完全可逆 | 人审签字后系统执行 |
| 中度（暂停发券 / 流量限制） | 人审确认、短期影响经营 | 人审签字 + 上级 review |
| 重度（下架 / 资金冻结 / 账号封禁） | 人审确认、涉及法律或重大商业后果 | 人审 + 法务会签 + 上级双签 |

**自动执行仅限"轻度可逆"动作，且必须先有人审签字**；重度处置必经多级会签。这不是偏袒任何类型商家，是处罚可逆性的客观分级。所有规模的商家共用这一张表。大商家不再享有算法豁免，小商家不再被丢进自动处置的传送带。

## 一线工作台

面向人审员的主产品界面：

- **案件列表按风险等级排序**：高 / 中 / 低三档，高优先处理
- **证据包展示**：事实数据区（原始，最显著位置）+ 信号区（模型输出，明确标注"内部视角，非证据"）
- **裁决选项**：① 确认刷单 + 选择处置强度 ② 驳回嫌疑 ③ 升级复核（法务 / 情报 / 上级）
- **规则版本锁定**：案件进入视图瞬间快照规则与模型版本
- **多标签批量处理**：最多 10 并发，本地缓存预加载，断网置灰保护
- **可疑新模式上报**：一键流转情报小组
- **外部报告导出（差分披露，见下一章节）**
- **降级字段一致**：LLM 失败时模板报告字段结构与正常报告严格一致

### 可审计性的工程收缩

v4 曾承诺"证据 hash + 摘要版本号 + 精确还原当时摘要内容"。该承诺在多组件频繁迭代的实战环境下工程上不可行（模型 + 规则 + 特征 + LLM 的版本组合状态爆炸）。v5 收缩到**行业通行做法**：

- 所有模型权重按周冻结快照
- 所有规则变更全量留档
- 案件原始数据全量留档
- 追溯时走**历史重放 API**：拉原始数据 + 冻结权重 + 当时规则版本 → 重新跑一遍
- **不承诺精确还原在线实时时点的完整状态**
- 申诉与复核直接基于原始事实数据 + 重放结果，不依赖在线时点的 hash 校验

这对商家和监管同样适用：申诉看到的不是"我们当时如何判的"这种不可还原的时点状态，而是"基于你的原始数据重跑一次是什么结果"。

## 可解释性：差分披露架构

v1~v4 用"规则隐蔽化"一句话应对对抗披露风险，过于简陋。v5 按受众分层披露：

| 受众 | 披露粒度 | 披露内容 |
|------|------|------|
| 商家（申诉） | 低 | 处置结果 + 事实依据摘要 + 申诉路径；**不暴露规则细节，不暴露模型归因** |
| 监管（问询） | 中 | 按《算法推荐管理规定》结构化披露决策主要考量因素，**自然语言描述、非 SHAP 数值** |
| 平台内部审计 | 高 | 完整证据包、规则命中明细、模型归因、版本信息 |
| 一线人审员（实时） | 高 | 同内部审计 |

规则体系内部再分**显规则**（公开用于拦截，被披露无害）与**暗规则**（仅作为信号加权因子，不单独作为拦截依据，被反推的价值有限）。降低黑产从外部反推完整规则拓扑的可能。

## 系统形态 / 接入方式

**在线链路**：订单落库与评价发布节点，Flink 流处理 → 特征查询 → 规则引擎 → GBDT → 综合风险等级 → 推送人审队列。**无自动处罚**，全程无 LLM。

**离线链路**：T+1 行为序列模型，补充信号叠加到人审队列。

**持续学习回路**：人审结论 + 申诉结果 + 新模式上报回流样本库。规则日级热更新，GBDT 周回训，序列模型月回训。

## 发布策略：Phase 0 原型前置 + Shadow Mode 放量门槛

**Phase 0 原型必做（前置门槛）**：在给定历史案件样本上，做**人审耗时对照实测**——人审员分两组，一组用证据包辅助，一组直接看原始数据。测量单案决策耗时、决策一致性、判别准确率。

**如果辅助组耗时不减反增**（参照医疗影像 AI 辅助判读 18~30% 拖慢现象），**立即放弃 FTE 节省叙事**，重新定位价值点（例如"提升判决一致性"、"降低疲劳误判率"、"沉淀可复核痕迹"，而不是"加速")。这是 v5 对"AI 辅助也可能变慢"这一反直觉现象的正面应对——不预承诺数字，先拿到原型数据再谈。

**Shadow mode 3 个月**：系统独立跑一套信号生成与排序，与人审实际结果比对，**不占用员工工时，不一致不进绩效**（这是校准数据质量的必要条件，不是员工福利）。

**放量门槛**（硬性）：
- 原型实测证明辅助组人审耗时有显著压缩（或在"耗时中性"下证明决策一致性提升）
- 信号等级与人审结论的一致性 ≥ Phase 0 基线
- **不同规模 / 不同地域 / 不同品类商家的信号触发率差异**未触公平性红线
- 灰区误伤率（处置后申诉成立率）不劣化

低于基线即回滚。

## 预算依据与交付节奏

**FTE 节省叙事（相对 v4 的大幅调整）**：
- v4 前提：黑白区 60% 自动替代 + 灰区 30% 压缩 → 55%~70% FTE
- v5 前提：**无自动替代，全量人审**；价值来自单案耗时压缩与决策质量提升
- 目标区间保守给到 **15%~35% FTE 节省**，具体数字待 Phase 0 原型验证
- 成本回收周期延长至 **10~14 季度**

诚实讲，这个系统的主要价值不再是"替代人力"，而是"提升一致性、加速单案、降低疲劳误判、沉淀可复核证据"。FTE 节省是副产品，不是主承诺。如果 Phase 0 原型跑出"无显著加速"，这一节的数字全部作废，产品 pitch 转向"质量与一致性"维度。

**交付节奏**（18~24 月）：

| 阶段 | 周期 | 产品侧交付物 |
|------|------|------|
| Phase 0 | 0~3 月 | 人工基线测量、**证据包原型 + 人审耗时对照实测**、特征口径清单、规则 DSL 原型、差分披露模板 |
| Phase 1 | 3~9 月 | 特征中台、规则引擎、GBDT 打分服务、在线 Flink 链路、工作台 v1（含证据包、差分披露、版本锁定、合规报告导出） |
| Phase 2 | 9~15 月 | Shadow mode、行为序列模型离线训练、主动学习回路、漂移熔断、历史重放 API |
| Phase 3 | 15~20 月 | 放量（工作台全线铺开），轻度可逆处置的"人审签字后自动执行"开关 |
| Phase 4 | 20~24 月 | 复核流程打磨、FTE 节省目标与决策质量目标双轨验证 |

**外部前置条件**：HR/OCM 方案、法务对《算法推荐管理规定》披露流程的会签、数据团队埋点版本对齐。任一缺失都会阻塞项目，但不是本文档的交付物。

## 关键风险与边界

**对抗演化不对称**：情报小组保留，规则日级热更新，对抗样本持续注入。差分披露限制黑产从申诉回复中反推。

**AI 辅助可能拖慢人审**：Phase 0 原型必须实测；若拖慢则放弃 FTE 节省叙事、重新定位价值点。不预承诺数字。

**可审计性工程边界**：只承诺历史重放 API + 模型周快照 + 规则变更留档，不承诺实时精确还原。

**公平性**：判别门槛对所有商家一致；处置力度按行为严重度分层。系统内部监控**不同规模 / 地域 / 品类商家的信号触发率**作为公平性指标，显著差异触发模型偏见复核。

**模型输出的法律地位**：模型归因（SHAP、注意力）在任何对外披露场景下都标注为"内部视角，非证据"；对商家与监管的披露回归事实数据 + 自然语言考量因素。

**数据口径漂移**：特征分布监控 + 熔断。

**人机责任边界**：所有处罚均由人审决定；系统输出是辅助信号，不是判决。这是本版最核心的立场——**系统不定罪，系统协助定罪**。

## 遗留局限说明

本版是 **v4 + 前提级调整**的收束产物，不是完整回 P1 重走 P0~P2 推导出来的结果。具体说：

- v5 在两条 kill shot（Arg 2、Arg 5）上做了定位与机制的大幅调整，但这些调整是在 v4 架构上被施加的，而不是从"问题 → 目标 → 约束"重新推导出来的。
- v4 的很多基础设施设计（特征中台、规则引擎、流处理链路、工作台 UI 结构、Phase 0~4 roadmap 框架）被保留并包装，但这些设计当初是为"自动判决替代"的产品逻辑服务的；在"人审加速器"的新定位下，它们是否仍是最优架构未被重新验证。例如：序列模型在新定位下是否还值得建设？GBDT SHAP 是否还是主要归因工具？工作台是否应围绕"决策一致性"而非"速度"重新设计？这些问题在 v5 里都没有被认真回答。
- FTE 节省数字（15%~35%、10~14 季度回收）是在 v4 框架上往下调的，不是从原型数据倒推出来的。在 Phase 0 原型跑出之前，这个数字依然不可靠。
- P2D 拆台时隐含的五个前置问题在 v5 里只是"被响应了"，不是"被重新推导产品形态"。

**正式立项建议**：如果这个产品真要做，P0~P2 应围绕以下问题从头走：

1. **产品价值主张**：在"模型输出不构成法律证据"的前提下，智能体产品的真正价值主张是什么？（加速？一致性？对抗黑产的模式发现？不同答案导向完全不同的产品形态。）
2. **分层执行的合法依据**：在"所有商家共用同一判别标准"的法律约束下，分层执行的唯一合法依据是"行为严重度"。这是否意味着系统应当更偏向"严重度分级引擎"而不是"刷单 / 正常二分类器"？
3. **差分披露的可行边界**：对商家披露什么程度的解释，能同时满足合规义务与对抗安全？这需要法务 + 风控 + 产品三方共同定产品规格，不是产品团队单方面决定。
4. **AI 辅助加速的经验验证**：没有 Phase 0 的原型实测，所有 FTE 数字都是待证条件；但同时，辅助如果不加速只提质，产品 pitch 要不要换？这关系到立项预算能不能批。
5. **工程可审计性的投入产出**：历史重放 API 在美团真实工程代价是多少？值不值？还是直接采纳"申诉 = 重跑"的更简架构？

v5 把这些问题标注为遗留局限而非已解决事项。作为本次迭代流程的终点版本可接受；作为正式立项书则应当重做。
