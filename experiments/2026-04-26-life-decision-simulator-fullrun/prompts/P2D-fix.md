# P2D-fix · Kill shot 分级 prompt 副本

本 prompt 实现 `docs/liangyi-auto-variant.md` 第 5.2 节定义的 Kill shot 分级判定规则——按"具体性 H/M/L × 严重度 K/F"两维度分级,只有"K + H"同时满足才算 kill shot,累积 ≥ 2 个 kill shot 才回 P1。

给 Claude-2(续 idea.md 执笔窗口)使用。

---

```
下面是拆台者的反馈。请按以下规则处理——

第一步:对每条拆台论据按两个维度分级。

【维度 1 · 具体性】
- 高(H):论据带具体反证 / 反例 / 行业案例 / 历史先例 / 监管参考、可由读者复核
- 中(M):论据带逻辑推理但缺少具体反证、说服力依赖前提认同
- 低(L):论据是泛泛断言、没有可验证支撑

【维度 2 · 严重度】
- 框架级(K):论据指向方案的核心前提 / 价值主张 / 框架本身、即使方案细节调整也无法消除(kill shot 候选)
- 框架内(F):论据指向方案的实施细节 / 局部假设 / 工程取舍、可通过加护栏 / 改阈值 / 加机制等方式消化

第二步:判定每条论据。
- Kill shot = 严重度框架级 + 具体性高(K + H)
- Fixable = 其他所有组合(任何 F、或 K 但具体性中 / 低)

第三步:决定处理方式。
- 累积 ≥ 2 个 kill shot → 宣布"回 P1 重做"、停止产出 v5
- 0 或 1 个 kill shot → 所有论据作为框架内修改、产出 v5

硬性要求:
- 自己判断、不反问
- 输出包含两部分:
  1. 每条论据的分级表(具体性 + 严重度 + 标签)
  2. 最终判定(回 P1 或产出 v5) + 一行理由
- 如果产出 v5:v5 末尾加"拆台响应日志"、注明每条论据是怎么消化的

终止条件保留:
- 如果这是第二次 P2D-fix → 不论 kill shot 数量、强制走框架内修改、产出 v5

【本次是第几次 P2D-fix】
[手动填:1 或 2]

【P2D 拆台】
[贴入 P2D 产出]
```

---

## 规则结构性特点(参考、来自 ExamSniper 实验和方法论本体)

- **新规则把"任何强否定 + 实质支撑"的回 P1 触发条件,缩窄为"框架级 + 高具体性的两个独立 kill shot 同时存在"**——结构性必然性大幅降低
- **N=2 的选择理由**:N=1 太严等同老规则、N=3 太宽可能让真方向问题被框架内消化产生内部矛盾 v5
- **已知限制**:K/F、H/M 边界存在主观空间——同一拆台让多个 Claude-2 实例分级可能不一致(见 longterm-and-reference.md 6.1 节)
- **场景固有议题密度的影响**:ExamSniper 实验暴露了"拆台密集 seed"会导致新规则的"放过"机制不触发(参见 longterm-and-reference 第 5 条);决策模拟器场景密度未知,这次跑可观察
- **终止条件保留**:第二次 P2D-fix 仍强制框架内修改,作为兜底
