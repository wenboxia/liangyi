# 两仪论·全自动变种

> 这份文档记录"两仪论"方法论的一个**衍生流程**——为效率优先场景设计、全程不需要人决策的全自动化版本。
>
> **重要**：这不是两仪论本体的简化、是为效率牺牲了本体某些核心立场的独立衍生版。本体保留不变，详见 `liangyi-workflow-refined.md`。
>
> 当前文档处于**实验阶段**——基于 2026-04-23 ~ 2026-04-27 在 4 个场景上的 6 次实战归纳，不是成熟的工作流。

---

> **定位（2026-08-27 修订）**：全自动变种**不是两仪论的一个并列产品形态**，是一个**实验工具**。
>
> 它存在的目的有两个：（1）测"人到底在哪些位置不可替代"——把人工决策点全部拿掉，看流程在哪里崩；（2）跑消融评测实验——因为全 AI 的链条**可复现**，剔除了"是方法论好还是使用者厉害"这个混淆变量。
>
> 对外呈现时，两仪论只有一条主线，就是本体。变种作为验证装置出现，不作为可选形态推荐给使用者。
>
> **它已经完成了第一个任务**：四个场景全部卡在 P2D-fix 的边界判断，这个结论已于 2026-08-27 上升为立场三的精确化（见 `liangyi-workflow-refined.md` 立场三 + 第十二章的区分判据）。

## 一、它是什么、不是什么

**它是**：

- 一套独立的衍生流程，跑完整个两仪论 P0-P4 链条但所有人决策环节由 AI 替代或规则化消化
- 适用于"决策可逆 / 重做成本低 / 防溶解需求弱"的简单场景

**它不是**：

- 不是两仪论本体的"轻量版"——本体的轻量化由 `liangyi-workflow-refined.md` 第十三章"节奏感"处理
- 不是替代本体——本体仍然是高风险 / 不可逆决策的默认方法
- 不是已成熟的工作流——目前跑过 4 个场景、有未解决的设计问题（见第六节）

## 二、命名

**正式名**：两仪论·全自动变种（Liangyi Auto-Variant）

**非正式名**：效率优先版、AI-only 版

命名要显性标记"变种"——让使用者一眼看出这不是两仪论本体。

## 三、适用场景

- 决策可逆、重做成本低
- 不涉及组织内重大不可逆投入
- 不需要"防 AI 溶解人独立判断"的核心立场保护
- 例：内部工具的快速 idea 验证、非关键产品的初稿生成、低风险方案的快速过滤

**反向**：高风险、不可逆、防溶解需求强的场景，应该用本体不是变种。

## 四、它和本体的关系

变种和本体是**独立衍生**关系：

- 本体保留不变（核心立场"不让 AI 替代做出最终决策"不动）
- 变种是为效率牺牲了核心立场的衍生流程
- 变种里出现的设计困难在变种内部解决、不反向修改本体（详见本体 `liangyi-workflow-refined.md` 第十二章"变种问题归变种"原则）

## 五、当前已知的设计要点

### 5.1 决策替代清单（参考前两次实战）

| 原本体的人决策点 | 变种里的替代 |
|---|---|
| 审 P0 精炼 | 跳过 |
| 综合两份专家方案 + 写执笔指令（P1.3） | Claude-2 读两份方案自行综合 |
| 批判取舍（2A-fix / 2B-fix / 2D-fix） | Claude-2 自行判断、默认"能改则改" |
| 是否回退（2C-rollback） | Claude-2 自行判断、默认"P2C 指出漂移就回退" |
| P2D 触发条件 | 强制触发 |
| 框架内 vs 框架级判定（2D-fix） | 规则化判定 + 终止条件（见 5.2） |
| idea.md 锁定 | 2D-fix 跑完自动锁 |

### 5.2 P2D-fix 判定规则（Kill shot 分级 + 终止条件）

> **面试价值：〔面试别提〕**（2026-08-27 标）。Kill shot 分级和终止条件都是**变种自己制造的问题的解**——P2D-fix 死循环只在"把人从流程里拿掉"之后才存在，本体里"什么时候停"是人的决定，不需要任何规则。面试主线里不介绍这两条机制；正确的讲法是把它们当作一次证伪尝试的注脚："我跑了四次实验想把人从方法论里拿掉，这两条都是为了绕开'人不可少'这个结论打的补丁，最后发现绕不过去。"完整用法见 `longterm-and-reference.md` 长期观察段首的面试价值标签说明。

P2D-fix 决定"回 P1 重做"还是"框架内修改产出 v5"。当前规则采用 Claude-2 对拆台论据按两个维度分级——

**两维度分级**：

- 具体性：高（H，带具体反证 / 反例 / 历史先例 / 监管参考）/ 中（M，带逻辑推理但缺反证）/ 低（L，泛泛断言）
- 严重度：框架级（K，指向核心前提 / 价值主张）/ 框架内（F，指向实施细节 / 局部假设、可加护栏修复）

**Kill shot 定义**：严重度框架级 + 具体性高（K + H）同时满足。其他所有组合归 fixable。

**判定规则**：

- 第 1 次 P2D-fix：累积 ≥ 2 个 kill shot → 回 P1；0 或 1 个 → 框架内修改产出 v5
- 第 2 次 P2D-fix：不论 kill shot 数量、强制走框架内修改（终止条件兜底，防止 N=2 在某些场景仍然必然命中、再次死循环）

**为什么 N=2**：参考美团 Round 1 数据——Claude-2 自己识别出 2 个 kill shot（Arg 2 SHAP ≠ 法律证据、Arg 5 tier 化 = 差别待遇）触发回 P1，这是真方向级问题。N=1 太严（几乎等同旧规则、仍会死循环）、N=3 太宽（可能让真方向级问题被框架内消化、产出"内部矛盾 v5"）。

**完整 prompt 模板**（给 Claude-2 续 idea.md 执笔窗口使用）：

```
下面是拆台者的反馈。请按以下规则处理——

第一步:对每条拆台论据按两个维度分级。

【维度 1 · 具体性】
- 高(H):论据带具体反证 / 反例 / 行业案例 / 历史先例 / 监管参考、可由读者复核
- 中(M):论据带逻辑推理但缺少具体反证、说服力依赖前提认同
- 低(L):论据是泛泛断言、没有可验证支撑

【维度 2 · 严重度】
- 框架级(K):论据指向方案的核心前提 / 价值主张 / 框架本身、即使方案细节调整也无法消除(kill shot 候选)
- 框架内(F):论据指向方案的实施细节 / 局部假设 / 工程取舍、可通过加护栏 / 改阈值 / 加机制等方式消化

第二步:判定每条论据。
- Kill shot = 严重度框架级 + 具体性高(K + H)
- Fixable = 其他所有组合(任何 F、或 K 但具体性中 / 低)

第三步:决定处理方式。
- 累积 ≥ 2 个 kill shot → 宣布"回 P1 重做"、停止产出 v5
- 0 或 1 个 kill shot → 所有论据作为框架内修改、产出 v5

硬性要求:
- 自己判断、不反问
- 输出包含两部分:
  1. 每条论据的分级表(具体性 + 严重度 + 标签)
  2. 最终判定(回 P1 或产出 v5) + 一行理由
- 如果产出 v5:v5 末尾加"拆台响应日志"、注明每条论据是怎么消化的

终止条件保留:
- 如果这是第二次 P2D-fix → 不论 kill shot 数量、强制走框架内修改、产出 v5

【本次是第几次 P2D-fix】
[手动填:1 或 2]

【P2D 拆台】
[贴入 P2D 产出]
```

**已知限制**：分级标准（K/F、H/M）边界有主观空间、不同 Claude-2 实例可能给不同分级。这是根本限制——但比"任何强否定就回 P1"已经好很多。

**实证状态（2026-08-27 更新）**：已由 ExamSniper 实验验证，**新旧规则零分歧**——6 次判定全部判"回 P1"。新规则提供的是判定粒度（K/H/M/F 分级让消化策略可分项执行），不是不同的方向级判定。而且新规则的"≤1 kill shot 框架内消化"路径**至今未被任何场景触发过**。完整数据见第八节"当前实证基础"。

### 5.3 回 P1 后 P0 输入的路径选择

如果第 1 次 P2D-fix 触发回 P1，新 P1 的输入应该用什么？三种可能路径：

- 路径 1：只给最初想法、不带 P2D 拆台日志（最严格自动化）
- 路径 2：原始想法 + P2D-fix 判定文档（半规则化）
- 路径 3：在这里做一次人工介入（违反"无人工决策"前提）

Round 2 用了路径 1、但因为终止条件没触发第 2 次回 P1、路径 1 的潜在问题（新方案大概率和上一轮高度相似）没机会暴露。**这条路径选择仍然是未验证的设计**。

## 六、已知的没解决问题

### 6.1 P2D-fix 死循环（已部分缓解、未完全根治）

**原结构性必然**：旧规则"强否定 + 实质支撑 → 回 P1"几乎必然命中、两场景同构（美团 / Agent 评测）。

**当前缓解**：已采用 Kill shot 分级判定（详见 5.2）——把"任何强否定都回 P1"改为"≥ 2 个 kill shot 才回 P1"，结构性必然性大幅降低（不是所有 P2D 拆台都必产 ≥ 2 个真 kill shot）。

**未完全根治的部分**：

- N=2 阈值在某些场景仍可能必然命中（比如场景固有议题导致 P2D 总能拿出 2 个独立框架级问题、见 6.2）
- 依赖 Claude-2 分级判断的稳定性（K/F、H/M 边界的主观空间）
- 终止条件（第 2 次强制框架内）作为兜底保留——但仍是"第 2 次产出可能内部矛盾"的代价

**待跨场景验证的问题**：

- N=2 在哪些场景下能让流程顺利跑完、哪些场景下仍触发回 P1
- Claude-2 分级稳定性（同一拆台让多个 Claude-2 实例分级、看一致性）
- 6.2 提的"P2D 议题敏感度"和 N=2 的关系——如果某些场景的核心议题反复触发 ≥ 2 个 kill shot、是不是说明"那个场景本来就不该用变种"

### 6.2 P2D 议题敏感度

> **面试价值：〔面试别提〕**（2026-08-27 标）。同 5.2——这个假设是为了让变种的规则化判定成立而提的，本体的 P2D 由人判断，不以议题稳定性为前提。
>
> **且这个假设已被 ExamSniper 实验推翻**：四对独立比对（D1 vs D2 = 50%、D1 vs Y-R1 = 43%、D2 vs Y-R2 = 29%、Y-R1 vs Y-R2 = 33%）全部低于 60% 门槛。更准确的表述见 `longterm-and-reference.md` 长期观察第 4 条——议题稳定性可能受场景核心锚点强度影响，而"拆台跟着方案的具体形态调整火力"本身可能不是缺陷。

P2D 在同一场景下反复指向同一组核心议题（Round 1 vs Round 2 对比 60% 底层重叠）——意味着回 P1 重做的隐含假设（"重做能改变 P2D 拆台结果"）在某些议题面前可能不成立。

**如果议题是场景固有的、回 P1 这个动作本身没用**——终止条件那种次数限制治不了根本。

注：60% 不是 100%、且只有一次同场景对比。需要多场景验证才能确认是稳定现象。

### 6.3 回 P1 后 P0 输入路径未验证

见 5.3。

## 七、什么时候不该用

- 高风险、不可逆决策
- 决策错误代价 >> 决策慢代价
- 需要"防 AI 溶解人独立判断"的核心立场保护
- 涉及组织内重大投入或战略方向

这类场景必须用本体、不能用变种。

## 八、当前实证基础

- 4 个场景：美团风控（B 端 / 专业用户）、Agent 评测平台（B 端 / 技术用户）、ExamSniper（C 端 / 学生）、人生决策模拟器（C 端 / 城市白领）
- 跑次：
  - 美团 1 次（P2D-fix 死循环人工退出、未产出自动化 v5）
  - Agent 评测 Round 1（P2D-fix 死循环触发回 P1、未产出 v5）
  - Agent 评测 Round 2（终止条件生效、首次跑通完整 v1→v5）
  - ExamSniper（2026-04-26）：X / Y 双实验对照，共 6 次 P2D-fix 判定
  - 人生决策模拟器（2026-04-26/27）：变种首次完整跑到 P3 四份工程文档；实际是"变种骨架 + 人工介入"的混合形态（见 `longterm-and-reference.md` 长期观察第 9 条）

**ExamSniper 对 5.2 Kill shot 分级的实证结论**（2026-08-27 补，此前一直缺）：**新旧规则零分歧**。6 次判定全部判"回 P1"，新规则提供的是判定粒度（K/H/M/F 分级让消化策略可分项执行），不是不同的方向级判定。而且新规则的"≤1 kill shot 框架内消化"路径**完全没被触发过**——ExamSniper 是拆台密集的 seed（监管 + 合规 + 竞品三条独立硬墙），撞两套规则都必然 ≥2 kill shot。**"提前结束"机制尚未在任何场景被验证过**，需要在拆台稀薄的 seed 上重跑才能验证。

**实证强度**：远不够"被证实在大多数情况下有效"——本变种当前是探索阶段、不是成熟方案。

下一步实证方向：拆台稀薄的 seed（验证新规则的"放过"路径）、以及开源工具等尚未覆盖的场景类型。
