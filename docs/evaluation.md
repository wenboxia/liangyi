# 评测方法与自查

这份文件回答一个问题：**凭什么相信[那个案例](case-voyageguard.md)里的数字？**

---

## 一、污染防护

两把尺子都在跑之前封存，顺序不可逆：

```
先看链条产出  →  再开原子点  →  最后才开返工清单
```

**先看答案再去产出里找对应，就是自导自演。**

- **原子点**由独立窗口从原始想法拆出，另一个独立窗口复核，三个窗口三向审计。
  **全部没见过该项目的成品，也没见过返工清单。**
- **返工清单**从项目真实开发史整理，跑之前封存，文件头写死「封存后不得修改，
  拆原子点的 agent 不得看到本文件」。
- **原文留白登记**：原始想法没说的事（16 条）单独登记。
  落在留白里的差异记为「原文未定」，**不算偏离**——
  不然等于拿事后想到的要求去倒扣当初没想过的分。

## 二、判定与复判

逐版判定做完之后，用独立窗口重判一次，双方互相看不到对方的结论。

- 最终版的一致率 **13/14**
- 复判推翻了 **3 处**状态变化，理由都是「同一段文本被两次判成不同的态」——
  是判定噪声，不是方案真的变了
- 分歧全部按**更严的一版**记

**但这不构成跨厂商独立性。** 判定者与复判者是同一家的模型。
项目自己的模型选型纪律要求「裁判必须来自没参与生产的厂商」，**这一条目前没有满足。**

## 三、引擎的结构保证

`engine/test_guarantees.py`，全部通过。锁住的是机制而不是措辞，例如：

- 单盲窗口**主动拒绝**任何注入历史的尝试（不是「默认不传」）
- P2 链条跨底模坐标至少一维，同坐标配置直接拒绝开跑
- 拆台必须由「任务优先」坐标承担
- 循环的出口 A（回 P1）、B（回 P2）用**真实跑出来的判定书**离线驱动验证；出口 C（结构性死锁）需要议题重叠度参数，编排器不传，真实运行不可达、也无测试用例

二十条方法论合规检验记在 [`../engine/VALIDATION.md`](../engine/VALIDATION.md)，
其中 7 条通过、8 条失败（4 条已修、4 条只记录）、5 条是对照记录不下判。**失败的照原样留着——全过的自查不叫自查。**

## 五、这轮自查抓到的东西

**五个同一类的解析 bug。** 根因都是**拿模型的措辞当契约**：

| 赌的是什么 | 后果 |
|---|---|
| 表头里有「论据摘要」四个字 | 表头被数成第 1 条论据 |
| 序号是阿拉伯数字 | 用中文数字的两条链整张表数成 0 条 |
| 标签列字面写着「Kill shot」 | 模型写 `K+M`，致命论据数出 0 |
| 第一格是**纯**数字 | 序号和论据挤同一格 → 整张表数成 0 条 |
| 一步只有一个产物名 | 续跑把已完成的判定步重跑，**重掷骰子** |

第四条代价最大：模型正确判出 2 条致命论据、写明「回 P1 重做」，
**路由看到 0 行直接放行，第二轮压根没启动。**
这正是循环本来要解决的「系统产出了一个它无法执行的判定」，从解析的缝里漏了回来。

现在改成靠内容认——一行是数据行，当且仅当它同时含有一个具体性格和一个严重度格；
致命论据从这两格算出来，不认标签字面。**并且漏行不再静默**：
分不了级的行会被单独记进 trace 标为异常。

**判定本身不稳定。** 同一个场景、同一份待判文档，三次运行给出三种分级：

| 运行 | 论据 | 打中前提 | 致命 | 判定 |
|---|---|---|---|---|
| 2026-09-02 | 5 | 5 | 0 | 产出 v5 |
| 2026-09-10 | 5 | 5 | **2** | **回 P1** |
| 同日重跑 | 5 | **0** | 0 | 产出 v5 |

打中前提的条数从 5 跳到 0。**整条链上唯一能推翻方向的判断点，自己就在骰子上**，
而路由的三条出口全建立在这个信号上。

这也是为什么循环用**离线**验证而不是「多跑几次撞上某个出口」——撞上了也只说明这次骰子这么掷。
**装置对不对，和模型判得准不准，是两件事。**

## 六、还没做到的

- **跨厂商复核没做。** 判定与复判同属一家模型。
- **出口 A、B 没有一次真实运行走完第二轮。** 装置离线验过，判定也判出过，
  但真实运行里循环一次都没有真的转起来。
- **出口 C（结构性死锁）真实运行不可达。** `route()` 的 `overlap` 参数编排器从不传，没有测试用例。
- **样本是一个项目、跑一次。** 案例里那个对比的差异只落在 3 条上，太少。
