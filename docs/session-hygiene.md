# 两仪论 · 会话卫生（Session Hygiene）

> 这是两仪论方法论在**操作层面**的核心规范。
> 一个方法论如果不说清"每一步用哪个 AI 窗口"，所有分离原则（单盲、角色独立、综合中立）都会在实操中失效。
>
> 本文档定义：每一步用哪个 AI，是否新开窗口，为什么。

---

## 核心原则

### 原则一 · 按上下文是否清零分类

一个 AI 在不同步骤出现时，有两种本质不同的状态：

- **续窗口（同 session）**：AI 保留之前的对话记忆
- **新窗口（new session）**：AI 从零开始，没有之前的上下文

**这两者的区别决定了 AI 是"知情的"还是"零上下文的"**——这直接影响方法论的核心机制能否生效。

### 原则二 · 编号规则

用 `AI名-数字` 标识窗口：
- **同一个数字** = 同一个窗口（保留上下文）
- **不同数字** = 新开窗口（清零上下文）

示例：
- `Claude-1` 和 `Claude-2` 是两个完全独立的 Claude 窗口，互不共享上下文
- `Claude-2` 在 Step 1.4 和 Step 2A-fix 都出现，意味着**这是同一个窗口的延续**

### 原则三 · Session Hygiene 的核心规则

1. **每个角色一个独立窗口** —— 角色纯度
2. **idea.md 的执笔者保持同一窗口** —— 方案连贯
3. **每次"新视角"都开新窗口** —— 视角独立
4. **单盲必须零上下文** —— 硬规则，无例外

### 原则四 · P2 链条底模坐标跨维度 divergence（硬规则）

P2 链条（2A / 2B / 2C / 2D 四步批判）**必须在底模坐标上跨维度**——链条内至少存在一对底模，在维度 A 或维度 B 上不重合。

**底模坐标 · 两个维度**：

- **维度 A · 冲突偏向（Conflict Bias）**——当任务要求和其他约束冲突时，模型默认倒向哪边。判据是两样东西合起来看：训练时的奖励信号设计，以及出厂后叠加的规范层（公开的规范文本、官方 system prompt、运行时分类器）。证据必须是一手材料。
  - A1 · 规范优先 — 存在独立于任务的成文规范，冲突时规范压过任务 — Anthropic Claude、Google Gemini
  - A2 · 权限优先 — 规范存在，但形态是"谁说了算"的权限链，不是价值命题 — OpenAI GPT
  - A3 · 任务优先 — 公开材料里没有独立于任务的规范层，奖励信号全部来自任务完成度 — DeepSeek、月之暗面 Kimi、智谱 GLM
  - 未公开 — 厂商不披露后训练目标、也无公开规范文本 — 阿里 Qwen、字节豆包、MiniMax

- **维度 B · 语料文化（Corpus Culture）**
  - B1 · 英文母语 — Claude / GPT / Gemini
  - B2 · 中文母语 — GLM / 豆包 / ERNIE
  - B3 · 跨文化双核 — DeepSeek / Kimi / Qwen / MiniMax

**"未公开"不是一个可用档位（硬规则）**：维度 A 未公开的模型**不进入方法论的任何窗口**。这不是对模型能力的评价——方法论要求选型依据可解释，用一个说不清它为什么会那样反应的模型，等于把判断权交回给运气，与立场三直接冲突。

**为什么出厂后叠加的规范层也算进维度 A**：厂商在权重之外还会叠东西——公开发布的 system prompt、带版本号的行为规范文档、运行时的内容分类器。使用者通过网页或 API 访问模型时这一层始终在，绕不过去。它和训练层是同一件事的两种形态：都是独立于当前任务的规范约束，都会在关键处把手拉住。

**违反即硬规则违规**：如果整个 P2 链条的四个窗口都落在同一个坐标（例如全 A1·B1 的 Claude），必须重新选型。

**为什么是坐标级而不是模型级**：同坐标的底模共享规范约束和语料先验。全 A1·B1 会导致"四条 failure mode 看似都覆盖，实际上有一整块维度没被任何人碰到"——假覆盖。

**宽松版与严格版**：默认采用**宽松版**——链条内至少一对底模单维度 divergent 即算过。如果想追求更稳的 divergence，可以要求**严格版**——P2 链条内存在一对底模两维度都 divergent（例如 Claude A1·B1 与 DeepSeek A3·B3）。

**维度 A 的判据换过一次（2026-08-27）**：原版按对齐算法路径分四档（Constitutional+RLAIF / 传统 RLHF / GRPO 家族 / 纯 RLVR）。复核发现该分法已失效——头部厂商不再公布 RL 算法（A1/A2 无法观测）、可验证奖励与生成式奖励模型变成按任务类型分流而非路线选择（A3/A4 不再互斥）、GRPO 已成为各家自研改造的公共基础设施（A3 失去区分度）。**换的是判据，不是机制**：硬规则要的东西没变，只是从"查它用什么算法"改成"查它有没有一层独立于任务的规范"。经过见 `../references/ai-training-landscape.md` 第五节。

（本体解释见 `liangyi-workflow-refined.md` 第八章"P2 的设计精密性"。各家底模的 A/B 坐标详见 `references/ai-training-landscape.md`。）

## 完整的窗口清单

一个完整的两仪论流程涉及以下窗口：

| 窗口编号 | 底层 AI | 扮演角色 | 用在哪些步骤 |
|---|---|---|---|
| **Claude-1** | Claude | P0 精炼 / P1 专家 A | P0, P1.1 |
| **Claude-2** | Claude | `idea.md` 执笔者 | P1.4, 2A-fix, 2B-fix, 2C-rollback, 2D-fix, P3 全部 |
| **Claude-3** | Claude | 投资人批判者 | P2A |
| **Claude-4** | Claude | 知情复审对比者 | P2C |
| **DeepSeek-1** | DeepSeek | P1 专家 B | P1.2 |
| **DeepSeek-2** | DeepSeek | 拆台专家 | P2D（触发式） |
| **DeepSeek-3**（可选） | DeepSeek | 技术问题顾问 | P4（按需召唤） |
| **Kimi-1** | Kimi | 单盲复审者 | P2B |
| **GPT-1**（可选） | GPT | 模拟目标用户 | P3.1.1 |

### 数量统计

- **核心必须开的窗口**：7 个（Claude-1 到 Claude-4、DeepSeek-1、DeepSeek-2、Kimi-1）
- **可能增加的窗口**：2 个（GPT-1 做用户模拟、DeepSeek-3 做技术咨询）
- **完整流程最多 9 个独立窗口**

### 关于 AI 选择

表中的 DeepSeek 和 Kimi 是**参考选项**，不是硬性要求。方法论的硬性要求有四条：

1. **只用维度 A 可判定的模型**（见核心原则四）——厂商未披露后训练目标、也无公开规范文本的模型不进入任何窗口
2. **Model B 必须和 Claude 在 AI identity 轴上 divergence 足够大**（底模坐标至少一维不同）
3. **P2 链条必须跨维度**（见核心原则四）
4. **单盲必须零上下文**（见核心原则三 / P2B 段落）

具体的 AI 组合示例见下方"参考组合示例"章节——那里的配置会随市场演化更新，本节的三条硬性要求不变。

## 参考组合示例

这是**参考**，不是本体——跨维度混合是硬规则（见核心原则四），具体选哪个模型只要满足硬规则即可替换。

本节列出当前（2026 年 8 月）几个典型组合。**本节随时间更新，本体硬规则不变**。底模 A/B 坐标以当前快照（2026-08）为准，详见 `../references/ai-training-landscape.md`。

**本节不写具体版本号**——只写厂商名 + "当前旗舰"。2026-08 的复核证明：四个月前写下的版本号已经全部过期。参考组合是给人照着做的，写死版本号等于给它设一个三个月的保质期。具体版本号只放进 landscape，那份文件本来就是重写覆盖制。

### 默认推荐组合

| 窗口 | 推荐模型 | 底模坐标 |
|---|---|---|
| Claude-1 到 Claude-4 | Claude（当前旗舰） | A1 · B1 |
| DeepSeek-1（P1 专家 B） | DeepSeek（当前旗舰） | A3 · B3 |
| DeepSeek-2（P2D 拆台） | DeepSeek（当前旗舰，新开 session） | A3 · B3 |
| Kimi-1（P2B 单盲） | Kimi（当前旗舰） | A3 · B3 |

**坐标分布**：A1·B1 × 4 + A3·B3 × 3 ✓ Claude↔DeepSeek 双维度 divergent（严格版满足）

**等价替代**：P2B 单盲的 Kimi 可以换成 GLM（A3·B2）。两者在方法论上等价——单盲主要激活的是 context 轴（零上下文），不依赖坐标 divergence；换 GLM 后本地语料先验反而更强。

**适用场景**：Claude 可访问、追求最强 divergence 的完整流程

### 替代组合 A · Claude 不可用时

国内部分使用者无法访问 Claude。此时 Claude 整体替换为 Gemini：

| 窗口 | 推荐模型 | 底模坐标 |
|---|---|---|
| Gemini-1 到 Gemini-4（替代 Claude-1 到 Claude-4） | Gemini（当前旗舰） | A1 · B1 |
| DeepSeek-1 / DeepSeek-2 | DeepSeek（当前旗舰） | A3 · B3 |
| Kimi-1 | Kimi（当前旗舰） | A3 · B3 |

**坐标分布**：A1·B1 × 4 + A3·B3 × 3 ✓ Gemini↔DeepSeek 双维度 divergent

**权衡**：Gemini 和 Claude 同属 A1（规范优先），但规范形态不同——Claude 的规范是价值命题（成文宪法，明确排序"无害性 ≥ 有用性"），Gemini 的规范是后果分级（safety policies + 风险后果预判）。替换后 idea.md 执笔的"遵循原意"保守倾向略弱；但后果分级型的规范在某些产品上会暴露不同盲区。

### 替代组合 B · 只有一个 A3 模型可用

如果资源受限，A3 档只能用一个厂商：

| 窗口 | 推荐模型 | 底模坐标 |
|---|---|---|
| Claude-1 到 Claude-4 | Claude（当前旗舰） | A1 · B1 |
| DeepSeek-1 / DeepSeek-2 / DeepSeek-3（P2B 单盲） | 同一个 A3 模型的三个独立 session | A3 · B3 |

**坐标分布**：A1·B1 × 4 + A3·B3 × 3 ✓ 严格版满足（Claude↔DeepSeek 双维度 divergent）

**权衡**：P2B 和 P2D 共用同一个底模（不同 session），两者之间的 divergence 只来自 session 隔离与 prompt 角色切换，弱于默认组合。建议 P2B 的 prompt 纪律（见下文）执行得更严格。

### 不推荐组合 · 同坐标全覆盖

| 反例 | 问题 |
|---|---|
| Claude × 4 + Gemini × 2 + GPT × 1 | 全 B1 英文语料，维度 A 也全在 A1/A2 有规范层的一侧 → 原则四违规，且 P2D 无合格人选 |
| Claude × 7（不同窗口号） | 同一底模坐标 A1·B1，假 divergence |
| 任意窗口使用维度 A 未公开的模型 | 违反"只用维度 A 可判定的模型"硬规则 |

### 组合的淘汰和更新

本节列出的具体厂商**会随市场演化过期**——新厂商出现、现有厂商改变披露策略或对齐配置，都会让参考更新。2026-08 这次复核就淘汰了三家（阿里 Qwen、字节豆包、MiniMax 因停止披露后训练方法而退出方法论可用池）。

本节的生命周期 ≤ 原则四的生命周期。

## 逐阶段详细规范

### P0 · 想法捕获

**窗口**：`Claude-1`（新开）

**为什么用 Claude**：Claude（A1·B1）的规范层里"忠实"本身就是一条被写进宪法的价值——它在"照原意重组"和"我觉得可以改得更好"之间会偏向前者。A3（任务优先）的模型奖励信号只看任务完成度，"把想法说得更好"会被它理解成任务的一部分，于是主动推理和扩展，不适合做忠实精炼。

**为什么新开窗口**：这是流程的第一步，没有"续"的选项。

**任务**：把粗糙想法精炼成清晰表达。**不改变逻辑、不扩展、不质疑**。

**产出**：一段精炼后的文本（`P0-refined-idea.md`）。

---

### P1 · 对抗式 Brainstorm

#### Step 1.1 · 专家 A 方案

**窗口**：`Claude-1`（续 P0 窗口）

**为什么续**：Claude-1 已经理解了原始想法。续窗口让它基于完整上下文生成专家 A 视角的方案。

**任务**：基于 P0 产出，从"专家 A"视角生成方案。

**产出**：`P1A-expert-a-proposal.md`

#### Step 1.2 · 专家 B 方案

**窗口**：`DeepSeek-1`（新开，独立 session）

**为什么必须新开且独立**：
- 如果 DeepSeek-1 看到 Claude-1 的方案，它会被锚定，失去 divergence 优势
- **独立是两仪论对抗的基础条件**，绝对不能违反

**任务**：只提供 P0 产出的精炼想法（不提供 Claude-1 的方案），从"专家 B"视角独立生成方案。

**产出**：`P1B-expert-b-proposal.md`

#### Step 1.3 · 人的综合

**无 AI 参与**。人亲自对比两份方案，在 `decision-log.md` 里记录自己的判断理由。

这一步不属于任何 AI 窗口。

#### Step 1.4 · 生成融合方案 `idea.md`

**窗口**：`Claude-2`（**新开**）

**为什么不续 Claude-1**：
- Claude-1 深度扮演过"专家 A"，它对某个立场已产生认同
- 如果让它写融合方案，它会不自觉偏向"专家 A"视角
- **新开 Claude-2 是为了获得一个角色中立的执笔者**

**输入**：
- P0 精炼后的想法
- Claude-1 的专家 A 方案
- DeepSeek-1 的专家 B 方案
- 人的综合判断（从 `decision-log.md` 提取执笔指令）

**任务**：基于人的综合指令，合成一份统一立场的 `idea.md`。不保留"专家 A 说 X、专家 B 说 Y"的双声音痕迹。

**产出**：`idea.md`（v1）

---

### P2 · 交叉验证

#### Step 2A · 投资人批判

**窗口**：`Claude-3`（**新开**）

**为什么不续 Claude-2**：
- Claude-2 是 `idea.md` 的作者，它会倾向保护自己的作品
- 投资人批判需要冷眼看，必须没有作者包袱
- **新开窗口才能真正"冷眼"**

**为什么也不续 Claude-1**：
- Claude-1 扮演过专家 A，带有特定立场
- 投资人视角必须从零上下文进入

**输入**：`idea.md`（v1）

**任务**：Claude-3 扮演怀疑论投资人，对 `idea.md` 提批判性问题。**只输出批判，不修改方案**。

**产出**：`P2A-critique.md`

#### Step 2A-fix · 基于批判修改方案

**窗口**：`Claude-2`（**续 Step 1.4 窗口**）

**为什么续**：
- Claude-2 是 `idea.md` 的执笔者
- 方案的连贯性要求由同一个"作者"修改
- **不能每次修改换一个 AI，否则 idea.md 会变成多个 AI 的拼贴**

**流程**：
1. 人读 `P2A-critique.md`
2. 人判断：哪些批判需要响应，哪些是噪音
3. 人写"修改指令"给 Claude-2：比如"接受批判 1 和 3，忽略批判 2，针对批判 1 加一段竞品分析"
4. Claude-2 基于指令修改 `idea.md`
5. 人审查修改结果

**产出**：`idea.md`（v2）

#### Step 2B · 单盲复审

**窗口**：`Kimi-1`（**新开，零上下文，硬规则**）

**为什么用一个前面没出现过的第三者 AI**：
- 已经用了 Claude 和 DeepSeek，这一步换一个没参与过任何环节的窗口，把"它什么都不知道"做到最实
- Kimi 的跨文化语料背景和 Claude 的英文母语背景不同，"补脑"方式不一样——反馈更真实
- **注意**：单盲主要激活的是 context 轴（零上下文），不是 AI identity 轴。所以 P2B 和 P2D 落在同一个坐标（都是 A3）**不构成问题**，两者激活的轴不同。不必为了"看起来更 divergent"给 P2B 额外加坐标约束——那是往本体里塞不必要的机制。真正的硬要求只有两条：不能用 Claude（同厂商补脑能力最强），必须零上下文

**为什么必须零上下文**：
- 单盲的本质就是**模拟真实传播中的陌生读者**
- 如果给它背景信息，它会"补脑"，失去单盲价值
- **这条规则没有例外**

**输入**：只给 `idea.md`（v2），不给任何其他信息

**任务**：Kimi-1 作为零上下文读者，回答：
- 这方案一句话总结是什么？
- 你会批准吗？
- 哪里读不通？

**关键检验**：Kimi-1 的"一句话总结"和使用者的原始意图一致吗？

**产出**：`P2B-blind-review.md`

**硬性 prompt 纪律（底线规则）**

P2B 的 prompt 必须显性写入以下约束，违反即 P2B 失效：

- **不许脑补**：看不懂的地方直接标"我看不懂"，不要推测作者意图补全
- **只报告第一眼困惑**：第一次读到哪里卡住、哪里读不通；不要读第二遍后给出"更完整的理解"
- **禁止补充优化建议**：单盲窗口的任务是反馈"读不通的地方"，不是"如何改得更好"
- **禁止判断批判严重度**：只报告看到什么，不判断是否重要

**参考 prompt 样板**：

> 你是一个完全零上下文的读者，只读下面这份产品文档。请按顺序做三件事：
> 1. 用一句话总结这产品是做什么的（直接写下你第一眼理解的版本，不要想太久）
> 2. 你会批准推进这方案吗？为什么？
> 3. 读的过程中，哪些地方让你卡住、看不懂、或者产生"啊？"的反应？
>
> 硬性要求：不许推测作者意图补全缺失信息；不许把"应该是这个意思"当作答案；看不懂就明说看不懂；不要提优化建议，只报告卡点；不要判断哪条卡点更重要。

**为什么是底线规则**：单盲窗口一旦开始脑补，P2B 的核心机制（暴露知识诅咒）当场失效。这不是 prompt 质量问题，是 P2B step 本身是否成立的问题。

#### Step 2B-fix · 基于单盲反馈修改

**窗口**：`Claude-2`（续）

和 2A-fix 同样的流程：人判断 → 人写指令 → Claude-2 修改。

**产出**：`idea.md`（v3）

#### Step 2C · 知情复审

**窗口**：`Claude-4`（**新开**）

**为什么这里需要第四个 Claude 窗口**：
- Claude-1：过去是专家 A，有立场
- Claude-2：方案作者，不能审自己的作品
- Claude-3：投资人批判立场已经固化
- **需要 Claude-4 作为"中立对比者"进入**

**输入**：
- `idea.md`（v1，最初版）
- `idea.md`（v3，当前版）
- 修改历史（每次改了什么、为什么改）

**任务**：对比 v1 和 v3，回答：**修改是否保留了原意？有没有因为响应批判而过度修改，破坏了方案的核心？**

**产出**：`P2C-review.md`

**产出规范（操作纪律）**

P2C 的产出**不是错漏列表**，是**方向漂移暴露**。

- **对比 v1 和 v3 的核心定位**：这个方案最初是什么产品？现在是什么产品？
- **暴露响应批判产生的累积漂移**：哪些修改单独看都合理，但加起来让方向走偏了？
- **向人提问，不替人决定**：P2C 不说"这版对/错"，说"方向从 A 漂到了 B——这是你想要的吗？"

**反例**（P2C 不该写成这样）：

> 错漏 1：第 3 段定价写错了
> 错漏 2：用户画像不够具体
> 错漏 3：缺少竞品分析

这种"错漏列表"是 2A 投资人该干的，不是 P2C 的任务。

**正例**（P2C 该写成这样）：

> v1 的核心定位是"纯粹的高端深度个性化"——所有付费用户都得到最深度体验。
> v3 把这拆成两层（基础 ¥99 + 深度 ¥299/次），核心定位已从"纯高端"变成"带高端付费入口的 freemium"。
>
> 响应 P2A 市场批判（月费太贵）是合理的；响应 P2B 盲读反馈（看不出高端）加按次付费也是合理的。但这两次响应**累积起来**实际上放弃了原本"专注高端用户"的差异化。
>
> 向人提问：这个商业模式转变是你想要的方向吗？如果不是，建议回退到更接近 v1 的变体。

**为什么 P2C 必须是方向漂移暴露、不是错漏列表**：P2C 是 linear 打散整合的兜底机制——它的价值不在于"再找一轮错漏"，在于"捕捉 linear 小循环单步看不出的整体漂移"。错漏列表化就失去了补救机制的意义（本体解释见 `liangyi-workflow-refined.md` 第八章"Linear 设计 · P2C 的双重角色"）。

#### Step 2C-rollback · 基于知情复审回退

**窗口**：`Claude-2`（续）

**流程**：
1. 人读 `P2C-review.md`
2. 如果 P2C 指出某处修改偏离了原意，人判断是否回退
3. 如果决定回退，人给 Claude-2 写回退指令
4. Claude-2 执行回退

**产出**：`idea.md`（v4，可能等于 v3 如果没回退）

#### Step 2D · 拆台专家（触发式）

**触发条件**（2026-08-27 修订为两档）：

- **必触发**：P2A、P2B、P2C 三步都顺利通过，没有重大修改。三方共识即警报，此时强制跑
- **可选触发**：三步都有重大修改时，人仍可以选择触发。因为 2A/2B/2C 打的是框架内的问题，P2D 打的是框架前提——**框架内改了很多，不等于框架本身被审过**

可选触发不是新的默认值，是人在当次判断的权利。原设计的顾虑（成本高、每次都跑方案永远通不过、显性问题会淹没深层质疑）仍然成立。本体解释见 `liangyi-workflow-refined.md` 第八章步骤 2D。

**窗口**：`DeepSeek-2`（**新开**）

**为什么不续 DeepSeek-1**：
- DeepSeek-1 贡献过专家 B 方案，那份贡献已经被融合进 `idea.md`
- 如果让 DeepSeek-1 拆台，它会为自己之前的贡献辩护
- **新开窗口才能纯粹质疑，不带包袱**

**输入**：
- `idea.md`（v4，通过了 P2A-C 的版本）
- 可选：P2A-C 的反馈文档

**任务**：DeepSeek-2 扮演彻底否定的拆台者。**不质疑细节**（细节已被 2A-C 审过），质疑**整个方案的框架、前提、假设**——"这事真的该做吗？前提假设对吗？"

**产出**：`P2D-devils-advocate.md`

**操作纪律**

P2D 的 AI 选择和 prompt 必须守住以下约束：

- **拆台身份必须由 A3（任务优先）的模型扮演**：A1 的规范层会在最关键那一刀上把攻击软化掉，A2 虽然认授权、比 A1 更能被 persona 推动，但运行时的拦截层仍在。把拆台交给 A1 或 A2 是结构性失败——受四轴框架跨轴约束限制（persona 轴在有规范层的底模上激活不足）。A3 的模型训练里没有一层独立于任务的价值观拉住它，让它拆它就真拆
- **主动攻击，不等"有问题才说"**：拆台者的预设就是"这方向是错的"——让它找支撑这个预设的证据，不要让它自己判断"方向对不对"再决定是否攻击
- **具体漏洞 + 反证**：每条拆台不能只说"这里有风险"，必须写"风险是 X，反证/反例是 Y"——给人可判断的具体材料
- **禁止软化措辞**：不许写"可能需要考虑""或许应当注意"这种对齐软化缓冲，必须直接写"这个假设是错的""这条逻辑不成立"
- **只拆框架，不拆细节**：细节已被 2A/2B/2C 审过，P2D 只质疑整个方向

**参考 prompt 样板**（给 DeepSeek-2）：

> 你是一个彻底否定这个方案的拆台者。不是建设性反馈，是找出这方案**根本不该做**的理由。
>
> 硬性要求：
> - 预设"这方向错了"，找证据支撑；不要预设"方向对不对"让证据引导
> - 每条拆台必须包含：具体漏洞 + 反证 / 反例
> - 不许软化：不许写"可能""或许""需要考虑"；直接写"错"或"不成立"
> - 只拆整个方向的前提假设，不拆细节
> - 输出 3-5 条最根本的拆台论据，不要列一堆小问题

#### Step 2D-fix · 基于拆台的处理

**窗口**：`Claude-2`（续）或**回到 P1**

**流程**：
1. 人读 `P2D-devils-advocate.md`
2. 人判断质疑级别：
   - **框架内质疑**（假设需加强论证）→ Claude-2 修改 `idea.md`
   - **框架级质疑**（方向可能错了）→ **回到 P1 重做**，不在 P2 修改

**产出**：`idea.md`（v5，最终版）或回到 P1 重启

## 常见错误（避免）

### 错误 1 · 为了省事，所有步骤都用同一个窗口

如果使用者只开一个 Claude 窗口跑完整个流程：

- Claude-1 同时是专家 A、idea.md 执笔者、投资人、知情复审
- 所有角色都污染在一起
- **单盲不单盲、综合不中立、批判不独立**
- 方法论完全失效

**这是最常见也最致命的错误**。

### 错误 2 · 单盲给了背景信息

一些使用者会"好心地"给单盲 AI 解释背景："这是一个关于老年人健康的 App……"

**立刻破坏单盲**。单盲的价值就是暴露"方案能否独立于作者背景被读懂"。一旦给背景，反馈就毫无意义。

### 错误 3 · 用 Claude-2 做拆台

想"省一个窗口"，让 `idea.md` 的作者自己拆台。

**结果**：作者会保护自己的作品，拆台走过场，毫无深度。

必须用**和方案零瓜葛的新窗口**做拆台。

### 错误 4 · 每次修改换不同的 AI

想"增加 divergence"，让不同 AI 轮流修改 `idea.md`。

**结果**：方案变成多个 AI 的拼贴，失去连贯性和风格统一。

**修改必须由同一个执笔者做**（Claude-2），divergence 体现在审查环节，不体现在修改环节。

开始一次完整 Liangyi 流程前，使用者应检查：

```
[ ] 我选的每个模型，维度 A 都能从一手材料判定吗？（未公开的不用）

    ├── idea.md (主文件,会有多版本,用 git 管理)

    ├── P0-refined-idea.md

```

## 总结

**会话卫生（Session Hygiene）是两仪论方法论从理论到实操的桥梁**。

没有它：方法论只是哲学原则。
有了它：方法论是可以照着做的工作流。

**核心口诀**：
- P0-P1.1：Claude-1
- P1.2：DeepSeek-1
- P1.4 + 所有修改 + P3：Claude-2
- P2A：Claude-3
- P2B：Kimi-1
- P2C：Claude-4
- P2D：DeepSeek-2

**七个窗口，各司其职**。
